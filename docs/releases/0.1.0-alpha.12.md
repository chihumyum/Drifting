# Drifting 0.1.0-alpha.12

- 修复侧栏在某些宽度下反复分开又合上、最后整个页面出错的问题。Windows 上用非整数显示缩放时，审阅栏的类型筛选也不再触发这个错误。
- 修复一本书在这台设备上停止同步的问题：一个要素原来所在的要素类别被永久删除后，另一台设备再改这个要素，或者在同一次操作里新建类别和其中的要素，都会让这台设备收不到这本书的改动。现在这样的要素会放进「未分类」，更新后这本书会接着同步。
- 用输入法打字时，字数统计不再跳来跳去。
- 删掉文字后撤销，光标回到删除前的位置；重做也一样。
- 新建批注时，取消勾选的对象不会再被关联上；批注直接关联的对象现在也能移除。
- 通知中心会显示 Drifting 服务的运营公告；通知中心开着时收到的消息，关上后算作已读。
- 首次打开的欢迎页最后一行写明继续使用即表示同意条款，悬停可以看到会发送故障报告、在哪里关闭，以及条款和隐私政策的链接。
- 书库打不开时，会说明是哪一步出了问题、原因是什么，可以重试、打开数据文件夹或发送反馈，也仍然能检查和安装更新。
- 设置 › 关于 和 外观 › 主题 里不再多出一行代码注释。
- 故障报告更容易查明原因：启动失败时写明是哪一步，数据库写入失败时带上数据库给出的原因，并附上版本的源码修订号和系统版本。报告仍然不含正文。

这是早期版本，重要的稿件请另外保留副本。

- The sidebar no longer splits and merges over and over at certain widths until the whole page fails. On Windows with fractional display scaling, the Review panel's type filter no longer sets off the same error.
- A book no longer stops syncing on one device when an element's original category has been permanently deleted and another device then edits that element, or when a category and an element in it are created in one step. Such an element now goes to Uncategorized, and the book syncs again after the update.
- The word count no longer jumps while you type with an input method.
- Undoing a deletion puts the caret back where it was before the deletion, and redo does the same.
- A new comment no longer links an item you deselected, and the item a comment is directly attached to can now be removed.
- The notification center shows notices from the Drifting service's operator, and messages that arrive while it is open count as read once you close it.
- The last line of the first-run welcome says that continuing means agreeing to the terms; hovering it shows that fault reports are sent, where to turn them off, and links to the terms and privacy policy.
- When the library cannot be opened, Drifting says which step failed and why, offers to retry, open the data folder or send feedback, and can still check for and install updates.
- Settings › About and Appearance › Theme no longer show a stray line of source comment.
- Fault reports are easier to act on: a launch that stops names its step, a failed database write carries the database's reason, and reports include the source revision and the system version. They still never contain your writing.

This is an early release. Keep independent copies of important manuscripts.
