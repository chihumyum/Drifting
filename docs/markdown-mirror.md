# Markdown 文件夹双向同步（第一期，2026-10-31）

项目 Markdown 文件夹里的**章节和构想**可以用任何编辑器修改。Drifting 运行时，保存的修改会合并回原稿；关着 Drifting 时改的，会在下次打开项目时合并。其余文件仍由 Drifting 生成，只读。

真相仍是 Yjs。文件不当真相，而是被当成一个**只会说 Markdown 的离线 Yjs 副本**：Drifting 记住每个文件写进去时对应的 Yjs 状态（基线）。文件变了，就把「基线 → 文件」的差异放在基线的副本上重演，得到的增量像别的设备的修改一样合进当前文档。所以外部修改和 Drifting 里的修改在不同位置时都保留，不需要提示。

## 文件格式

```markdown
---
drifting-id: <节点 ID>
写作状态: 草稿
摘要: "……"
aliases: ["雨夜"]
（其他属性原样保留）
---

# 场景

正文……
```

- 标题就是文件名。正文标题不再整体降一级：`#`、`##`、`###` 分别是场景、节拍、笔记。
- 「相关内容」不再写进章节和构想文件；要素、故事线等生成文件仍然列出它们。
- 正文用 Agent 读写正文时用的那套 Markdown（`markdown-prose-adapter`）。人物提及写成纯文字，读回时按名字重新识别；Drifting 不会因为识别出提及而改写文件。
- 一行换行即另起一段（围栏代码块除外）。正文不支持的写法（列表、表格等）按 Agent 写入的规则变成普通段落。
- `写作状态` 接受中文标签或存储值；不认识的值忽略。`aliases` 由标题生成，读回时忽略。其他属性（Obsidian 的 `tags` 等）存在账本里，写回时照抄。

## 账本

`markdown_mirror_file`（迁移 `0013`），每台设备、每个文件夹一行，不同步：

- `base_state`：文件内容对应的 Yjs 状态。编辑器的 Y.Doc 开着 GC，旧版本没法从版本号回放，所以存整份状态。
- `file_sha256`：Drifting 最后一次写入或读入的文件指纹。
- `base_fields_json`：基线时的写作状态、摘要和其他属性。
- `pending_*`：已经交给原生层、还没确认写到盘上的写入。

## 读入

`ingestAuthoredFile`（`src/renderer/services/markdown-mirror/ingest.ts`）：

1. 解析文件。frontmatter 写坏了就不合并，也不覆盖，等作者修好。
2. 在基线上规划想要的段落列表：按渲染结果做段落 LCS（先削首尾相同部分），空隙里只配对相似的段落（字符二元组 Dice ≥ 0.3），不相似的当作删一段、加一段，避免把新段落套上旧段落的身份。
3. 在基线的副本上逐字修改（`reconcile-yjs.ts`）：只改变了的字，标记按文件改，人物链接不增不删；同一段里插入或去掉换行时只重建这一段的行内内容。随后对改过的段落重新识别人物提及。
4. 一个事务里：检查基线是当前文档见过的历史（否则不自动合并）、合并增量、把文件改过而 Drifting 已经删掉的段落按文件内容放回原位、追加 Yjs 更新（来源 `file`）、刷新正文缓存和字数、按文件改写作状态和摘要、记同步日志、更新账本。崩溃时要么都发生，要么都没发生，同一份修改不会被读入两次。
5. 提交后，把同一个增量合进打开着的编辑器。

一次删掉正文一半以上（且超过 200 字）时，先存一份快照历史。输入法组字时延后。外部修改在检查和回顾里算作者自己写的。

## 写出

- 章节和构想由主线程直接从持久化的 Yjs 渲染，渲染用的状态就是新的基线；其余文件仍由投影 Worker 生成。
- 写入前把要写的内容记为 pending，原生层只在文件还是账本里的指纹时才替换（`expectedSha256`），否则报冲突、不写，下一轮先合并再写。写成功后确认 pending。
- 文件内容已经是这些字时不写。
- 作者文件权限 0600，生成文件仍是 0400。
- 没有基线的作者文件（从只读投影升级、换位置）：和上次发布的指纹不同说明被改过，先另存到 `.drifting/preserved/<时间>/` 再替换。改名或删除后不再写的作者文件同样处理。
- 合并不了的修改（`drifting-id` 指向别的章节、正文被清空、基线不在当前历史里、不是 UTF-8、太大）：提示作者，账本放弃对这些字节的预期，下一次写入另存原文件再重写。

## 发现修改

- 每次投影捕获前先扫一遍；打开项目后的第一次扫描对所有文件算指纹，之后只比较大小和修改时间。
- 窗口可见时每 1.5 秒扫一次，窗口获得焦点时立刻扫。合并会像普通修改一样排期写回（停笔 5 秒后）。
- 修改时间不到 0.4 秒的文件可能还在保存，下一轮再读。
- 文件夹由一个 Drifting 安装独占（`.drifting/owner.json`）。另一个安装的 Drifting 遇到它会拒绝读写，否则两边各读入一次，同步后文字会重复。跨设备一律走 Hosted 同步，每台设备有自己的文件夹。

## 让作者知道（2026-10-31）

- **合并不了的文件**进通知中心（来源「Markdown 文件夹」）：标题是章节名，下面一行是原因，点开打开这一章。同一个文件同一个原因只通知一次；文件后来合并成功或原因变了，这条通知自动消失。设置面板里仍列出同样的问题。
- **另存了旧文件**时，通知中心多一条「N 个改过的文件另存到了 .drifting/preserved」。
- **两边改了同一处**（同一段里改动的字有重叠或相邻），在这一段上挂一条 TODO（作者「Markdown 文件夹」，`metadataJson.markdownFolder.path` 记文件路径），走普通的同步评论路径。同一段已有未完成的这种 TODO 时不再加。只是同一段的不同位置被两边改，合并本来就正确，不挂。
- **合并成功**用 Agent 改动的那套未读显示，统一用蓝色（`--external-ink`，比故事线的浅蓝更深）：章节列表上蓝色的「M」（悬停写「外部文件改动了这里 · 标为已读」）、改过的段落播蓝色的出现动画、之后新字保持蓝色直到指针停在上面、滚动条刻度三条道都是蓝色。为让蓝色只代表外部改动，Agent「改写」的刻度从蓝色改成和它正文一样的紫色。
  - 改动记录带 `source: 'file'`，章节记住最后一次改动的来源（`lastSource`），侧栏按它选颜色。
  - 打开着的编辑器在合并落下之前先遮住要播的段落（和 Agent 写入一样），动画不会先露出结果。
  - 同一段播完后 15 秒内再次合并（外部编辑器自动保存）不重播，只把这段时间里新加的字一起染蓝。
  - 某段有尚未结算的 Agent 审阅时，外部改动不接管这一段的标记。
  - 设置里的出现动画开关同时管 Agent 和外部改动。外部改动不提供撤回，也分不出是作者还是外部 Agent 改的；只在合并的这台设备上标出。

## 第一期不做

- 新建、删除、改名、移动文件不同步：删掉的章节文件会重新生成，改名后的文件不受管理。
- 要素、故事线、分类和资料仍是只读生成文件。
- 写回时不保留作者自己的 Markdown 写法（例如 `_斜体_` 会被写成 `*斜体*`）。只有内容真的变了才会写回。
- 用系统文件事件代替轮询。
