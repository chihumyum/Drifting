# ADR 001: Apple hosts over a shared document and domain core

Decision: AppKit on macOS, UIKit on iOS/iPadOS. Rust owns shared document,
persistence, transaction and domain correctness. Shared Swift owns typed UI
models and the native adapter; platform Swift owns view composition, input,
window/scene lifecycle, system file access and user interaction.

Scope decision (2026-09-26): Google Drive sync is excluded from the native
migration; the author will redesign synchronization afterwards. Existing
document/transaction/replay foundations stay in shared Rust, but the old cloud
transport, OAuth connection, provider snapshot bootstrap and account recovery
are not work to port or gates for completing this migration.

## Ownership

| Layer | Target owner | Rule |
| --- | --- | --- |
| SQLite, migrations, safety snapshots, recovery | `crates/drifting-core` | One gateway/worker per working library; reuse the published journal |
| Prose revision/provenance and authored update journal | `crates/drifting-core/src/prose.rs`, `prose_journal.rs` | Existing tables and deterministic CBOR; callback composes Yrs validation and comment CAS in the same transaction |
| Live prose durability owner | `crates/drifting-prose` | Exact local transaction updates; ordered persisted-tail replay; snapshot/prune in one transaction |
| Durable file replacement and atomic writes | `crates/drifting-core/src/file_io.rs` | Preserve fsync, rename and failure behavior |
| CRDT, block operations, anchors, semantic undo | Rust document sessions, P2 decision | Preserve existing Yjs document tree and identities; display is a projection |
| Domain commands, repositories, journal, derived data | Rust domain services, P3 | Migrate operation by operation with semantic comparison to TypeScript |
| Accepted document receiver and replay foundation | Shared Rust services | Remote SQLite commit precedes live-document replay; exact tail coverage controls compaction; Google Drive migration deferred |
| Agent orchestration | Shared in-process Rust runtime, P4 | Preserve provider-neutral protocol, permissions, CAS, durable reviews and receipts |
| Credentials, file picking, OAuth and lifecycle | Apple host adapters behind core ports | Keep credentials out of UI/model payloads; do not force UI APIs into Rust |
| Text rendering and native input | AppKit/UIKit TextKit adapters | One document owner across views; no full-document reconstruction on keystrokes |

The current renderer-owned Agent remains unchanged while Tauri runs. In the
native target, its responsibilities move to the shared in-process runtime; the
protocol remains provider-neutral. `local`, `sidecar` and `remote` remain
transport seams. Unsupported transports are explicitly unavailable per platform;
iOS is not assumed to support arbitrary desktop subprocesses. Portability of a
minimal permission/read/write/review transaction must be demonstrated before the
full P4 migration. No separate Shadow CI, Element Arc or Goal Evolve product is
revived. Ambient remains unimplemented and must use the same runtime.

## First extraction

The existing database engine and all its 18 regression tests move together from
`src-tauri/src/database.rs` into `crates/drifting-core/src/database.rs`. Tauri
commands, async executor and recovery dialogs remain in the adapter. The core
embeds the same `drizzle/` directory. Its package version must match the client:
the existing safety-snapshot implementation uses that version for upgrade
markers. Changing the core's version independently would alter behavior.

`crates/drifting-apple-bridge` is a fixture-only C ABI v1 static library. Swift
serializes calls on a background queue. Handles are opaque integers, errors are
explicit JSON replies, and every returned string has one matching free. No Rust
panic may unwind across the C boundary. This small ABI is not the eventual P3
business API. The production seam will use versioned commands and batched
change notifications, not per-character SQL or exposed CRDT pointers.

The P2b fixture checkpoint stores comment relative positions as an additive
`nativeAnchorV1` field in existing `anchor_json`, alongside preserved v4 anchor
fields and original quotes/snapshots. Prose and anchor changes commit together;
anchor compare-and-swap prevents replacing an externally changed anchor.
This does not change SQLite schema. The P2c owner now commits exact authored
updates, revision/provenance, writer sequence/HLC, immutable change-set/mutation,
apply receipt and changed anchors atomically. The deterministic CBOR fixture is
generated by the actual old TypeScript builder and codec. Complete domain
creation/deletion, conflict repair and the remote sync reducer remain P3/P4;
the lab's synthetic bootstrap does not pretend to author those operations.
The compatibility harness uses the old renderer's actual parsers.

The Rust 1.88 core remains independent of Yrs. The Rust 1.96 prose crate joins
the core and document owner, performs consistent snapshot/tail loading and
captures local/UndoManager transaction events. A state-vector diff would also
carry historical delete sets, so it is not used as the authored log. Only actual
applied tail rows advance snapshot coverage; neither a local append result nor
MAX(id) can acknowledge unseen remote updates. See [durability](durability.md).

## Document validation decisions still required

- D1: selected Yrs `=0.28.0` with vendored redone-offset, sparse-replay and undo deletion-filter fixes, `sync`, UTF-16 offsets, GC enabled and
  session-local undo tracking only `native-local`. Headless interoperability
  with Yjs 13.6.32 passes both input encodings and v1 output, metadata preservation, duplicate and
  out-of-order updates, anchors and local undo. This module requires Rust 1.96;
  Rust 1.88 compilation of the dependency fails. Native v2 emission is disabled
  after binary-array interoperability failed. See [document contract](document-core.md).
  Native editor compatibility remains gated by P2b/P2c. The upstream nested-array
  pending-update discrepancy was reduced to sparse-hole replay and now has
  deterministic native/Yjs regressions, checkpoints and a separate baseline/
  patched stress comparison. Future upgrades must preserve these checks.
- D2: explicitly select and observe the TextKit engine on both platforms.
  Measure long paragraphs, wrapping, IME, selection and decorations before
  accepting TextKit 2 as the final binding.
- D3: specify UTF-16 view offsets, CRDT positions and grapheme boundaries;
  composition is transient UI state and must survive remote changes without
  publishing half-composed text or resetting the input context.
- D4: one document session owns local/remote/Agent origins and semantic undo.
  Native undo menus forward to this owner; text storage must not accumulate a
  second independent prose history. Selection/scroll are per view. A shared
  Swift `DocumentStore` now serializes every view's committed input and owns
  save/retry state; bindings subscribe weakly and keep their own marked draft.
  Pending work and rejected recovery drafts outlive the last view. Ephemeral
  CRDT input branches merge overlapping inline edits without resetting composition. Rust now owns ephemeral view-relative positions
  and matching-epoch history metadata; the native binding sends exact TextKit
  replacement ranges and discards stale selection-capture replies. Compressed
  per-item lineage maps newer selections through copied/redone sibling text.
  An optional child-before-parent deletion policy now preserves remote-owned
  text in reconstructed subtrees and retains their IDs/attributes. Native/Yjs
  history and checkpoint tests cover this policy; copied local items retain the
  old plugin's undo semantics. Snapshot-authored inline drafts and sequential
  input branches now pass Rust/Yjs/Swift checks. The shared native queue also
  passes programmatic AppKit overlap/remote-composition, continued-input and
  refresh-race cases, keeping each queued operation attached to its visible basis.
  Hosted iPhone/iPad tests now cover actual UIKit marked-text entry points,
  repeated-character identity, Unicode deletion and responder resignation. UIKit
  captures ranges directly at native input methods, which can bypass the text
  delegate. AppKit responder actions/menu validation and UIKit key commands/system
  UndoManager forwarding now use only the shared Rust history, with pending-work
  and composition guards. Physical IME/device interruptions remain separate gates.
  Structural drafts now accept concurrent inline changes outside the affected
  sibling blocks after comparing tree topology, marks, attributes and CRDT item
  tapes. They map live anchors using current offsets while retaining the author
  branch for queued input. Same-block structural concurrency remains open.
  Blockquote boundaries work when no unselected subtree needs relocation; such
  relocation remains rejected because remote input followed by undo could
  restore duplicate domain IDs. The accepted quote join retains the original
  right container and suffix only when the left quote has no preceding sibling.
  The three remaining old-schema cases have both a left prefix and a right
  suffix: retaining one physical parent requires copying the other side's
  surviving subtree. XML item parents cannot simply be reassigned on the current
  compatible wire format. Copying the prefix instead moves the same history and
  late-update problem; changing public IDs is not an accepted workaround. Before
  removing these rejections, specify durable relocation identity and late-update
  routing, then verify both implementations and repeated history. Extending safe
  single-left-block shapes alone does not close this decision. Binary
  snapshot-copy cost belongs to the P2c performance gate.
- D5: choose release channels and test sandbox, entitlements, credential access,
  updater replacement and Intel packaging before P5 completion. No credentials
  are accessed in P1. Future lab Keychain service and account namespaces must be
  distinct from the existing `Drifting` service, as must OAuth redirect schemes.
