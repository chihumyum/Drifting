# 通用内核 v5：项目也是模板（设计稿）

2026-11-13 起草。**这是设计稿：没有审过，没有实现，格式号和步骤都还没排。** 现在跑的仍然是 [kernel-v4.md](kernel-v4.md)，现状见 [progress.md](progress.md)。

输入是作者 2026-11-13 在设计会话里的一组决定，原话在本页末尾「输入」一节。作者把底层做法交给了设计会话的地方，单列在「替作者定的」；和输入不一样的地方单列在「和输入不一样的地方」；还要作者定的在第 15 节。

它在 kernel-v4 上改。v4 的条目模型不动：只有一种条目、「层级」是条目自己的开关、模块任意拼、「下面」的设置往下继承、住处与归属。下文只写变的部分。

## 1. 大白话

**为什么改。** v4 把条目做成了通用的、可拼装的东西，但「项目」这一层还是写死的一本小说：新建只会照小说模板建，「成书」挂在「书稿」那个文件夹上，素材、待办各有一套自己的结构。作者的方向是把 App 做成通用的 Markdown 编辑器，写书只是其中一种项目。

**改了什么：**

1. **项目有一份自己的定义。** 它从项目模板抄来，之后可以自己改：有哪些项目开关、写给帮手的项目说明、左栏有哪些 Tab。
2. **「成书」是项目的开关，不再挂在某个文件夹上。** 开着的项目选一个起点，成书就是从起点读出来的正文。「书稿」不再是 App 认识的东西，它只是写书模板里一个普通的文件夹。
3. **顺序只有两种来源。** 文件夹里是手动排的先后；视图里是刻度，泳道跟着视图的刻度走。按修改时间、创建时间、名字排只是换个看法。
4. **左栏的 Tab 由用户自己定。** 把层级挂上去，自己起名。
5. **素材并进条目。** 文本素材就是条目。图片和 PDF 是「文件」，放在条目的媒体模块里，或直接嵌在正文里。素材栏不再存东西，只是全书文件的索引。
6. **待办并进批注。** 只有批注一种；它可以挂在任何模块的某一处；每张批注卡上常驻「交给帮手」。
7. **两个小项。** 条目可以有自己的记号；画布上拖出来的位置不再存在书里。
8. **多一个全书视图「结构」。** 看所有模板怎么定义、层级怎么嵌、各项设置从哪来、有什么游离的。

**作者会看到的不同：**

- 左栏不再是「书稿 / 构想 / 要素 / 故事线」这四个写死的 Tab，而是项目里记着的一组 Tab，可以加、删、改名、换挂的层级。
- 项目主页多出「项目模板」：成书开没开、成书从哪开始、给帮手的项目说明。
- 没开成书的项目里，看不到导出成书、全书字数和目标、章节编号、正文上的「进成书」开关。
- 在同一个文件夹里可以拖着调先后。
- 底栏视图里的先后就是泳道里唯一的先后；打开泳道自己的页面，看到的也是这个顺序。
- 右栏的素材库变成文件索引：每个文件指回它出现的地方。没有素材夹，单独存的文件和笔记都是条目树里的条目。
- 审阅栏只有批注。字段、键值行、情节规划的格子、图上的一块都能写批注。

**作者要做的。** 这是一次格式改动。和 v3、v4 一样：旧格式的书原样拒开，不修、不删；开发库从 0.1 重新导入到一个新目录。0.1 不受影响。

## 2. 项目定义

### 现状

- `project.create` 只会照小说模板建（`dr-doc` 的 `novel` 模块，一个 Rust 函数）。书里只有 `meta.project_template = {id, version}` 记来源，没有项目自己的定义。
- 写给帮手的整本书说明（「这是一部小说……」）挂在「书稿」模板的帮手说明上，因为项目没有地方放。
- 全书字数目标、每日目标、导出成书、章节编号对每个项目都开着。
- 好的一面：产品代码已经不按内置模板 id 认东西（v4 第 9 节，门禁 `cutover`），左栏、主页的新建入口、时间线都按数据来。缺的只是项目这一层自己的定义。

### 定义里有什么

项目定义存在书目文档里（第 10 节的 `project` 根），跟着同步：

| 部分 | 说明 |
| --- | --- |
| 来源 | 从哪个项目模板建的，只记不用（沿用 v4「模板更新与项目无关」） |
| 写给帮手的项目说明 | 名字、描述、指示，形状和条目模板的帮手说明一样；帮手的结构说明从这里读，不再从某个条目模板读 |
| 项目开关 | 这一版只有「成书」。它带着成书的起点、全书字数目标和每日目标（第 3 节） |
| 左栏的 Tab | 一组有先后的 Tab，每个有名字和挂的东西（第 5 节） |

**项目模板** = 一份项目定义 + 一组条目模板 + 起始的条目 + 起始的视图。新建项目时整份抄进项目，之后两边各走各的。内置的只有「写书」这一个，就是现在的小说模板换个形状。用户把自己的项目另存成模板、模板放在哪，这一版不做（第 15 节）。

「成书」以外的项目级功能（写作日、视图、项目设定、Project Memory）这一版照旧一直开着。以后要让某一样可关，照「成书」的做法加一个开关。

## 3. 成书

### 规则

- 项目定义里有没有「成书」，决定这个项目有没有「最后合成一本书」这回事。**一个项目只有一本书。**
- 成书有一个**起点**，用户选：
  - 根；
  - 一个开着层级的条目（文件夹）；
  - 一个视图；
  - 某个视图里的一条泳道。
- **成书 = 从起点按它自己的顺序读出条目，每个条目交出它「进成书」开着的正文。** 进不进成书只看正文模块上的 `in_book`（v4 已有），不看条目住在哪、用什么名字。
- 导出、全书字数和目标、章节编号、书架上的字数都只看这一串。带着成书正文的条目从 1 起编号（沿用 v4）。

### 从四种起点怎么读

| 起点 | 读法 |
| --- | --- |
| 文件夹、根 | 先序走：条目自己的成书正文，然后是住在它下面的条目（手动排的先后），然后是挂名进来的条目。每个条目只收一次，先遇到先收 |
| 视图 | 这个视图各条泳道里的全部条目，沿刻度从头到尾。几条泳道自然交错 |
| 视图里的一条泳道 | 沿同一条刻度，只读这条泳道里的 |

- 两个条目落在同一刻度上：按泳道在视图里从上到下的先后，再按 id。
- 从文件夹往下走时遇到一条泳道，它里面的条目按「泳道自己的页面」的顺序取（第 4 节）。
- 整书视图（v4 的 T7）用同一个读法，只是不限「进成书」的正文、可以从任意层级或视图打开。成书就是「起点的整书视图里，进成书的那些正文」。两处不再各算各的。

### 随之而来的

- **一个用「章」模板的条目拖进构想那个文件夹，它还是章**，不自动换模板。它还算不算进书，看构想那个文件夹在不在起点下面。
- **起点选根时，根上几个文件夹的先后会影响成书。** 故事线排在前面，就会先按故事线把章收进来，没挂到任何故事线的章排在后面。
- **起点选视图时，条目住在哪个文件夹、在文件夹里排第几，对成书没有影响**，先后只在视图里排。不在这个视图任何一条泳道里的条目不进书。
- **起点不在了**（条目进了回收站或关了层级、视图删了）：成书读作空，界面提示重新选；不替作者换一个。

### 去掉的

`is_manuscript` 这项层级设置、「成书的层级不嵌套、只认最外层」这条不变量和它的检查、「一本书可以有几处成书」以及导出时的选择、成书设置在显示上往下继承这件事（代码继承、文档写不继承，本来就没对上），都去掉。

## 4. 顺序

**装什么和排成什么先后，是两件事。** 层级管「装什么」：文件夹下面住着谁、泳道里挂了谁。先后只有两种来源：

| 东西 | 它的顺序 | 能不能当成书起点 |
| --- | --- | --- |
| 文件夹、根 | 手动排的先后 | 能 |
| 视图 | 刻度 | 能 |
| 视图里的一条泳道 | 跟着视图的刻度 | 能 |
| 按修改时间、创建时间、名字排 | 只是显示 | 不参与 |

### 文件夹：手动先后

- 这是文件夹唯一真正的顺序，就是 v4 说的「兄弟之间的先后」。数据和命令已经支持（`entry.move` 收 `parent` 和 `index`）。
- 缺的是界面：现在的拖放只传 `{id, parent}`，只能换文件夹，不能在同一个文件夹里调先后。要在三处能拖：左栏的列表、条目页里「下面的条目」、结构视图的层级表。根上几个文件夹谁先谁后，在结构视图里拖。
- 按修改时间、创建时间、名字排是显示选项，记在本机，不改手动先后。按别的方式看的时候不能拖着调先后；拖进别的文件夹照常可以。
- 看板和岛屿是自由摆放的，不体现先后；要调先后切到列表。

### 视图：刻度

视图在代码里叫 `timeline_views`。**刻度代表什么由用户自己定**，不一定是时间。

- 一个视图有一条刻度，它的所有泳道共用。条目在刻度上的位置记在视图上，不记在泳道上。这已经是现在的数据（`placements`，每个条目在一个视图里只有一个位置）。
- **泳道自己没有顺序**，它的顺序就是视图的刻度。
- 条目挂进一条泳道时，在包含这条泳道的每个视图里自动落在刻度末尾；不留「挂进来了但没有位置」的状态。
- 一条泳道可以放进几个视图，它在每个视图里各有一套位置。这是视图的本意：每个视图是一种排法。
- 泳道自己的页面里「下面的条目」按视图的刻度排：泳道在成书起点那个视图里就用它，否则用它所在的第一个视图。

### 归属自己的顺序

归属记录上现在有一个 `pos`，对泳道来说是藏着的第二个顺序，作者在界面上看不到。改成：

- 泳道在某个视图里时，不读也不写这个 `pos`。
- 一个收别处条目、但不在任何视图里的文件夹（比如要素的分类）照旧用它排挂名进来的条目。这时它就是个普通文件夹，这个顺序就是它的手动先后的一部分。

## 5. 左栏的 Tab

- 现状：左栏的 Tab 就是最外层那几个开着层级的条目，条目叫什么 Tab 就叫什么。
- 改成：项目定义里记着一组 Tab。每个 Tab 有自己的名字，挂一个开着层级的条目，或者挂根。先后可以调。
- 条目住在哪是一回事，Tab 上挂什么、叫什么是另一回事。一个层级可以不挂在任何 Tab 上，也可以挂在几个 Tab 上。
- Tab 里怎么显示，照旧由挂上去的那个层级的「显示」设置决定（列表、网格、看板、岛屿）。
- 没挂到任何 Tab 的层级不会丢：结构视图里都能看到，层级表有一列标出每一层挂在哪个 Tab。
- 挂的层级不在了（进了回收站、关了层级）：这个 Tab 显示为空并提示，不自动删。
- 当前停在哪个 Tab、栏宽留在本机。
- 右栏的四个 Tab 这一版不动。

## 6. 素材并进条目

### 现状

- 素材是条目树之外的一套东西：`materials`（文本、图片、PDF 三种）加一棵 `material_folders` 树。
- 文本素材的正文是 `material:<id>` 文档，用「笔记」格式档，比条目正文多任务清单、代码块、提示块、高亮、行内代码；表格和嵌入也只在笔记里画。
- 正文嵌素材的数据结构已有（`embeds` 里 `kind = "material"`），索引里也记着哪篇正文的哪一段嵌了哪个素材，但斜杠菜单只在素材笔记里给「插入素材」；右栏「当前」只看关系，不看嵌入。

### 改成

| 现在 | 改成 |
| --- | --- |
| 文本素材 | 条目。写书模板带一个「笔记」模板（一篇不进成书的正文） |
| 素材夹 | 开着层级的条目 |
| 图片、PDF 素材 | **文件**：字节只存一份（现有的 `assets`，加一个名字）。它放在条目的**媒体模块**里，或直接嵌在任何一篇正文里 |
| 单独存一张参考图 | 用带媒体模块的模板建一个条目，默认住在一个叫「素材」的层级下 |
| 素材栏 | 全书文件的索引：每个文件一格，列出它出现的每个地方，点了跳过去。它不存任何东西 |
| 图上框一块写批注 | 批注挂在（条目，模块，模块里的哪一处）上（第 7 节） |
| 正文链到素材 | 就是链到条目 |

- **媒体模块**是一种新的模块种类（`media`），任何模板都能拼。一个媒体模块里可以放几个文件，各有说明文字和先后。
- 把图片拖进或粘进正文：存成一个文件，正文里放一个指向它的嵌入。同一个文件可以嵌在几处。
- **正文只有一种格式档。** 原来只有笔记里有的格式对所有正文开放，「笔记」格式档退役。不这样做，文本素材并进条目就是降级。层级上的「格式快捷输入」设置照旧只管输入时的便利，不限制正文能有什么。
- 没有任何地方引用的文件，照现有的嵌入清理规则处理：读取时不显示，后台清理时再删字节。

### 去掉的

`materials`、`material_folders` 两个根；`material:<id>` 这种文档；素材的三种种类；关系、批注、链接里「素材」这种端点；`material.*`、`material_folder.*` 命令。项目设定（`facts`）不动。

## 7. 批注

### 现状

- 批注和待办是同一种记录，只差一个 `kind`（`note` / `todo`）。优先级两边都能设，状态都是未解决 / 已解决。
- 能挂的地方：整个条目；条目某一篇正文里的段落或一段文字；文本素材；图片和 PDF 上的一块；或者不挂。命令层写死了「给了模块就必须是正文模块」。
- 从侧栏打开的故事线页，「说明」正文没接上批注入口（界面问题，另有修复）。

### 改成

- **只有批注。** `kind` 去掉。状态、优先级保留。
- **来源**记下来：手写的、正文里打的标记投出来的、清单项投出来的、帮手写的、读者写的。标记和清单项照旧自动变成批注。
- **目标**是（条目，模块，模块里的哪一处），三项都可以空着：

| 模块 | 「哪一处」是什么 |
| --- | --- |
| 正文 | 段落和文字锚点（现有的）；正文里嵌的文件是嵌入 id 加上面的一块 |
| 字段 | 哪个字段 |
| 键值表 | 哪一行 |
| 情节规划 | 哪个格子 |
| 补丁 | 哪条补丁 |
| 媒体 | 哪个文件，加上面的一块，PDF 还有页码 |

- 指着的那一处不在了（字段删了、行删了、换了模板），批注读作「找不到原处」，不丢，和现在目标进回收站一样。
- **每张批注卡常驻「交给帮手」。** 帮手拿读写权限和一句简短的提示词去处理，对话记在批注上（现有的 `agent_conversation`）。原来要单独做的「把待办交给帮手」入口就是它；章末交给帮手审阅整章是另一件事，不在这里。
- 审阅栏只有一个列表，按状态和来源筛。从清单项来的默认收成一组，免得淹没别的。全书视图里分开的两栏并成一栏。

## 8. 两个小项

**条目自己的记号。** 现在记号只在模板上，八个名字对应七种砂笔。条目加一个可选的记号，没设就用模板的。记号可以是砂笔库里的一个，也可以是任意一个字（包括 emoji）。模板的记号同样放开。

**画布坐标挪出书目。** 看板、网格、关系图上拖出来的位置现在存在条目上，每拖一下都算「书变了」：推进书目版本、叫醒自动链接、写撤销记录。改成存在书旁边的一篇小文档里（和 v4 的写作日、快照点清单一个做法），跟着同步，按视图存：哪个范围、哪种摆法、哪个条目在哪。同一个条目在不同范围里可以各有位置。视图刻度上的位置是内容，不是摆放，留在书里不动。

## 9. 结构视图

一个新的全书视图「结构」，两种看法：

- **模板**：每个模板一块，模块一行一个；默认开着层级的模板底部一行写它对「下面」的设置。连线是实际的树里谁住在谁下面，粗细按数量；点线是归属。右边列出游离的：没人用的模板、没有模板的条目。点一个模板出小卡：模块细节、「下面」的设置、它的条目住在哪、归属到哪。
- **层级**：每个开着层级的条目一行，列是各项「下面」的设置。这一层自己定的、模板定的、从上一层继承的，三种画法不同。

模板之间「谁放在谁下面」在模板定义里读不出来（v4 去掉了「允许的模板」），只能从实际的树里统计，所以连线画的是统计结果。

这一版给层级表加三样：一列「挂在哪个 Tab」；成书那一列去掉（成书不再是层级设置），改成标出成书的起点；行可以拖着调先后，包括最外层。

原型在作者的设计画布上（<https://claude.ai/artifact/VUhhDED2YfauK4zwXJCMdk>），作者 2026-11-13 看过，暂定可以。它和别的全书视图一起迁：故事图等几个的形状还没谈完（第 15 节）。帮手拿到的结构说明就是这个视图的机器版，两边用同一份数据；层级很多时结构说明只给每层按模板的计数，不逐条列。

## 10. 数据结构

以下是相对 v4 第 4 节的变化。格式号升到 5；只开 5 的书，4 和更早的原样拒开，和以前的政策一样。

| 根容器 | 变化 |
| --- | --- |
| `meta` | `v = 5`；`word_target`、`daily_word_target` 挪进 `project.book`；`project_template` 挪成 `project.source` |
| **`project`**（新，映射） | `source = {id, version}`；`agent = {name, description, instructions}`；`book`（没有这个键 = 没有成书）`= {root, word_target, daily_word_target}`；`tabs`：Tab id → `{name, pos, mount}` |

## 14. 步骤建议

排步骤是监管会话的事，这里只说依赖关系。v4 的八条轨道在这页起草时大多已经合进 `main`，以 [progress.md](progress.md) 为准。

1. **文件夹里拖着调先后**：只动界面，不动格式，可以先做。
2. **数据层一步**（格式 5）：项目定义、成书起点和读法、去掉 `is_manuscript`、批注的 `part` 和去掉 `kind`、媒体模块和文件嵌入、去掉素材两个根、条目的 `mark`、`layout:<书>`、落位规则。和 v4 的 2b 一样是一次跨工作区的类型变更，要同时把导入和种子做对。
3. **数据层之后可以并行的**：
   - 外壳：左栏 Tab、条目页的记号、拖拽；
   - 项目主页：项目模板的查看和修改；
   - 成书：导出、字数、编号、书架按起点；
   - 视图：刻度当权威、泳道页的顺序；
   - 文件：媒体模块、编辑器里嵌文件、素材栏改成索引、统一格式档；
   - 审阅：合并、各种模块的批注入口、交给帮手；
   - 帮手工具与 MCP；
   - 结构视图（等第 15 节第 7 条）。

会话「Rust 迁移和 Entity v4 审查」手上那批修复（故事线页正文接线、整理类条目的改名入口、要素全景离屏重算等）和这页不冲突。请它留意的三点已经当面说过：成书继承不用修；批注入口按（条目，模块）接、不按种类分叉；素材和左栏只修确实坏的，不做结构整理。

## 15. 还要作者定的

1. **写书模板里，成书的默认起点选哪个。** 放章的那个文件夹：稳妥，没挂到任何故事线的章也在书里，和现在一样。默认的那个视图：章的先后只在视图里排，和 0.1 的全书顺序是一回事，但不在任何泳道里的章不进书，要么给它们一条「未归属」泳道，要么接受。不等答复时按文件夹做。

## 替作者定的

作者说「底层细节我不在乎，你按照最优最干净设计」的地方，设计会话这样定：

- 文件只存一份，放在媒体模块里或嵌在正文里；素材和素材夹这套平行结构整个去掉；素材栏只是索引。
- 正文只有一种格式档。
- 项目定义存在书目文档里；Tab 记在项目定义里跟着同步，停在哪个 Tab 和栏宽留在本机。
- 画布坐标存进跟着同步的小文档，按视图存。
- 选泳道当成书起点时，选的是「某个视图里的这条泳道」。

- 按时间或名字排的显示选项记在本机，按别的方式看时不能拖着调先后。
- 起点、Tab 挂的层级不在了，都读作空并提示，不替作者换。

## 和输入不一样的地方

- **归属自己的顺序没有整个删掉。** 作者说让视图里的轨道顺序作为泳道唯一的顺序。泳道照做了；但一个收别处条目、不在任何视图里的文件夹（要素的分类）仍然要给挂名进来的条目排先后，所以归属上的 `pos` 留着给它用。
- **「挂根层级都可以」**这里读作 Tab 可以挂根，也可以挂最外层的层级。
- **写书模板的默认起点**没有照「兼容 0.1 就用底栏视图」直接定成视图，因为那样会让没挂故事线的章不进书，留给作者定（第 15 节第 1 条）。
- **成书和整书视图合成一个读法**是这页加的，输入里没有这一句；它来自作者说的「选一个层级作为成书的 root，然后自动从树上拿正文」。
