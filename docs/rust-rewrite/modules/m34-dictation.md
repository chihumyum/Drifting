# M34：帮手输入框口述（不做）

作者 2026-11-16 定：「移除语音输入的功能。自己做不如用户自己用第三方产品。」`next/` 里做好的口述已经删除，不再排期；2026-11-19 作者确认把 0.1 客户端的口述也一并删除。

## 现在怎么口述

用系统自带的听写，或者任何能往输入框里打字的第三方语音输入法、听写工具。它们对正文和帮手输入框一样有效，不限于帮手输入框。

macOS 的听写挂在「编辑」菜单上，`dr-shell/src/menus.rs` 按这条规矩留着这个菜单。**还没有人在真窗口里试过系统听写和第三方工具**，要作者手测；发现打不进字，按输入法问题处理（[f4c-input.md](../foundations/f4c-input.md)）。

## 删掉了什么

- `dr-view-agent/src/speech/`：麦克风采集、百炼转写客户端、专名上下文、口述视图，连同 16 项契约测试。
- 帮手面板里的录音按钮、「语音转写」凭据区，以及「录音或转写期间不能发送」的限制。
- 麦克风用途描述：`app/drifting/build.rs`、`resources/microphone.plist`、`script/bundle-mac` 里的那一段。新版不声明、也不请求麦克风权限，正式签名不需要录音授权。
- 两个验收示例里的假转写服务，`scenarios/dictation.json`。
- 文案键 `voiceAgent.*`、`settings.models.speechTitle`、`settings.models.speechDesc`、`speech.backlog`。
- 音频采集依赖及它带进来的 12 个包。

`next/` 最后一版实现在提交 `cc339ce9c`；两个客户端都还带着口述的提交打了标签 `dictation-retired-2026-11-16`，0.1 客户端的口述于 2026-11-19 删除。`cargo xtask check` 的 `retired` 门禁拦着采集库、转写服务的键名和麦克风用途描述回到 `next/`；0.1 客户端由 `retired-client-integrations.acceptance.test.ts` 守着。旧版钥匙串里的语音 Key 两个客户端都不读，也不删。

## 为什么

- 原来的做法要作者自己去申请一个百炼 Key，录音和项目里的名字直接发给百炼。
- 2026-11-16 试过换成 App 自带的本机模型（sherpa-onnx，六个候选在本机实跑）。合成语音上小模型又快又准，作者真人小声说一段时，130 MB 和 155 MB 的两个小模型都漏词、错字；听得稳的 Qwen3-ASR-0.6B 要下载 837 MB、占 1.2–2.3 GB 内存。另外还要自己托管模型文件、解决 Windows 的链接方式和两个平台的打包。
- 系统听写和第三方语音输入对任何输入框都能用，质量由它们负责。

丢掉的只有一样：按项目里的人名、别名把专名写对。
