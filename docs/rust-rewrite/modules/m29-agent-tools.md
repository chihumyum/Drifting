## 做了什么（大白话）

- 模型只收到 `tool_search` 和 `call_tool` 两个入口。搜索按名称和说明返回分页结果、输入输出格式、读写类别和修订号；实际能力从 F3 注册表生成，没有第二份手写工具清单。
- 对象可以用 id、名称或已有别名定位；同名而无法唯一确定时返回歧义，不替作者选。正文也能用对象种类和名称定位。所有定位都限制在本次运行的书里。
- 正文读取附带可编辑文本、H1/H2/H3、稳定段落标记和批注标记。不改文本就不触碰 Loro；改一个已有段落时生成最小的精确替换，交给现有 `prose.replace`。
- 写入要求本会话、本作者回合读过对应对象和正文范围。读取版本过期时返回冲突，模型必须重新读。同一个目标在一回合内冲突两次，运行时结算错误后停止，不继续请求模型。
- 写入仍由 F3 和 M27 记录来源与结算。`history.agent_changes` 配合 `history.undo_agent` 按来源撤回，不重跑原工具。

本次注册表共 134 项，外观开放 111 项、明确排除 23 项；完整名字、排除原因和格式修订哈希由快照测试生成。旧版当前清单实际有 97 项，映射表按这个实数逐项核对，不沿用任务书中的约数。

## 定下的事

**读取内容和读取版本一起成立。** 正文在 holder 的一次读任务中取得段落和版本。元数据查询前后分别观察所有涉及文档；版本不同就重新读取，最多三次。F3 的规范缓存随 holder 提交同步失效，并用缓存代次阻止竞态填充；派生搜索和统计结果不获得正文或实体写入授权。

**读过一本书不等于读过书里所有对象。** 屏障记录对象、完整集合和正文段落的覆盖范围。部分正文只允许修改已读段落；链接和恢复等可能跨范围的操作要求完整正文。正文与同名元数据使用不同覆盖标记。新版本的读取会清除旧版本的覆盖范围，不会用新版本号替旧内容背书。会话结束时清除观察，取消后尚未退出的读取线程也不能重新发布观察。

**按来源撤回读取的是结算清单。** `history.agent_changes` 只授权撤回同一个 session／turn 的来源，不代表已经读过其中正文或实体，不授权普通修改。撤回时仍对涉及文档做 CAS，并由 F3 再检查字段或正文自原 Agent 写入后没有别人修改；不符合的部分保留并报告冲突。这一来源操作与基于正文内容的替换使用不同屏障。

**CAS 在实际写入处检查。** `Workspace::call_guarded` 把预期版本送入 holder，在修改前比较 Loro frontiers，因此编辑器或同步在模型思考期间的修改也受保护。新建正文先检查父书版本，后续写入只允许覆盖本次创建的初始版本；它仍遵循下述多文档边界。冲突次数按 holder 报告的实际文档累计，换工具名或改用多文档调用不会重置次数。工具修订号另行检查，避免工具定义变化后沿用旧输入约定。

**多文档调用沿用现有事务边界。** 每个文档在自己的写任务里检查并提交；后一个文档冲突时，前一个可能已经提交。外观不会自动重试整个写调用，M27 从持久化结算记录补齐已经发生的修改。这不是跨文档原子事务，也不声称它能回滚全部已完成部分。

**懒加载不改变提供商回放。** `ToolExecutor::describe` 为调度器解析 `call_tool` 的实际读写类别和策略；模型收到和回放的调用外壳保持原样。读操作仍受 M27 的并发上限约束，写操作独占，写入一旦开始就等到结算。没有新增本地写入权限档或确认开关。

## 接口与外壳里的挂接点

- `dr_agent_tools::AgentTools::new()`：交给 `Runtime::new` 作为工具执行器。M31 负责运行生命周期，M32 直接复用此对象。
- `catalog()`：注册表派生的目录；`search(Search)`、`manifest()` 和 `directory()` 给发现、快照或 MCP 使用。完整目录不附加到模型初始工具说明。
- `invoke(workspace, book, actor, CallRequest)`：同步共享入口；运行时在工作线程执行，MCP 也必须离开 UI 线程。`CallRequest` 包含 `name`、`arguments`、可选 `revision` 和仅用于 `prose.replace` 的 `edited_text`。
- `forget_session(session)`：连接结束时清理读取观察。M27 在运行结束、进入的写入结算之后自动调用 `ToolExecutor::finish_session`；MCP 连接拥有者也应调用。
- `prose::project` / `prose::plan`：投影与单段落替换计划。批注来自同书 `comment.list`，只挂接精确文档和可确定的段落；仅有游标的批注保留文档标记，不猜段落位置。
- F3 最小新增接口是 `Workspace::observe`、`Workspace::call_guarded` 和 `WritePreconditions`。没有新增命令或修改注册表输入格式；普通 `Workspace::call` 保持原调用方式。另修正了 `prose.read` 的正文／版本一致性，以及相同查找和替换内容产生无效写入的问题。
- `ToolOutput::Error` 结算结构化错误，`ToolOutput::Stop` 结算后结束运行。错误码 `read_required`、`conflict`、`conflict_limit` 可供 M31/M32 展示或处理；本地写入来源仍是 `Actor::Agent { session, turn, .. }`。

## 正文范围与待协调

1. F3 目前只有既有段落的精确替换、链接、解除链接与恢复，缺少可保留富文本的结构编辑命令。当前可编辑投影支持一次修改一个已有段落的文字；段落标记、批注标记和 H1/H2/H3 层级必须保持。新增／删除段落、调整层级、格式、嵌入内容和向空段落插入会明确拒绝。请 F3 提供按稳定 block id 和版本执行的结构／富文本编辑接口，再扩展此投影。
2. 精确替换沿用 F3 的删除加插入语义：未触碰内容保持，替换范围内的富文本标记以及为插入选取的相邻锚字符按该命令处理。当前不是可任意编辑的无损富文本 Markdown。未编辑投影的往返则逐字节保持原 Loro 快照。
3. F3 的 `history.restore_point` 在写入前创建历史标签，缺少标签与 CAS 写入的原子挂接点；暂不向 Agent 暴露。`history.undo_agent` 的来源撤回仍可用。请 F3 把恢复点的标签和版本检查收进同一个受守卫操作。
4. 级联清除涉及已隐藏的关系或已回收对象时，不能用只返回可见对象的列表冒充完整读取。目录及覆盖规则保守限制这些能力；请 F3 提供带版本的准确受影响对象查询，再开放相应级联。逐项状态见映射表。
5. 旧版工具中缺失的结构编辑、关系更新、原子故事线成员替换等不在这里另造存储路径；能由现有命令组合的保留组合方式，其余交 F3。M32 只能导出本目录实际提供的能力。
6. 账号、模型、外部插件和生图不由此作者域目录代办。M28/M31 管模型连接，M32 管外部插件，M33 管付费生图。

## 验收

契约证据均为 Rust 测试；注册表派生目录使用 insta 快照，由测试生成，不手改快照。种子与正文只取 `dr_testkit`。

- 假驱动完整跑通工具搜索、按名称定位、读正文、修改一个段落、按来源撤回；每次模型请求只有两个发现入口，实际写入仍按写工具调度。
- 同一正文两次遭遇并发作者修改，第一次要求重读，第二次停止；没有第五次模型请求，也没有失败 Agent 写入的结算记录。
- tiny / lite 种子的正文不改往返逐字节一致；覆盖稳定 block id、H1/H2/H3、Unicode、转义、批注定位和被拒绝的结构修改。
- 注册目录和修订号、输出外壳、分页搜索、按名称与别名解析、歧义、跨书拒绝、实体及正文读取范围分别断言。
- F3 检查陈旧元数据、正文和编辑器写入、新文档创建、损坏版本、真实无操作以及恢复点被拒绝时不落历史标签。
