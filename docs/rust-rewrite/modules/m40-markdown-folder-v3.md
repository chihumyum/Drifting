# M40 Markdown 文件夹（canonical v3 待定方案）

本页只定义 canonical v3 下 Markdown 文件夹双向同步的约束边界、供作者拍板的格式与交互选项矩阵、选定后的技术实现顺序与永久验收清单。**当前未接入 v3 文件监听、外部写回或 App 设置入口，本轮不写任何代码。**

切换前的第一期旧实现记录见 [m40-markdown-folder.md](m40-markdown-folder.md)，通用内核定稿见 [kernel-v3.md](../kernel-v3.md)，切换范围与保留边界见 [v3-cutover.md](../v3-cutover.md)。

## 1. 当前状态与保留边界

- **应用层零激活：** 第 70 批 canonical v3 切换（`ad97a43c`）已移除旧固定域路径映射、台账与后台监听（`dr-mirror` 的旧 `layout`／`ledger`／`service`／`sync` 及 `dr-shell/src/mirror.rs`）。App 运行时不再扫描或改写外部 Markdown 文件夹，磁盘上已有的外部目录与本机旧设置原样保留、不自动删除或改写。
- **独立原语保留：** `next/crates/dr-mirror/src/` 仍保留与旧目录结构解耦的底层原语，供作者拍板格式后复用或演进：
  - `body.rs`：段落与单行 Markdown 往返渲染、标点与边界内联标记转义（`<b>`／`<i>`／`<s>` 兜底）、表格与素材嵌入占位行（`<!-- drifting:embed <id> -->`）；
  - `merge.rs`、`merge_plan.rs`：基于 Loro `fork_at` 基线分叉的三方合并、Myers 行差异加字符二元组 Dice ≥ 0.3 段落配对、段内逐字最小编辑、基于 `(doc, base, file_bytes)` 派生 peer 的崩溃重放幂等去重、改动段落自动链接重识别；
  - `disk.rs`：临时文件刷盘后原子替换（权限 `0600`）、`.drifting/owner.json` 单安装独占认领、`.drifting/preserved/<timestamp>/` 冲突与异常原件另存；
  - `file.rs`：切换前 frontmatter 解析器（绑定旧固定状态枚举与单节点 ID，v3 须按新文件头规格重做，不可直接启用）。
- **旧证据不沿用：** [m40-markdown-folder.md](m40-markdown-folder.md) 中的旧测试与测量仅对应切换前章节／构想双目录模型，不能作为 canonical v3 的通过证据。

## 2. 已知 canonical v3 硬约束

无论最终选用哪种目录组织与文件格式，v3 实现都必须满足以下内核不变量：

1. **树住处、多归属与时间线严格分离：**
   - 每个条目在 `entries`（`LoroTree`）中**只有一个树住处**，兄弟先后构成唯一的文稿顺序。
   - 开了「收别处的条目」的层级（如故事线泳道、多归属分类）通过 `memberships` 引用条目，不复制条目本体；时间线摆放（`timeline_views.placements`）与时间钉（`pins`）完全独立于文稿树。
   - 磁盘路径最多只能反映单一条目住处（或平铺清单），**绝不能把多归属或时间线泳道映射成多份可写文件副本**。
2. **多正文模块与层级说明各自独立：**
   - 叶子模板可声明 0 到多个正文模块，每篇正文是独立的 `body:<entry_id>/<module_id>` 文档；每个层级条目自带一篇说明文档 `body:<entry_id>/about`。
   - 模板初始正文存于 `template:<book_id>/<template_id>/<module_id>`，与作者条目实例严格隔离；**模板文档绝不作为普通条目正文混入外部双向同步**。
   - 文件身份不能只记裸 `entry_id` 或靠文件名反推，必须精确锚定到 `(library, book, entry, module, doc)`。
3. **非正文模块与换模板保留数据不被抹除：**
   - v3 条目除正文外还可含字段（`fields`）、自由键值表（`kv:<module_id>`）、补丁（`patches`）、情节规划（`plot_grids`）与关联（`relations`），且换模板后旧模块数据仍保留在「原来的内容」中。
   - Markdown 文件只承载已明确定义为可表示的子集；**文件未写出的模块、隐藏字段、未知枚举值、补丁、情节规划、关系与条目布局（`layout`）在读回时必须原封保留，严禁整份重建条目或把“文件里没出现”解释为删除**。
4. **标题层级语义中立：**
   - 正文内 `#`、`##`、`###` 仅对应 H1、H2、H3 三级标题，含义完全由作者决定；文件头、导出注释、通知文案与同步规则中均只称 H1／H2／H3，不赋予任何固定叙事角色名称。
5. **Loro 与应用托管资源仍是唯一事实来源：**
   - Markdown 文件夹是受限的外部编辑投影，不替代 `.driftingbook` 单书归档或 `.drifting` 整库备份。
   - 正文内人物与条目链接（`EntityLinkV3`，目标种类 `entry`／`material`、可选 `module` 与 `target_block` 范围）、批注锚点（Loro 光标对）、段落块 ID、对齐与缩进属性在未改动的范围中必须无损保留。
6. **双书隔离与多安装隔离：**
   - 同一库内所有书共用 `loro_doc` 表（`doc_id` 全局唯一），但外部文件夹按书分目录并绑定具体 `book_id`。一本书下的外部文件即使伪造或篡改文件头中的 `entry_id`／`doc_id`，也绝不能读取、覆盖或删除同一库内另一本书的文档、模板、资源或台账，更不能越界访问书目录之外的路径。
   - 一个外部根目录在同一时刻只归属一个 Drifting 安装实例（`installation_id` + `bundle_id`），跨设备同步只走 Hosted 同步 v2，严禁两台设备或两个 profile 共指同一同步文件夹造成双端重复读入。

## 3. 供作者拍板的格式与交互选项矩阵

以下七组决策属于产品设计与外部编辑体验取舍，待作者选定后再进入编码：

| # | 决策项 | 可选方向 | 体验与实现影响 | 必须守住的安全底线 |
| --- | --- | --- | --- | --- |

| 2 | **多正文模块的文件颗粒度** | **A. 单正文模块单文件**（条目仅一篇正文时用 `<条目标题>.md`；多篇正文时拆为子目录或 `<条目标题> · <模块名>.md`）<br>**B. 单条目单聚合文件**（用受保护分隔符串联同一条目的多篇正文模块） | **A** 每个文件严格对应单一 `LoroDoc`（`body:<entry>/<module>`），基线 frontier、SHA-256 与冲突粒度天然一一对应；**B** 磁盘文件数更少，但作者误删分隔符会导致整份文件无法归属到具体模块而必须拒绝并另存 | 单文件或单分节都必须携带明确的 `entry_id` 与 `module_id` 机器身份；模块改名或增删模块不能静默串写到另一篇正文 |
| 3 | **磁盘目录结构** | **A. 跟随条目树住处嵌套**（树层级即子文件夹，可选是否加文稿序数字前缀如 `001 `）<br>**B. 按顶层根层级分桶＋桶内跟随子层级，不加序号前缀**<br>**C. 固定平铺目录＋可选只读目录索引文件** | **A** 在访达与 Obsidian 中最直观反映书稿／构想／要素层级，但树上移动、改名或调整文稿顺序会批量改文件路径（若带序号，插一章会重命名后续所有同级文件）；**B** 兼顾层级可读性与插入稳定性；**C** 改名与重排最稳，但外部浏览缺少树层次 | 仅树住处（`entries` 父子）决定路径；`memberships` 多归属与 `timeline_views` 永不生成第二份可写文件；路径变化前必须先合并未读外改 |
| 4 | **文件头（Frontmatter）与元数据读回范围** | **A. 仅同步正文，文件头只放只读身份键**（`drifting-book`、`drifting-entry`、`drifting-module`）与第三方编辑器自留键（如 `tags`）<br>**B. 正文 ＋ 白名单标量字段双向同步**（如单选状态、纯文本摘要／梗概，按模板字段 ID 或固定别名映射） | **A** 完全消除动态模板字段改名、重名字段与类型校验冲突，实现最稳；**B** 保留旧版在外部改“写作状态／摘要”的顺手体验，但 v3 字段归属具体 `Fields` 模块且由模板自定义，需明确哪些字段类型可投影、重名字段如何消歧 | 第三方未知 frontmatter 键必须原样保留写回；文件头缺少某字段或值非法时只能忽略或整文件报 `Frontmatter` 问题停写，绝不清空条目已有字段值 |

| 7 | **冲突提示与编辑器显现** | **A. 沿用蓝色外部墨色（`source: file`）＋ 同段重叠修改挂一条待办 ＋ 删字超半数自动打条目快照**<br>**B. 仅蓝色未读显现与通知中心问题提示，不在书目文档自动新增待办** | **A** 与旧版及 [m31-agent-panel.md](m31-agent-panel.md) 预留的蓝色显现完全对齐，需接通 G1 条目完整快照打点与 v3 带模块批注命令；**B** 外部合并只改目标正文文档、零书目文档副作用 | 合并写入不得覆盖未结算的作者本地编辑草稿或输入法组字；失败或越界一律走通知中心与 `.drifting/preserved` 另存，不静默吞错 |

## 4. 技术实现顺序（作者拍板格式后）

作者确定上述选项后，按以下五步自底向上推进，每一步先写契约测试再接上层：

1. **定义版本化文件头协议与本机台账（`dr-mirror` 数据层）：**
   - 升级文件头 schema（明确携带格式版本号、`book_id`、`entry_id`、`module_id`，以及按选项 4 决定的可选白名单字段映射）。
   - 在 `dr-store` 的 `local_state`（独立命名空间如 `mirror_v3`，与旧 `mirror` 键隔离，避免误读切换前残留台账）记录每本书的认领目录名与每个导出文件的 `(book_id, entry_id, module_id, doc_id, rel_path, sha256, stat, base_frontiers, base_fields, extra_frontmatter, unmerged_sha256)`。
   - 路径构造统一经过 NFKC 归一化、非法文件名字符清洗、大小写不敏感撞名稳定后缀（基于 `(entry_id, module_id)` 短哈希）、目录逃逸与符号链接拦截。
2. **实现只读投影与严格往返预检（无副作用层）：**
   - 从同一 `BookV3` 快照 revision 与对应 `body:<entry>/<module>`（及可选 `about`）读取可表示内容，生成目标路径树与文件字节。
   - 补齐属性测试：任意包含中英文、Markdown 特殊标点、H1/H2/H3、引用、分隔线、五种行内样式、网页链接、`EntityLinkV3`（含 `module` 与块范围）和表格／素材嵌入的随机 v3 正文段落，写出后再按解析器读回，在无外部改动时产生**零字节 Loro 更新**且所有原有属性与链接精确不变。
   - 明确不可表示或损坏输入的失败分类（`Frontmatter`、`WrongBook`、`WrongEntryOrModule`、`DeletedTarget`、`UnknownBase`、`Emptied`、`NotUtf8`、`TooLarge`、`SymlinkOrEscape`、`OwnedElsewhere`），错误定位到具体书、条目、模块与文件路径。
3. **接入带身份与版本守卫的最窄写回（`dr-workspace` 协调层）：**
   - 正文合并继续在 `base_frontiers` 分叉上计算最小字符与段落属性增量，导入前核对活动库实例、`book_id`、条目存活状态与模块存在性；若配置了大幅删除保护（选项 7A），在首次提交前先调用 v3 条目快照接口打点。
   - 若开放白名单字段读回（选项 4B），必须使用基于 `base_fields` 与观测 revision 的局部字段更新（`Workspace::call_guarded`），只改发生变化的那一个字段键，绝不整份写回 `Fields` 模块或覆盖并发修改的其他字段。
   - 若开放同段重叠待办（选项 7A），通过 v3 批注命令指向精确 `(Entry, module, block)` 锚点，且同一段已有未解决外部重叠待办时不重复创建。
4. **完善异常保护、另存恢复与崩溃幂等（磁盘安全层）：**
   - 写出前核对磁盘当前字节或 `(size, mtime)` 与台账一致：凡发现磁盘存在未读外改，先取消本次覆盖、转入读入合并轮次。
   - 遇到身份失配（如把 A 书或甲模块的文件拷到 B 书或乙模块路径）、基线缺失、清空正文、条目／模块已移入最近删除或切换前遗留无 v3 头旧文件时，先将磁盘原文件完整复制到该书 `.drifting/preserved/<timestamp>/` 下（磁盘空间不足或另存失败时**立即中止替换，绝不破坏原文件**），再决定重写或停写报错。
   - 验证在「Loro 已提交合并、台账尚未落盘」任意点崩溃重启后，依靠确定性 `(doc_id, base_frontiers, file_bytes)` peer 重放不会产生重复文字或重复待办。
5. **最后挂接应用生命周期、设置界面与释放屏障（`dr-shell` 外壳层）：**
   - 在设置「本地数据」与通知中心接回 v3 版文件夹开关、路径选择、「在访达中打开」与问题列表（九语种 `dr-i18n` 文案齐全）。
   - 严格接入 `dr-shell/src/release.rs` 的 `before_release`／`after_drain`／`after_release` 屏障：换库、重导开发库、关闭书库或退出应用前，先停止新监听轮次、排空正在合并或待刷盘的同步任务并关闭后台 watcher 线程；若排空或保存失败则阻止释放并保留现场，绝不在库关闭后继续持有旧 `Workspace` 句柄读写文件。

## 5. 必须通过的永久验收清单（数据不丢与双书隔离）

未来实现合入 `main` 前，除常规全套门禁外，必须新增并长期保留以下机器可检查测试：

1. **v3 结构与多模块往返契约：**
   - 基于 `dr_testkit::seed` 的 canonical v3 `tiny`／`lite` 与合成样书构造覆盖用例：单条目多篇正文模块、层级 `about` 说明（若启用）、同层级同名条目（含仅大小写不同与全半角标点差异）、多归属条目（验证磁盘只出一份文件）、换模板后带隐藏保留模块的条目、含默认字段值与未知枚举值的条目。
   - 全量写出后逐文件当作“外部重新保存但内容未改”读回一遍：全部正文文档与书目文档的 Loro frontiers 不前进（或零语义差异），非正文模块（键值表、补丁、情节规划、关系、`layout`、时间线视图）逐值完全不变。
2. **并发双写与局部冲突契约：**
   - 作者在编辑器修改第 1 段的同时外部编辑器修改第 3 段：合并后两处修改均在原段落身份上保留，写回磁盘后的文件同时包含两边内容，再扫一轮零额外写入。
   - 作者在编辑器修改某字段／添加批注的同时外部修改正文（及白名单另一字段）：各自成功、互不冲掉对方刚提交的值。
   - 同一段同一位置并发改写：两边文字均保留、不丢字，按已定冲突提示规则准确触发（且重复扫描不重复挂待办）。
3. **双书隔离与删除不复活契约（核心红线）：**
   - 同一库内同时存在书 A 与书 B：
     - 在书 A 外部目录中将文件头篡改为书 B 的 `book_id`／`entry_id`／`doc_id` 并修改正文：书 A 报身份错误并另存该文件，**书 B 的全部 Loro 文档版本、正文内容、字段、资源字节与台账行零变化**。
     - 删除书 A（或移入最近删除／彻底清除）：书 A 对应台账与同步状态按规则清理，书 B 的外部文件、`.drifting/owner.json`、Loro 文档与资源一个不少。
