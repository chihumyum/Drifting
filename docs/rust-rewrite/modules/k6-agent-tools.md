# K6：通用帮手工具与书的结构说明（方案）

2026-11-09，轨道 3。按 [夜间队列](../handoff/overnight.md) 第二段交回；**本段只写方案，不实现、不登记工具、不修改目录快照或 F1／F3 结构。** 数据语义以作者定稿的 [kernel-v3.md](../kernel-v3.md) 为准，实施排在 K2 通用命令之后。

前一段 M30、小说提示词集中、M32 P2 复验和 M34 已在 `9e8be2f5` 第一次交回，见 [M34 结论](m34-dictation.md)。本方案不重做这些机制，不做 M33，不恢复冻结的 M11／M13／M14／M16／M17／M19 产品收尾。

## 已有基础与目标

当前 [M29](m29-agent-tools.md) 的 `Catalog::new` 从 `dr_workspace::registry` 投影目录，`AgentTools` 执行名称解析、读取覆盖、版本保护和来源结算；[M31](m31-agent-panel.md) 提供作者提问与库级 controller；[M32](m32-mcp.md) 复用同一作者工具面。模型的三个内建入口仍是 `tool_search`、`call_tool`、`ask_user`，另有作者已配置的 MCP 插件入口。K6 保留这种惰性发现，不把每个模板动作另注册成提供商函数。

v3 需要换掉目录内部按种类的命令和解析器：帮手操作条目、模块、归属、时间线，认识来自当前书内的模板和说明。读写仍经过一个进程内 Runtime、一个 F3 命令注册表、一条带结算的执行管线。模板说明不创造命令，模板动作也不能绕过这条管线。

本方案核对的 main 已接 K1 第 1–4 步（第三十六批，`574e7a4f`）：`dr-model/src/v3.rs`、`dr-doc/src/v3/`、存储识别与 v3 种子已经有了，K2 通用命令尚待接入。下文区分现有数据接口、拟议的 facade 接线和仍缺的 F3 能力，不把数据读写器当成已经开放的 Agent 工具。

## 通用能力怎么分

下表是能力分工，不是第二份可执行工具清单；最终命令标识、Schema、读写类别和并发类别均从 K2 的注册表生成。

| 对象 | 读 | 写及边界 |
| --- | --- | --- |
| 条目 | 找／读条目，分页列子条目，读树上住处、模板和原来的内容 | 新建、移动住处、兄弟重排、改名、换模板、回收、恢复。层级／叶子由模板决定；不把标题或模板名称当内建种类 |
| 层级设置与模板 | 读模板、模块定义、层级的有效设置及其来源 | 使用 K2 的模板／模块／覆盖设置命令；改模板不清旧数据，层级换叶子前必须没有子条目；模板只能在无人使用时删除 |
| 正文模块／层级说明 | 按条目和模块定位，分页读正文、段落及可编辑投影 | 走现有 prose 管线与 K2 提供的结构编辑能力；多篇正文须明确模块。层级的说明是 `about`，不是继承来的叶子正文 |
| 字段／键值表模块 | 读字段定义、类型和值，或具名键值项 | 按模块写特定字段／项；别名按 `FieldType::Aliases` 等类型识别，不硬编码“人物”“别名”字段名 |
| 补丁／情节规划模块 | 按条目＋模块读补丁、来源锚点、格子 | 沿用注册的补丁／格子命令，目标加模块；不再假定每章只有一张表 |
| 关联模块 | 投影此条目的关系和关系类型 | 委托现有全局 `relations`／`relation_types` 命令。关联模块本身不存另一份关系 |
| 归属 | 读接收层级、成员、主归属及有效性 | 加入、移出、设主归属。归属不改树上住处；是否允许由接收层级的有效设置决定 |
| 时间线 | 读视图、泳道顺序、成员与本视图的位置、时间钉 | 建／改视图，增减或重排泳道，条目入泳道、定位／改长度、移出，时间钉增删改；均显式指定视图，不从文稿树推算位置 |
| 项目外对象 | 关系、批注与现有待办入口、素材／素材夹、事实、Project Memory、搜索、历史等 | 保留当前已开放的注册操作，适配条目／模块引用。未登记的能力不因表中出现一个名词就自动补齐 |

### 住处、归属、时间线分别执行

树上只有一个住处，兄弟先后是文稿顺序。移动住处与加入归属是不同命令；主归属也不等于住处。叶子没有“可属于几处”的开关。接收层级必须收别处条目并允许其模板，泳道层级始终收别处条目。设置解析复用 `BookViewV3::level_settings`／K2 的规范读取结果，顺序为自身覆盖、自己的模板、最近祖先、默认值，模型不自行重算。

泳道成员取全局归属，不取树上的子条目；只有在某视图的泳道中、且在该视图有 placement 的条目才显示。一个条目在同一视图的两条泳道中共用同一位置／长度，在另一视图可以不同。删除最后一个相关泳道归属时，K2 同时处理相应 placement；共享泳道在多个视图里的影响必须出现在受影响集合与回执中，不能假装只改当前视图。时间钉可挂任意条目，不恢复幕轨或“按书序”时间轴。

删一个层级时，住在其中的子树与仅归属到它的条目分别计算；后者本体不能跟着删。所有级联、自动链接和关联影响由 K2 的受控命令／查询给出，facade 不根据当前可见列表猜出完整集合。并发合并后的不合法归属、缺失模板、无效泳道等，沿用 F1 的读取容错与数据保留，不在 Agent 读取时顺便修库。

## 目录与模板动作

### 按书和版本生成目录

将目前静态目录的实现改成两部分：注册表的、按文档版本筛选的基础投影，加当前书有效层级实例的模板动作绑定。两者构成同一个 `CatalogSnapshot`（逻辑上的内存快照，不是新持久文档）。controller 在请求开始、外部 scope 建立时取得它；排队调用执行前重新校验书的代次及依赖修订。

基础投影需要 K2 的命令规格明确标出支持的书版本、当前书作用域及所需目标，不再仅靠参数里有没有 `book` 推断权限。v2.2 与 v3 使用各自目录和 resolver；v3 调用不能落到旧 `chapter.*`，不支持的版本明确失败。仍按 M29 的排除表筛选，再投影完整输入／输出 Schema、访问与并发类别、revision、Outcome／journal。注册表新命令不能无审查地全部放行。

快照缓存键至少包含库实例／epoch、书及其代次、schema 版本、F3／facade 语义版本、模板与动作定义、有效设置和说明依赖的修订；内部库身份不作为本机路径发给模型。同一模板被两个层级使用，会产生两个有各自层级绑定的动作。缓存不能只按模板名，也不能因面板切书而让仍在旧书运行的会话改绑新书。

### 当前 TemplateVerb 的确定解释

已合入的 `TemplateVerb` 有 `id`、`name`、`description`、`target_template`、`pos`，**没有任意命令或脚本字段**。小说模板现有动作全部是“在这一层新建某模板的条目”。K6 首版按这套数据生成通用新建动作：显式 `target_template` 优先，否则取该层级有效默认模板；两者都没有时不生成可执行的新建入口。不会根据动作名称猜“转换”“删除”或别的执行语义。

生成与执行按下列顺序：

1. 读取书内的层级实例、它使用的存活层级模板及 verbs；用 `(book, level entry, template, verb.id)` 作稳定动作引用。作者名称用于发现与显示；重名动作返回各自所在路径，不取第一个。叶子模板、缺目标模板或不合法绑定不生成可执行项，诊断随结构读取结果返回。
2. 绑定 K2 的通用新建命令。固定当前书、接收层级、目标模板和经规范解析的默认住处；模型只填该动作允许变化的参数，例如标题。输入 Schema 从该命令派生，隐藏固定参数，执行时仍拒绝模型伪造／覆盖这些参数。
3. 同时检查住处层级与归属接收层级的约束、模块能力、读取覆盖和 CAS；不能用“这是模板动作”免除普通写入检查。已存模块 `agent.writable = false` 只能收窄能力，`true` 不额外授予写权限或取消版本保护。
4. revision 绑定注册命令语义、动作定义及有效设置；排队期间作者改了模板、动作或住处，拒绝旧绑定，重新发现／读取。动作说明变化同样使旧快照失效，不自动重放写入。
5. 执行仍进入 M29／M27 的调度、Origin、结算与来源撤回。需要正文与书目两份文档时，沿用先正文后书目和实际 journal；失败后查看已提交部分，不承诺整体回滚。

例：书稿的“新建章节”绑定当前书稿层级及“章”模板。在故事线泳道层级执行同名动作，使用那一层的默认模板／显式目标模板，新条目按有效 `home` 住进书稿，再归属到该泳道。本体不能住进两处。仅有泳道归属不自动赋予任何视图位置；从某时间线视图明确发起定位时才带该视图及位置，不拿文稿顺序充当坐标。

动作需要的“新建＋住处＋归属”必须是 K2 登记的受控语义，不能在 facade 私拼三次命令并称为原子操作。若 K2 尚未提供完整接口，就暂不开放这种组合动作。其他操作仍用基础通用工具；将来要让 verbs 声明转换等其他动作，需 K2／K5 先给有类型的绑定契约，不能让自然语言说明执行任意命令。本方案不自行给 v3 添加字段。

### 作者名称与调用引用

`tool_search` 返回作者写的动作名称、所在层级路径、参数 Schema、revision 和稳定动作引用。提供商只看到原有 ASCII 入口名，作者名称中的中文、空格等不受提供商函数名限制。两个“新建章节”不能靠字符串名称区分；调用使用返回的动作引用。

对外 MCP 同样以稳定的技术标识作 tool name，作者叫法放显示标题／描述及所在路径；技术标识反解到同一 scope 的动作引用，不能再建一份执行目录。作者改名不改动作身份，revision 仍因说明／绑定变化而更新。

这要求将当前 `CallRequest.name` 单一寻址改成互斥的注册命令引用／模板动作引用，或等价的有类型 target；明确提升 facade revision 与 Schema，保留 v2.2 路径的原有行为。具体字段随实现评审确定，不能仅把现有 `name` 替换成中文后继续做全局字符串查找。引用只解决寻址，执行端仍验证当前书、代次和完整 revision。

## 每次请求的“这本书的结构说明”

来源是**当前书已复制并由作者维护的模板**：`TemplateAgentConfig::{name,description,instructions}`，加各模块 `agent.instructions`，并配上当前条目／层级、有效设置和可发现动作。不能根据 `meta.project_template` 回到 App 里拿最新小说提示词；该字段记录来源与版本，不代表持续绑定 App 模板。

同一次规范读取快照产出 `StructureContext` 和目录依赖版本。下面只是请求上下文的投影示意，字段不是新增的 Loro 根容器或持久 Schema；省略号代表示例未列出，实际装载不能靠省略号丢弃固定指导：

```yaml
book: <当前书的 opaque id>
schema_version: 3
structure_revision: <书目 frontier 与模板依赖摘要>
project_template_source: <来源 id 与复制版本，仅供说明>
roots: [<顶层条目的引用、作者标题、模板引用和层级／叶子类别>]
templates:
  - ref: <书内模板 id>
    kind: leaf
    name: <作者模板名称>
    agent:
      name: <原文>
      description: <是什么、什么时候用，原文>
      instructions: <注意事项原文>
    modules:
      - ref: <模块 id>
        kind: prose
        name: <作者模块名称>
        agent: <模块说明原文>
        capabilities: <注册表与模块定义共同允许的读写能力>
levels:
  - ref: <当前或相关层级 id>
    path: [<祖先引用>, <本层引用>]
    template: <模板引用>
    effective_settings: <规范解析的值及来源>
    actions: [<带 revision 的动作引用>]
manuscript_roots: [<最外层成书层级引用>]
focus:
  entry: <本轮要处理的条目引用>
  home: <树上住处>
  memberships: [<接收层级引用>]
  modules: [<可读模块／层级说明的引用与文档修订>]
  timeline_view: <若本轮明确涉及某视图>
```

组装规则：

1. 给出当前书的顶层条目索引，再从存活条目使用的模板开始，加入有效默认／允许模板、有效动作目标模板以及焦点条目的祖先和归属所需模板。尚未创建第一个叶子时，默认模板的说明也要在。无关的未使用或已删模板不塞进固定前缀；缺失模板、保留的旧模块要在相关条目读取中明确报告。
2. 模板按稳定 id、模块／动作按规范顺序输出并去重；条目标题和路径是转义的数据，不能拼成新的指令段落。层级只带自己的说明、字段、键值表及管理设置，不把层级的模块继承给叶子。
3. 模板说明是作者配置的项目指导，服从作者本轮请求与通用执行规则。正文、名称、素材、搜索结果、外部结果仍是数据；不能因为引用中写了“调用某工具”就变成模板动作或新的授权。
4. 模板说明不替代读取原文，也不自动授予普通写入的读取覆盖。叶子正文、字段值、关系和受影响集合按工具分页读；当前焦点只给已明确选择的上下文，不把编辑器选择偷偷变成作者请求。
5. `ModuleAgentConfig.read_tier` 只作装载偏好，摘要不能当全文阅读记录。固定指导超过 M30 容量时暂停，不静默删作者注意事项；正文按需读取，不能为腾空间删原请求或把文学摘要冒充无损索引。
6. 每次作者请求和长任务分片开始都校验说明／目录的当前修订，重启恢复也重读；前一轮 system prompt 和持久历史不被重写。结构变化使原有任务范围过期时，走 M30 对齐和重新读取，不能仅把旧章节 id 换个显示名后继续写。

正文引用由宿主解析到实际 DocId 和段落覆盖。模型按书内条目＋模块引用读写，不自行拼 `body:<entry>/<module>`、`body:<entry>/about` 或 `template:<template>/<module>`。同名的多篇正文必须消歧；被换模板保留下来的“原来的内容”继续可读，不映射到新模板里碰巧同名的模块。

## 小说提示词搬到哪里

轨道 3 已把临时内容集中在 `dr-agent/src/novel_template.rs`（`945e3632`）。K1 已有真正的 `dr-doc/src/v3/novel.rs` 工厂和书内 `TemplateAgentConfig`；后续搬移以这个工厂／配套模板资源为单一源，不能再在 controller、provider、MCP 或 UI 各留一套小说兜底。

| 现在的内容 | v3 落点 | 通用运行时保留什么 |
| --- | --- | --- |
| `PROJECT_GUIDANCE` 的章节／构想／要素／故事线／幕等枚举 | 小说项目模板各层级／叶子的 `agent.description`、`instructions`，全书指导放在书稿层级模板；幕不再内置 | 作者意图优先、不捏造作者已定要求或实际能力、作用域与工具诚实性 |
| `OUTLINE_GUIDANCE` 与 `OUTLINE_LABEL` | 小说模板说明默认书稿／章及作者命名层级；结构标题由实际树与模板名称得到 | 稳定块／批注锚点、H1/H2/H3 无固定叙事角色的约束、当前 F3 实际可编辑范围；不把单段能力写成整篇替换 |
| `CHECKIN_SYSTEM_PROMPT` 的文学与要素维护部分 | 小说相关模板的 `agent.instructions`，随同书的结构说明参与建议生成 | 一次无工具请求、0–4 张卡、证据／记忆约束、卡片点开才运行、输出格式与作者语言 |
| `organize()` 的“章／构想→维护要素、补丁、关系”任务 | 小说模板对应说明，保留原有任务边界：读证据、维护记录、不擅改原文或删除 | 来源差分、批次／消费游标、节流、点击后普通会话、取消与结算；changed target 改用通用条目／模块／正文引用 |
| `Starter::{Outline,Interview,Cast,Comment,Tighten,Relate,Complete,Extract}` 及八个旧键绑定 | 小说项目模板的配套本地化资源及相应模板说明，移出通用运行时模块 | 普通作者请求的发送和既有 onboarding 完成机制；不能把自然语言 starter 当成 F3 verb 工具 |

迁入 `instructions` 的任务指导要注明适用条件：“整理”不改正文、不删除的边界只约束整理任务，不能变成所有会话的禁止。作者明确要求创作、改写或删除时，仍按本轮请求与实际工具能力执行。

新建小说书时，工厂将小说指导填进书内模板；随后每次请求只读这份副本。App 更新或界面语言切换不能悄悄改写既有书的说明／名称；作者删除或改写指导后，运行时不得从 `builtin:novel` 恢复旧提示。已有书的模板更新应走作者明确选择的模板更新流程，K6 不加后台替换。

小说的自动整理意图也必须来自模板说明：本机差分产生通用正文证据，建议阶段结合模板指导决定合适任务；不在通用代码里按 `chapter`／`idea` 造“整理要素”任务。没有这类指导的项目，不强加维护小说设定的卡片。若保留独立整理卡或八个固定 starter 的界面槽位，由 K4／K5 对齐其通用入口；本方案不为它们新造持久字段、脚本 verb 或一份 Agent 项目文档。

迁移翻译沿用唯一来源：旧键登记 `keys.txt`、运行 `sync-locales.py`；没有旧键的真实界面标签才进 `own/` 九语言。既有 starter 的翻译不复制进 Rust 常量，不手改 `locales/`；工厂填充说明与 UI 快捷请求的职责分开。此文不新增产品说明文案。

F1 的工厂不能反向依赖 `dr-agent` 或 UI 本地化层。小说文本／旧键绑定归项目模板的配套资源，允许的上层组装者先解析本地化，再以普通数据参数交给工厂复制进书；种子也使用同一模板源。所需工厂参数由 K1／K5 协调，不为搬提示词制造反向 Cargo 依赖。

## 执行与相邻模块

- **M29／M27：** 执行前将作者名称或返回的引用解析成当前书内身份；先读目标，普通写入记录完整所需元数据、模块／正文范围及 frontier。发现工具和结构说明都不是写许可。二次同文档冲突停止；部分提交只认 F3 回执，不能盲重放或伪称全撤销。模块的 Origin、来源撤回和快照恢复不能省略。
- **M30：** 整书范围用成书根与通用条目／模块枚举，证据与计划步骤绑真实目标、当前正文及结算；结构变化重新对齐。保留本机计划、工作记忆、上下文、两次无进展暂停和重启不自动续跑。本方案不借工具改名补注册任务计划／工作记忆伪工具；模型接入这些宿主 API 仍单列协调，提示词不要求调用不存在的入口。
- **M31／K4：** 跳转引用带条目、模块及可选块／锚点，作者名称只作显示。隐藏、切书、关窗、退出继续走原 controller／worker ACK 屏障，不因生成新目录换一个 driver。
- **M32：** 对外目录与聊天使用同一按书／版本快照和同一执行 facade，外部 scope 不另维护 CRUD 清单；共享的是不可变目录，各 session／scope 的读观察、授权和来源不合并。客户端通过同一结构读取能力取得说明，不在协议服务里另写小说 system prompt。结构或动作修订变化要使旧目录不可用。既有入站授权、出站 `ExternalPlugin` 确认及未知结果不可重放的规则保留；模板动作只能绑定本地作者命令，不能包装凭据或外部插件绕开确认。
- **M34：** 语音管线不变，专名适配器改读通用条目标题和类型为 aliases 的字段，优先有效自动链接范围，再按原容量规则补充其他标题。ASR 只接收名称数据，不接收模板指令，不加语音工具或新服务。
