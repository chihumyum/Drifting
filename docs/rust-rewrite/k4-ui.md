# K4：界面接回 v3（方案）

2026-11-09。K1+K2（v3 的数据层和通用命令）已经合进 `main`，K3（旧库导入成 v3、样书）在收尾。这一页说怎么把冻结的界面接到 v3 上，接完就切换。方案本身见 [kernel-v3.md](kernel-v3.md)，分轨和交回见 [handoff/kernel-v3-split.md](handoff/kernel-v3-split.md)、[handoff/overnight.md](handoff/overnight.md)。

## 目标

在 App 里打开一本 v3 的书（种子，或者从旧版导入的书），能照今天的方式写下去：写章节、管构想和要素、看时间线、搜索、看字数、审阅、导出、用帮手。作者看到的和今天一样，只是底下换成了 v3。做到这一步就切换。

## 两种书并存，最后一次切换

- **同一个 App 里，v2.2 和 v3 的书都能打开。** 书架上两种书都在，打开时按书的版本走两套页面。
- **2026-11-10 起 v2.2 冻结**（作者定）：next/ 里的 v2.2 没有真实用户（作者日常用的是 0.1 版，开发库随时可以从 0.1 重新导入），所以不再为它写新测试，也不再因为它退回。改 v3 时碰坏了 v2.2 的测试，可以删掉那条测试，在交回里列出来；v2.2 的代码切换时整套删掉。
- 切换前，v3 的书只靠开发手段来：`cargo drifting workspace scenario seed:v3-lite`（tiny、lite、heavy、showcase 四档），或者用 K3 的路径把旧版库导入成 v3。界面上不给作者新建 v3 的书。
- **切换**就是：新建书改成 v3；开发库从旧版重新导入；删掉 v2.2 那一套页面、命令和数据层。

现在的界面怎么拿数据：外壳有一份书的快照 `dr_shell::book::Book`（章节、幕、要素、分类、故事线、构想……各一张列表），各个视图从快照读，经 `Workspace::run::<命令>` 写；导航目标 `dr_shell::nav::Target` 按种类分（`Chapter`、`Idea`、`Element`……）。K4 要给这两样各加一个 v3 的版本，其他视图都挂在它们上面。

## 第一步：外壳（K4-0，一个会话）

各组都要用的东西，先由一个会话做出来。分两次交回。

**第一次交回（接口，交了各组就能开工）：**

1. **v3 的书快照**：条目树、模板、每个层级的有效设置（含来源）、归属、时间线视图；从 v3 的查询读，书变了就刷新。外壳按书的版本持有 v2.2 或 v3 的快照之一。
2. **导航**：`Target::Entry(条目 id)`，可以带模块 id（跳到某一篇正文）；`Target::Template(模板 id)`，给 K5 的模板编辑器用。标签、前进后退、页内位置跳转照旧。
3. **页面怎么拼**：
   - 叶子页按模板里模块的顺序，一个模块交给一个**模块渲染器**画。外壳给注册口（比如 `add_module_view(模块种类, …)`），各组注册自己的。
   - 层级页由三块组成：这一层的说明、下面的条目（按「显示」设置交给**显示渲染器**画，注册口比如 `add_level_display(显示方式, …)`）、这一层的设置。
4. **条目的记号和颜色**：一个公用函数。按模板的记号和颜色画；章节这类叶子的颜色跟主归属的泳道走，和今天一样。
5. **开发手段**：`seed:v3-tiny` / `v3-lite` / `v3-heavy` / `v3-showcase`；调试桥能打开 v3 的书、读出 v3 页面的状态。

**第二次交回：**

6. **左栏**：每个顶层层级是一个标签。小说模板默认就是书稿、构想、要素、故事线四个，对应今天的章节、构想、要素面板。标签里的内容按那一层的「显示」设置交给显示渲染器。左栏底部是模板集合（K5 定的位置），这里只放列表和新建按钮，编辑器归 K5。
7. **条目的悬停卡**：公用的头部和操作行（打开、新建、编辑模板、换模板、归属到、放进最近删除）。各组只往里加自己的行。

K4-0 交完第二次以后，`dr-shell` 的左栏（`workspace/sidebar.rs`）和大纲栏（`workspace/outline.rs`）交给 G2；其余部分仍然由 K4-0 维护，各组要加接口就写进待协调。

## 开工细则（2026-11-09，K4-0 交回以后）

K4-0 的两次交回见 [f6-shell.md](foundations/f6-shell.md) 的「K4-0」各节。外壳已经给出：`dr_shell::v3` 的 `add_module_view`（按模块种类）、`add_level_display`（按显示方式，左栏和层级页共用一个渲染器，`LevelHost.surface` 区分）、`add_entry_action`（`EntryAction::{New, ChangeTemplate, BelongTo}`）、`add_entry_card_rows`、`add_template_creator`、`add_v3_bottom_panel`；`Target::Entry { id, module }` 和 `Target::Template`；书快照 `book.v3()`，层级的有效设置在 `levels`。渲染器拿到的 `Rendered` 要接 `on_refresh`，刷新时不能冲掉没提交的输入。

各组开工前，先确认 `main` 里已经有 K4-0 的两次交回（看 overnight.md「收进来的」）。

### G1 页面与正文

- 模块渲染器：`body`（照今天章节页的章首章末、⁂、斜杠菜单、浮条、批注砂笔；层级的说明 `about` 也走它）、`field`（文字、长文字、数字、日期、单选、多选、图片、条目引用、别名；把 `dr-view-elements` 的字段编辑器改成各模块共用）、`kv`、`patches`、`plot`、`relations`。
- 一个条目多篇正文：每篇各自的编辑器、各自的撤销。
- 通览全书：按成书层级下面、文稿顺序的叶子拼。
- 人物链接：候选是「自动链接的叶子」（住处或任何一个归属的层级开了自动链接）；链接只认条目和素材，链到某一篇正文时带模块；点链接走 `Target::Entry { id, module }`。f6-shell.md K4-0 待协调第 2 条（模块链接的 URL、`EntityLink.module`）归你。
- 快照历史按条目恢复。
- 交回指针 `handback/k4-g1`。

### G2 层级与左栏

- 显示渲染器：`list`（今天的章节面板：书稿顺序，以及按故事线分组的看法）、`board`（今天的构想面板，看板坐标在 `layout` 里）、`grid` 和 `isles`（今天的要素紧凑索引和分类框）。左栏和层级页都用它们。
- 层级页上，住在这里的条目和归属进来的条目都要排出来，分开显示；这一层的设置显示有效值和来源，改过的可以还原。
- 树上拖动换住处，遵守「允许的模板」；用 `add_entry_action` 接上新建、换模板、归属到。
- 大纲栏接 v3。K4-0 第二次交回以后，`dr-shell` 的 `workspace/sidebar.rs`、`workspace/outline.rs` 归你。
- 交回指针 `handback/k4-g2`。

### G3 时间线

- 用 `add_v3_bottom_panel` 接 v3 的时间线：视图（新建、改名、删除）；泳道（把泳道条目加进视图、排序、拿出）；摆放（拖进泳道就是归属，拖动、换泳道、加长缩短；拿出最后一条泳道时位置一起去掉）；时间钉（双击标尺新建，改名、换颜色、挂条目）。
- 故事线页（`dr-view-elements` 的 `storyline.rs`）只留泳道层级特有的部分，比如颜色；通用的层级页归 G2。
- 交回指针 `handback/k4-g3`。

### G4 全书功能

- 搜索、统计、审阅、素材直接用 `Target::Entry` 和模块，不经过旧的 `book::nav_target`。
- 统计的全书字数只算成书层级下面的叶子。
- 作品主页：v3 现在只显示书名。你可以在 `dr-shell` 加一个按书的版本挂主页的注册口，只加不改；新建入口改成层级模板声明的动作。
- 导出：`dr-export` 加从成书层级拼出原稿的 v3 转换；单本书导出导入加 v3。
- 交回指针 `handback/k4-g4`。

### K5 模板编辑器

- 新开一个视图 crate，用 `add_template_creator` 和 `Target::Template` 接进外壳；界面照 [K5 原型第 2 版](https://claude.ai/artifact/Q9cfuRn9u5T5vZ38qG1JU7)：层级模板和叶子模板分开；模块（添加、改名、拖动排序、删除、字段类型）；层级设置；泳道开关；动作；写给帮手的说明（名字、一句说明、注意事项、每个模块一句）和「帮手看到的」预览（K6 已经有拼结构说明的函数就用它）。
- 写入走 v3 的 `entry_template.*` 命令。
- 模板的记号：先用现有的砂笔记号集合，未知的记号照 K4-0 的做法退回通用方印，不丢原值（f6-shell.md K4-0 待协调第 3 条）。
- 交回指针 `handback/k5`。

## 各组共同的规矩

- **作者看到的照今天，但先求能用**：用小说模板的书，结构和操作和今天一样。样式不用一模一样：先用 `dr-ui` 现成的组件，间距、动画、颜色这类细节放到切换前的打磨阶段。新出现的东西（归属到、换模板、时间线视图、时间钉）照 K5 原型第 2 版的结构来。
- **只动 v3 那条路，v2.2 冻结**：不再为 v2.2 写测试、不再因它退回；碰坏的 v2.2 测试可以删，交回里列出来。
- **自己的地方随便改；公共的地方只加不改**（2026-11-10 作者定）：表里归你的地方照旧随便改。外壳的 v3 注册口（`dr_shell::v3`）、内核的 v3 命令和查询（`dr-workspace` 的 `commands/v3`、`dr-doc` 的 `v3` 读写）、`dr-ui` 组件这类公共地方，**新增**一个注册口、命令、查询或参数，谁需要谁自己加，带上测试，在交回里写明；整合者合并时解冲突。要**改动**公共地方已有的行为或签名，照旧写进待协调，由负责方改。
- **验收分两档**（2026-11-10 作者定）：
  - **每次交回**：全套自动检查（fmt、Clippy、测试、xtask、public）照旧一样不少；真窗口只跑**一条冒烟场景**，把这次做的主要流程走一遍，不逐项覆盖，不截图目检；不做 heavy 测量。
  - **切换前统一做**：逐项的真窗口场景、截图目检、heavy 种子的打开和滚动测量、样式打磨。由整合者在四组和 K6 都合进来以后排一轮。
  - **不放松的**：数据正确性（见「写入不能拿读到的整份去替换」）、写作手感（打字上屏、输入法、焦点、滚动位置）。这些照旧每次都要有测试。
- **文案**：新文案写进 `dr-i18n` 的 own，九种语言都写；不自编说明文字。
- **写入不能拿读到的整份去替换**：第 49 批（G1 情节规划）和第 53 批（K6 时间线）都因为这个被退回——先读一份（或者只读到过滤后的一部分），改一处，再整份写回，会把别人刚写的、或者没读到的数据冲掉。改用带版本守卫的写（`Workspace::call_guarded`）或者逐项命令；冲突时拒绝旧的写入，保留作者的编辑，不能静默成功。每组都把「两次各自成功的写入不互相覆盖」「没显示的数据不被整份写入删掉」写成自己的永久测试。
- **交回**：照 overnight.md 的协议，指针分别是 `handback/k4-0`、`handback/k4-g1` 到 `handback/k4-g4`。交回小节写短：做了什么、检查结果、待协调，三段就够。

## 切换的标准

必须先做完的：四组的功能、K6、快照历史（帮手写入以后靠它撤销）、大书性能。然后：

1. 整合者排一轮统一验收：逐项的真窗口场景、截图目检、heavy 种子的打开和滚动测量，查出来的问题分给各组修；样式打磨同时进行。
2. 作者拿一份旧库副本导入成 v3，在 App 里写一周。这就是阶段 2 原来的过关标准。
3. 用 v3 的书在假服务上同步往返一次（M36）。

都过了就切换：新建书改成 v3，开发库从旧版重新导入，删掉 v2.2 的页面、命令和数据层。
