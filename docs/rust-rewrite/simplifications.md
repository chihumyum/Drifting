# 重写时的简化清单

2026-11-07，作者要求「趁着迁移，检查现存架构有什么值得简化或调整得更干净的地方」。监管会话分五路审查了旧代码：

1. 数据与同步；
2. 界面层；
3. 帮手；
4. Rust 原生层；
5. 工程设施。

关键结论都对照代码核实过。本页是结论，计划里受影响的条目已经同步改过。

每一条都标了处理方式，并写明影响计划里的哪一项：

| 处理方式 | 意思 |
| --- | --- |
| **必须接住** | 计划原来漏了，新版必须做 |
| **不搬** | 旧版有，新版不要 |
| **合成一份** | 旧版有好几份，新版只留一份 |
| **直接复用** | 旧代码可以搬进 `next/` |

## 一句话

旧版大部分的复杂，不在功能本身，而在**同一件事有好几份真相**，以及**为了 WebView 与原生之间的边界、为了 Yjs 和 SQLite 两边对账而补的机制**：

- 写入有四套入口；
- 内存状态有两条更新路径；
- 帮手的工具有三套名字；
- 一次工具调用存了七份。

单进程的 Rust、Loro 加命令注册表，正好把这些拿掉。

但有一类要特别小心：**旧版用一套复杂机制解决了一个真问题，新计划删掉了机制，问题却没人接。**下面第一节列的都是这一类，比「删什么」更要紧。

## 一、必须接住（计划原来漏了）

### 数据与存储

| # | 内容 | 影响 |
| --- | --- | --- |
| 1 | **库被搬走时自动换代。** 旧版在库外放一个本机身份文件（`sync-installation-v2.json`），库到了别的机器，下次写入就自动换写入者。新计划只在恢复、复制这些已知路径上换代，抓不到作者用 Finder、迁移助理、Time Machine 搬库，后果是 Loro 悄悄不一致、查不出来。做法：`library_meta` 记 `installation_id`，打开时和库外身份比对；库外再记每个库的最大 `seq`，抓「拿旧备份覆盖」 | F2 |
| 2 | **记住服务器已经有什么。** 每个文档一行 `sync_doc(doc_id, remote_vv)`，上传导出 `remote_vv` 之后的更新。这样压缩和上传互不相干，「有改动只在这台电脑上」也能算出来。资源文件加 `uploaded_at`。旧版的写入者、HLC、`device_seq` 都不要 | F2、M36 |
| 3 | **派生索引带版本戳。** `index_state(doc_id, indexed_seq)` 和索引行在同一个事务里写，打开库时重建落后的文档。P0-E 发现的「缓存落后正文」就是旧版缺这一条 | F2、F3 |
| 4 | **快照按实体恢复。** 旧版恢复快照时，会连带恢复当时的标题、梗概、要素字段（`restoreMetadata`）。新版历史点要同时记书目文档的 frontiers，恢复时在单独载入的副本上读出这个实体的旧字段，作为新提交写回，不整篇回退书目文档 | F1、F2、M09 |
| 5 | **来源写进 Loro 提交信息。** `loro_update.origin` 会被压缩删掉，而主页签到要问「某个时间以来，谁改了哪些文档」。agent、mirror、import 的写入都写提交信息，来源一律从 Loro 变更读。Agent 结算记录只要一张表（会话、轮次、调用、文档、前后 frontiers、摘要）。这条依赖「不做浅快照」 | F2、M29、M30 |
| 6 | **提交即落盘。** GPUI 在 macOS 上只接了 `applicationWillTerminate`，`on_app_quit` 只有 200 ms，退出时做不了重活。旧版退出时冲刷 10 条「车道」，⌘S 用来强制保存，新版都不该需要 | F2、F6 |
| 7 | **写作日的设备键**沿用旧版 installationId 的摘要，导入后同一台设备在写作日里还是同一台 | F2、M07 |
| 8 | **资源存储以 `src-tauri/src/native_capabilities.rs` 为准**：source / display / thumbnail 三种版本，导入标记 `.drifting-import-v1`，Windows 上删目录会落盘。计划原来指的 `drifting-core/asset_store.rs` 只有 source，产品没在用 | F2 |

## 三、不搬

**数据**
- 同步 v1 引擎整体：变更集、字段时钟、归约器、校验内核、排序寄存器、`domain-manifest.ts`。
- 投影列，以及锚点 v1–v4 的重新定位。后者只留在导入里。
- `block_section`。
- `local-folder` 和 `memory` 两种同步提供方，以及提供方这一层抽象。
- 新基线**一律不写 SQL 触发器**。旧版同一条规则常常挡好几道（触发器 + 同步内核 + 用例），新版的不变量只放在命令层预防、读取时容错。退役的枚举值在导入时就规整掉。

**帮手**
- 精确撤回 `applyInverse`：生产代码里一处都没有调用，只有测试在调。
- 每个工具身上的风险、确认、撤回分级。权限策略自 2026-11-06 起已经一律放行。
- 8 个阶段的写入日志、多张回执表、三版检查点格式：它们补的都是 WebView 与原生之间的崩溃窗口。新版把 Loro 更新和结算记录放进同一个 SQLite 事务就够了。
- 只有评测在用的工具选择器。
- 对话分支模型：从没用过。
- 记忆的 veto / directive、待确认流程。
- 「Rust MCP 服务端」里转发给 WebView 的那一层，改用 rmcp 直接调命令注册表。
- `sidecar` / `remote` 接缝：两种都没有实现，作者已定不保留，见文末。

**界面**
- 为 WebKit 写的性能补丁：隐藏常驻的标签页、输入法查询遍历的拦截、暂停动画的样式税、`content-visibility` 高度估算、按需加载。只照它们背后的视觉规格来做。
- 手机端分支：33 处判断、5.3k 行外壳、4.9k 行 CSS。
- 死设置项、`canUseFeature()` 恒真的分支、约 220 个没人引用的文案键。文案按新代码真正引用的键来搬，孤儿靠编译期检查清掉。
- ⌘S。

**Rust**
- yrs 三件套：`drifting-document`、`drifting-prose`、vendored 的 `yrs`；以及只为 iOS 打补丁的 vendored `tao`。只留下两份规格：`count_words` 的规则，以及人物自动链接的规则（逐字、最长优先、不重叠）。
- `drifting-core` 里的同步 v1 部分，以及 `workspace/*`。后者是已退役 Apple 前端的后端，Tauri 从没调用，也落后于素材夹和写作日。**它不能当规则参考**，F3 的参考改成 TS 的用例层、同步内核和帮手写策略。
- 只为 WebView 存在的胶水：
  - 给渲染层的 SQL 网关；
  - Tauri 命令和状态；
  - 退出屏障；
  - `dev_watchdog`；
  - WebView 媒体和字体桥。
- Android 和 iOS 插件。

**工程**
- `docs/renderer-performance/`：178 个 JSON 加 38 篇 md。
- 浏览器试验台。
- TS 与 Rust 之间的复用基准。
- CI 写法的契约检查。
- yrs 和 tao 的来源校验。
- 手机端文档。
- 按日期记的 QA 报告。

## 五、更轻的验收证据（新工作区适用）

旧版「每个里程碑都交证据」的成本：

- 8 月以来 43% 的提交改过证据文件，30 次提交只是「合并 main 之后重新生成」；
- 53 个脚本各写了一份指纹函数；
- 86 个脚本带 `--check`，CI 只跑了约 8 个。

`next/` 改用下面的做法，旧客户端照旧：

- **契约类证据**（工具清单、种子形状、表结构）：不提交 JSON，由 `cargo test` 当场生成并断言。需要人审 diff 的（工具清单）用快照测试。
- **测量类证据**：只在阶段关口、以及「优化前后」提交，文件名带里程碑。指纹只覆盖语料生成器、bench 和被测 crate，源码变了只报「过期」，不判失败。合并以后不刷新。
- **只有一处**：一个 `dr-testkit::evidence` 模块、一个 `cargo xtask evidence --check`，CI 全跑。不留 CI 不检查的证据。
