# 通用内核 v3（方案）

2026-11-09 起草，同日按作者的决定改了时间线、幕和泳道，**作者已定稿**；作者看过原型后又定了两处，见文末「改动记录」。数据层照这一页做（K1+K2 已开工），做完把结构记进 [loro-schema.md](loro-schema.md)，版本记成 v3。这一页怎么分轨推进，见 [handoff/kernel-v3-split.md](handoff/kernel-v3-split.md)。

## 一句话

书里所有东西都是**条目**，放在**一棵可以随意嵌套的树**里。条目分两种：**层级**下面放别的条目，**叶子**装内容。叶子长什么样由**叶子模板**决定（正文、字段、补丁、情节规划……）；层级管什么由**层级模板**决定（下面放什么、要不要自动链接、收不收住在别处的条目）。时间线是作者自己建的**视图**，和树完全分开。小说是第一个**项目模板**：新书打开就是现在这套结构，作者不碰就和今天差不多。

## 照旧不变的

- 新书的默认结构：书稿与章、构想看板、要素与分类、故事线、素材、审阅。和现在相比只有一处不同：**幕不再内置**，作者需要就自己用树里的一层或时间钉做。
- 正文文档的结构：扁平 LoroText、段落属性打在 `\n` 上、块 ID、H1/H2/H3、表格和素材嵌入、锚点、Agent 就地写入、撤销规则，全部照 v2.2。
- 素材、批注、待办、项目设定、Project Memory、写作日、帮手对话，原样保留。
- Agent 写入直接生效，作者靠快照历史撤销。
- 新版还没发给任何人，所以 v2.2 不做迁移：开发库一律从旧版重新导入。

## 概念

### 条目

条目就是树上的一个节点，有标题和模板。用层级模板的条目是**层级**，可以有子条目；用叶子模板的条目是**叶子**，装内容，不能有子条目。

兄弟条目之间的先后就是**文稿顺序**，像文件夹里文件的先后。导出、通览全书、章节编号都按它来。它只属于树，和时间线没有任何关系。

### 两种模板

| | 层级模板 | 叶子模板 |
| --- | --- | --- |
| 管什么 | 下面放什么、怎么管 | 自己由哪些模块组成 |
| 自己的内容 | 一篇说明，加上字段和键值表 | 模块：正文（可以多篇、各自命名）、字段、键值表、补丁、情节规划、关联 |
| 层级设置 | 有，见下一节 | 没有 |
| 泳道开关 | 有 | 没有 |
| 动作（比如「新建章节」） | 有 | 没有 |
| 记号和颜色 | 有 | 有 |
| 写给帮手的说明 | 有 | 有 |

层级模板**不带叶子的模块**：叶子长什么样只由叶子模板自己定。层级只说「这里默认放哪种叶子、允许放哪些」。

写给帮手的说明，形式照 skill 的写法：一个名字、一句「这是什么、什么时候用」，再加一段「写的时候注意什么」。叶子的每个模块也可以有一句说明。

模板存在书里。新建书时，从 App 内置的项目模板**复制一份**进书，以后 App 升级不会悄悄改动已有的书；内置模板有新版本时，只提示作者可以更新。

### 层级的设置

| 设置 | 意思 |
| --- | --- |
| 默认模板 | 在这一层新建时用哪个模板 |
| 允许的模板 | 这一层能放哪些模板的条目；不设就是都能放 |
| 显示 | 列表、网格、看板、岛屿 |
| 自动链接 | 这一层里的叶子，名字和别名在正文里自动链接 |
| 收别处的条目 | 住在别处的条目可以归属到这一层，见下面「住处和归属」 |
| 新条目住在 | 只对收别处条目的层级有用：在这一层新建的条目，住处放在哪一层；不设就住在这一层 |
| 成书 | 这一层下面按文稿顺序排好的叶子，就是书的正文 |
| 格式快捷输入 | 这一层里的正文，行首打 `- `、`1. ` 这类时会不会自动变格式 |

**往下继承**：一个层级的某项设置，先看它自己有没有覆盖，再看它的模板，再往上找最近一个说了这一项的祖先，都没有就用默认值。所以在「人物」这一层打开「自动链接」，下面各级分组里的人物都会自动链接；某个分组想关掉，就在那个分组上覆盖。

### 归属由层级决定，叶子不管

一个条目能不能挂到别处，**只看要挂去的那一层**：它开没开「收别处的条目」，允不允许这个条目的模板。叶子模板里不写「我能属于几处」。理由：

1. 层级只管理放什么，收不收、收什么，本来就是层级的事。
2. 叶子模板不用知道自己会被放进什么结构，拿到别的项目也能用。
3. 拖放时只问一处：拖进去的那一层收不收。

自动链接同理：叶子的住处所在的层级，或者它归属的任何一层，只要开了自动链接，它就自动链接。

### 模块

叶子的模块：

| 模块 | 数据放在哪 | 现在对应的东西 |
| --- | --- | --- |
| 正文 | 自己的正文文档，一个模块一篇 | 章节、构想、要素的正文 |
| 字段 | 条目的字段表：文字、长文字、数字、日期、单选、多选、图片、条目引用、别名 | 梗概、写作状态、摘要、别名、立绘、分类的字段模板 |
| 键值表 | 条目自己的一张自由键值表 | 要素字段 |
| 补丁 | 书目文档的补丁表 | 要素补丁 |
| 情节规划 | 书目文档的格子表 | 每章一张的情节规划 |
| 关联 | 不存数据，显示和编辑这个条目的关系 | 要素页的「关联」 |

层级自己的内容只有三样：一篇**说明**（每个层级都有，像文件夹里的说明文件）、字段、键值表。层级页面上，下面的条目（和归属进来的条目）按「显示」设置排出来，不需要另外的模块。

每个模块都要交代清楚下面六件事，交代不了的不进内核：

1. 数据怎么存；
2. 帮手怎么读、怎么写；
3. 搜不搜得到，算不算字数；
4. 导出时变成什么（只有成书层级下面的叶子才导出）；
5. 在 Markdown 文件夹里写成什么；
6. 撤销和快照恢复怎么处理。

### 住处和归属

每个条目在树里**只有一个住处**，决定它在哪、排第几、在磁盘上放在哪个目录。

开了「收别处的条目」的层级，除了住在这里的条目，还可以有**归属**：别处的条目挂一个名在这里，本体不动。把东西拖进这种层级是「加入」，不是「移动」；删掉这个层级时，归属的条目不跟着删。一个条目可以同时归属到好几处，可以标其中一处为**主归属**（现在的「主故事线」）。

分类打开这个开关，一个要素就能同时属于几个分类。泳道层级总是收别处的条目。

### 成书

层级设置里的「成书」打开后，这一层下面按文稿顺序排好的叶子就是书的正文：导出、通览全书、全书字数和字数目标、章节编号都只看它。成书层级下面可以再有作者自己加的层级（比如卷），它们照常继承设置。默认结构里只有「书稿」这一层打开。一本书里可以有几处成书（比如正篇和番外），导出时选。

### 时间线

时间线和文稿树、和树里的层级**完全分开**。没有「书序」这回事，也没有哪个条目会自动出现在时间线上。

- **视图**：作者自己建，可以建很多个。视图由泳道组成，每个视图有自己的顺序，完全由作者摆。
- **泳道**：泳道是一个打开了「泳道」开关的层级条目。它和别的层级一样放在树里、有自己的说明和字段，能收哪些模板的条目由它的设置定。视图里摆哪几条泳道、什么顺序，作者定。
  - 把条目拖进某条泳道，它就**多一个归属**到这个泳道，同时在这个视图里有了位置（可以带长度）。
  - **条目只有在泳道里才在视图里**，没有「不在泳道里」这一说。从泳道里拿出来，就去掉这个归属；如果它在这个视图的别的泳道里也没有了，它在这个视图里的位置一起去掉。
  - 泳道的成员只来自归属，**不看**泳道条目在树里的位置，也不看成员住在哪。
  - 同一个条目在一个视图的两条泳道里，位置是同一个。
  - 同一条泳道可以摆进好几个视图；成员在哪个视图里出现，看它在那个视图里有没有位置。
- **时间钉**：视图上的一个标记，位置、名字、颜色都由作者定，可以挂一个条目。

### 项目外的东西

素材（图片、PDF、素材笔记、素材夹）、批注和待办不在条目树里，和现在一样单独存。批注可以指向条目的某一篇正文，素材可以和条目建关系。

## 小说项目模板

新建一本小说时的默认结构：

```text
书稿            层级：成书；默认模板「章」；格式快捷输入关；动作「新建章节」
  第一章        叶子「章」：梗概、写作状态、正文、情节规划
构想            层级：看板显示；默认模板「构想」
  某个分组      层级「构想分组」：颜色
    某条构想    叶子「构想」：梗概、写作状态、正文
要素            层级：岛屿显示；默认模板「分类」
  人物          层级「分类」：颜色、说明；默认模板「人物」、自动链接
    主角们      层级「分组」，继承上一层的设置
      阿Q       叶子「人物」：别名、摘要、立绘、字段、键值表、正文、补丁、关联
故事线          层级：默认模板「故事线」
  主线          层级「故事线」：泳道；颜色、说明、键值表；默认模板「章」；新条目住在书稿
```

再加一个默认的时间线视图，摆着各条故事线。

- 每个分类各有一个要素模板（「人物」「地点」……），对应现在每个分类自己的字段模板和正文模板。
- 要素的分组、构想分组都是层级。
- 故事线就是泳道层级。故事线自己的章节模板保留：它是这条线的默认模板（一个叶子模板）；在这条线上新建章节时，新章节住进书稿、归属到这条线、用这条线的模板。
- 「构想」现在是一层的名字，不再是一种条目。构想转章节，就是把它挪进书稿、换成「章」模板。
- 模板里写好给帮手的说明：这是一部小说、书稿下的章是书的结构、H1/H2/H3 的含义由作者定、各层是什么。现在散在帮手提示词里、和小说绑定的部分，全部挪到这里。

## 帮手

- **认识来自结构**：帮手每次拿到的是「这本书用到的模板和它们的说明」，加上它要处理的条目，不再有写死的「章节、要素、故事线」概念。
- **工具改成通用的一套**，按条目、模块、归属、时间线来：
  - 条目：找、读、列出子条目、新建、移动、改名、换模板、放进最近删除、恢复；
  - 模块：按模块名读写字段和键值表，按模块名读写正文（照现在的块 ID 写法）；层级的说明同样当一篇正文读写；
  - 归属：加入、移出、设主归属；
  - 时间线：建视图、把条目拖进泳道、挪动、拿出来，时间钉增删改；
  - 关系、批注与待办、素材、Project Memory、搜索：照现在的。
- **层级模板可以声明动作**，比如书稿的「新建章节」＝在书稿下用「章」模板新建。工具清单照旧从命令注册表生成，再加上这本书模板里声明的动作，名字用作者的叫法。
- 换模板、改结构这类写入，和别的 Agent 写入一样直接生效、可按来源撤销。

## 数据结构（Loro）

### 书目文档 v3 的根容器

| 根容器 | 类型 | 内容 |
| --- | --- | --- |
| `meta` | 映射 | `v = 3`；书名、梗概、创建与删除时间；字数目标；`project_template`（复制自哪个内置模板、哪一版） |
| `entries` | LoroTree | 条目树。节点 meta：`id`（uuidv7）、`title`、`template`、`overrides`（层级设置的覆盖，只有层级有）、`fields`（字段的值，键是模块 id）、`kv:<模块 id>`（键值表，条目 id → `{key, value, pos}`）、`primary`（主归属）、`layout`（各种显示里作者亲手摆的位置：看板、网格、关系图）、`created_at`、`deleted_at`。兄弟顺序就是文稿顺序 |
| `templates` | 映射 | 模板 id → `kind`（`level` / `leaf`）、`name`、`mark`、`color`、`agent`（名字、一句说明、一段注意事项）、`modules`（模块 id → `{kind, name, pos, config, agent}`；层级模板只能有字段和键值表）、`deleted_at`；层级模板另有 `settings`（层级设置）、`lane`（泳道开关）、`verbs`（声明的动作） |
| `memberships` | 映射 | 键 `"<归属到的层级>\|<成员>"` → `{pos, created_at}`。泳道的成员也在这里 |
| `timeline_views` | 映射 | 视图 id → `name`、`pos`、`lanes`（泳道条目 id → `{pos}`）、`placements`（条目 id → `{at, span?}`，`at` 是带间隙的实数）、`pins`（时间钉 id → `{at, label, color, entry?}`）、`deleted_at` |
| `patches` | 映射 | 照 v2.2，`element` 换成 `entry` + `module` |
| `plot_grids` | 映射 | 键 `"<条目>/<模块>"`，内容照 v2.2 |
| `relation_types`、`relations` | 映射 | 照 v2.2；端点种类只剩 `entry`、`material`、`comment`、`patch`；端点限制可以按模板 |
| `comments` | 映射 | 照 v2.2，`target_kind` 改用上面的种类，加 `module`（指向哪一篇正文） |
| `materials`、`assets`、`material_folders`、`facts`、`memory`、`writing_days` | 照 v2.2 | |

去掉的根容器：`nodes`、`acts`、`storylines`、`categories`、`elements`、`time_pins`、`drift_groups`。

### 正文文档的 id

| 文档 | id |
| --- | --- |
| 叶子的一篇正文 | `body:<条目 id>/<模块 id>` |
| 层级的说明 | `body:<条目 id>/about` |
| 叶子模板里一篇正文的初始内容 | `template:<书 id>/<模板 id>/<模块 id>` |
| 素材笔记、帮手对话 | 照 v2.2 |

**文档 id 在整个库里唯一**：库里所有书的 Loro 文档共用一张表（`loro_doc.doc_id` 是主键），彻底删除一本书时按书删文档。所以：

- 条目 id 一律在新建时生成 uuidv7，**书稿、构想、要素、故事线这些默认层级和默认分类也一样**，不用写死的 id；`apply_novel_project_template` 把生成的 id 返回给调用方，之后按模板找根层级，不按固定 id 找。
- 模板 id 在一本书里可以是固定的（比如 `tpl-chapter`），方便以后按内置模板更新；所以模板正文文档的 id 带上书 id。

人物链接的标记照旧是 `entity:<目标 id>`，值里的 `kind` 只剩 `entry` 和 `material`，链到某一篇正文时加 `module`。

### 不变量

| 不变量 | 靠什么 |
| --- | --- |
| 树不成环 | LoroTree 保证 |
| 叶子没有子条目 | 命令层预防；合并后出现时，读取时把这些子条目当作住在叶子的上一层，数据不动 |
| 条目放进的层级允许它的模板 | 命令层预防；合并后不满足时照常显示，只是不能再往里放新的 |
| 条目的模板不在了 | 读取时当作没有模板的条目，只显示已有的数据，不丢 |
| 换模板不删数据 | 新模板没有的模块，数据原样留着，界面放在「原来的内容」里，换回来就回来；层级换成叶子之前要先没有子条目 |
| 只能删没人用的模板 | 命令层预防；合并后仍有人用已删的模板，照上一条容错 |
| 归属到的层级收别处的条目、允许这个模板 | 命令层预防；读取时不满足就忽略这条归属，数据留着 |
| 视图里的泳道必须是泳道层级 | 命令层预防；读取时不是就不当泳道画 |
| 视图里的条目在这个视图的某条泳道里 | 命令层预防：拿出最后一条泳道时一起去掉位置；读取时不在任何泳道里的位置不显示 |
| 自动链接的名字和别名唯一 | 范围改成「自动链接的叶子」，规则照 v2.2 |
| 视图里的泳道、时间钉挂的条目都要在 | 读取时不在就不显示 |
| 成书的层级不嵌套 | 命令层预防；读取时只认最外层 |
| 跨文档写入的先后 | 照 v2.2：先写正文文档，再写书目文档 |
| 文档 id 在库里唯一 | 结构上保证：条目 id 新生成，模板正文文档带书 id；测试：一个库里建两本小说，所有文档 id 不重；彻底删除其中一本，另一本的文档一个不少 |

## 旧库导入的映射

| 旧版 | v3 |
| --- | --- |
| 幕 | 书稿下的一层「分组」层级，名字照旧，按书序把章节分进去。作者的分组是作者的数据，不能丢；不想要可以自己拆掉。幕绑定的构想变成一条关系 |
| 章节 | 「章」叶子，住进书稿（有幕的进那一层），按书序排；有叙事序的，按叙事序摆进默认视图里它所在的故事线泳道 |
| 构想 | 「构想」叶子，住处按构想分组；看板坐标进 `layout`；有叙事序的同样摆进它所在的故事线泳道 |
| 有叙事序、但不属于任何故事线的章节和构想 | 默认视图里另建一条泳道装它们，名字用旧版界面里对这类条目的叫法，作者可以改名或拆散 |
| 构想分组 | 「构想」下面的「构想分组」层级 |
| 分类 | 「要素」下面的「分类」层级；每个分类生成一个叶子模板，带上它的字段模板和正文模板，并设为这一层的默认模板；网格位置进 `layout`；说明进层级的说明 |

### 怎么换过去

- **并存，最后一次切换**：v3 和 v2.2 在同一组 crate 里并存。`dr-model`、`dr-doc` 各加一个 `v3` 模块；`dr-workspace` 加通用命令，只对 v3 的书生效；v2.2 的类型和按种类的命令先留着。这样 `main` 一直能编译、测试一直全绿，别的轨道不受影响。
- 切换前，App 照旧打开 v2.2 的库；v3 先靠测试、`cargo drifting` 命令行和调试桥验收。
- K4 的界面都接到 v3 以后，一次切换：App 改开 v3 的库，开发库从旧版重新导入，然后删掉 v2.2 的代码和按种类的命令。
- 帮手的工具清单在切换前不收 v3 的新命令（照 M29 的排除表），K6 再开放。

以后再做：模板分享（导出、导入模板包）。AGENTS.md 里「大纲是幕 / 章 / H1 / H2 / H3」那条，要在 K1 合进 `main` 时一起改：幕不再内置，默认结构是书稿 / 章 / H1 / H2 / H3，作者自己加的层级由作者命名，H1/H2/H3 的规矩不变。

## 改动记录

- **2026-11-09 定稿**：条目树、模板与模块、住处和归属、作者自建的时间线视图（泳道是条目、时间钉代替幕、没有书序）。
- **2026-11-09 作者看过 K5 原型后**：
  - 模板分成**层级模板**和**叶子模板**。层级模板只管理下面放什么（默认模板、允许的模板、显示、自动链接、收别处的条目、新条目住在、成书、格式快捷输入）和自己的说明、字段、键值表；叶子模板只定义自己的模块。叶子不能有子条目。去掉「子条目卡片」模块，层级页面按「显示」排出下面的条目。
  - 归属由层级决定：要挂去的那一层收不收、允许哪些模板，叶子模板不管。
  - 时间线去掉「不在泳道里」：条目只有在泳道里才在视图里。
  - 已经按旧写法开工的 K1，照这一节改：`templates` 加 `kind`，层级设置从 `children` 改名为 `settings` 并加上 `allow`、`accept`、`home`；`timeline_views.placements` 只对在泳道里的条目有效。
- **2026-11-09 审 K1 时发现**：默认层级、默认分类用了写死的 id（`root-manuscript`、`cat-character` 等），模板正文文档 id 不带书 id。库里文档 id 是全局主键，两本书会共用同一篇「书稿说明」和同一篇章节模板正文，彻底删除一本书时会删掉另一本的文档。改成：条目 id 一律新生成，模板正文文档 id 为 `template:<书 id>/<模板 id>/<模块 id>`，并加上「文档 id 在库里唯一」这条不变量。
