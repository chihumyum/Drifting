## 一句话

书里所有东西都是**条目**，放在**一棵可以随意嵌套的树**里。一个条目长什么样由它的**模板**决定：模板里列着它由哪些**模块**组成（正文、字段、补丁、情节规划……），以及它下面的子条目默认是什么、要不要自动链接、能不能同时归属到别处。小说是第一个**项目模板**：新书打开就是现在这套结构，作者不碰就和今天一样。

## 照旧不变的

- 新书的默认结构和界面：书稿与幕、章，构想看板，要素与分类，故事线，素材，审阅。作者看到的和现在一样，靠小说项目模板保证。
- 正文文档的结构：扁平 LoroText、段落属性打在 `\n` 上、块 ID、H1/H2/H3、表格和素材嵌入、锚点、Agent 就地写入、撤销规则，全部照 v2.2。
- 素材、批注、待办、项目设定、Project Memory、写作日、帮手对话，原样保留。
- Agent 写入直接生效，作者靠快照历史撤销。
- 新版还没发给任何人，所以 v2.2 不做迁移：开发库一律从旧版重新导入。

## 概念

### 条目

条目就是树上的一个节点。它有标题、模板、自己的设置覆盖，以及各个模块的数据。条目可以有子条目，也可以没有；**不分文件夹和文件**，没有子条目的就是叶子。

兄弟条目之间的先后就是**文稿顺序**，像文件夹里文件的先后。导出、通览全书、章节编号都按它来。它和时间线上的顺序完全无关。

### 条目模板

模板是一份定义，有三部分：

1. **模块清单**：这个条目由哪些模块组成，每个模块有自己的名字（作者起的，比如「梗概」「正文」「人物小传」）。
2. **子条目设置**：在它下面新建的条目默认用哪个模板、子条目的名字要不要自动链接、子条目能不能同时归属到别处、用什么方式显示（列表、网格、看板、岛屿）、编辑时要不要格式快捷输入、这一层是不是成书。
3. **写给帮手的说明**：形式照 skill 的写法，一个名字、一句「这是什么、什么时候用」，再加一段「写的时候注意什么」。每个模块也可以有一句说明。

模板存在书里。新建书时，从 App 内置的项目模板**复制一份**进书，以后 App 升级不会悄悄改动已有的书；内置模板有新版本时，只提示作者可以更新。

### 设置怎么继承

子条目设置往下继承：一个条目的某项设置，先看它自己有没有覆盖，再看它的模板，再往上找最近一个说了这一项的祖先，都没有就用默认值。所以在「人物」这一层打开「子条目自动链接」，下面各级分组里的人物都会自动链接；某个分组想关掉，就在那个分组上覆盖。

### 模块

| 模块 | 数据放在哪 | 现在对应的东西 |
| --- | --- | --- |
| 正文 | 自己的正文文档，一个模块一篇 | 章节、构想、要素的正文，故事线和分类的说明 |
| 字段 | 条目的字段表：文字、长文字、数字、日期、单选、多选、图片、条目引用、别名 | 梗概、写作状态、摘要、别名、立绘、分类的字段模板 |
| 键值表 | 条目自己的一张自由键值表 | 要素字段、故事线字段 |
| 补丁 | 书目文档的补丁表 | 要素补丁 |
| 情节规划 | 书目文档的格子表 | 每章一张的情节规划 |
| 子条目卡片 | 不存数据，把子条目平铺成卡片 | 分组卡、故事线的章节序列 |
| 关联 | 不存数据，显示和编辑这个条目的关系 | 要素页的「关联」 |

一个条目可以有**多篇正文**，各自命名。每个模块都要交代清楚下面六件事，交代不了的不进内核：

1. 数据怎么存；
2. 帮手怎么读、怎么写；
3. 搜不搜得到，算不算字数；
4. 导出时变成什么（只有成书的条目才导出）；
5. 在 Markdown 文件夹里写成什么；
6. 撤销和快照恢复怎么处理。

### 住处和归属

每个条目在树里**只有一个住处**，决定它在哪、排第几、在磁盘上放在哪个目录。

打开了「子条目可以同时归属到别处」的条目，下面放的除了住在这里的条目，还可以有**归属**：别处的条目挂一个名在这里，本体不动。把东西拖进这种条目是「加入」，不是「移动」；删掉它时，归属的条目不跟着删。一个条目可以同时归属到好几处，可以标其中一处为**主归属**（现在的「主故事线」）。

故事线就是开了这个开关的条目：章节住在书稿里，归属到一条或几条故事线。分类也可以打开，那样一个要素就能同时属于几个分类。

### 成书

子条目设置里的「成书」打开后，这一层下面按文稿顺序排好的条目就是书的正文：导出、通览全书、全书字数和字数目标、章节编号都只看它。默认结构里只有「书稿」这一层打开。一本书里可以有几处成书（比如正篇和番外），导出时选。

### 时间线

时间线和文稿树完全分开，由四样东西组成：

- **轴**：一条有名字的坐标轴，比如「叙事时间」。轴可以有很多条，作者自己加。
- **落点**：一个条目在一条轴上的位置（可以带长度）。**把条目拖到时间线上才有落点**，不再是所有章节、构想都自动在上面。
- **泳道**：绑定一个条目。绑的是开了归属的条目（比如一条故事线），泳道里就是它的成员；绑的是一般的层级，就是它下面的条目；绑叶子的情况见文末「要作者定的事」。
- **区段**：轴上的一段（没有终点就是一个时间钉），可以绑一个条目。现在的幕轨和时间钉都变成区段。

**视图**是「一条轴 + 若干泳道 + 若干区段」，可以存好几个。默认给一个「叙事时间」视图，泳道是各条故事线。

### 项目外的东西

素材（图片、PDF、素材笔记、素材夹）、批注和待办不在条目树里，和现在一样单独存。批注可以指向条目的某一篇正文，素材可以和条目建关系。

## 小说项目模板

新建一本小说时的默认结构：

```text
书稿            成书；子条目默认「章」；格式快捷输入关
  第一幕        模板「幕」；子条目默认「章」
    第一章      模板「章」：梗概、写作状态、正文、情节规划
构想            看板显示；子条目默认「构想」
  某个分组      模板「构想分组」：颜色
    某条构想    模板「构想」：梗概、写作状态、正文
要素            岛屿显示；子条目默认「分类」
  人物          模板「分类」：颜色、说明；子条目默认「人物」模板、自动链接
    主角们      分组，继承上一层的设置
      阿Q       模板「人物」：别名、摘要、立绘、字段、键值表、正文、补丁、关联
故事线          子条目默认「故事线」
  主线          模板「故事线」：颜色、说明、键值表、成员卡片；子条目可以归属
```

- 每个分类各有一个要素模板（「人物」「地点」……），对应现在每个分类自己的字段模板和正文模板。
- 要素的分组变成分类下面的一层子条目；构想分组同样。
- 故事线自己的章节模板保留：从某条故事线新建章节时，新章节住进书稿末尾、归属到这条线、用这条线的模板。数据上就是故事线对「子条目默认模板」的覆盖。
- 「构想」现在是一层的名字，不再是一种条目。构想转章节，就是把它挪进书稿、换成「章」模板。
- 模板里写好给帮手的说明：这是一部小说、幕和章是书的结构、H1/H2/H3 的含义由作者定、各层是什么。现在散在帮手提示词里、和小说绑定的部分，全部挪到这里。

## 帮手

- **认识来自结构**：帮手每次拿到的是「这本书用到的模板和它们的说明」，加上它要处理的条目，不再有写死的「章节、要素、故事线」概念。
- **工具改成通用的一套**，按条目、模块、归属、时间线来：
  - 条目：找、读、列出子条目、新建、移动、改名、换模板、放进最近删除、恢复；
  - 模块：按模块名读写字段和键值表，按模块名读写正文（照现在的块 ID 写法）；
  - 归属：加入、移出、设主归属；
  - 时间线：放上轴、挪动、拿下，区段增删改；
  - 关系、批注与待办、素材、Project Memory、搜索：照现在的。
- **模板可以声明动作**，比如「新建章节」＝在书稿（或当前幕）下用「章」模板新建。工具清单照旧从命令注册表生成，再加上这本书模板里声明的动作，名字用作者的叫法。
- 换模板、改结构这类写入，和别的 Agent 写入一样直接生效、可按来源撤销。

## 数据结构（Loro）

### 书目文档 v3 的根容器

| 根容器 | 类型 | 内容 |
| --- | --- | --- |
| `meta` | 映射 | `v = 3`；书名、梗概、创建与删除时间；字数目标；`project_template`（复制自哪个内置模板、哪一版） |
| `entries` | LoroTree | 条目树。节点 meta：`id`（uuidv7）、`title`、`template`、`overrides`（子条目设置的覆盖）、`fields`（字段模块的值，键是模块 id）、`kv:<模块 id>`（键值表，条目 id → `{key, value, pos}`）、`primary`（主归属）、`layout`（各种显示里作者亲手摆的位置：看板、网格、关系图）、`created_at`、`deleted_at`。兄弟顺序就是文稿顺序 |
| `templates` | 映射 | 模板 id → `name`、`agent`（名字、一句说明、一段注意事项）、`modules`（模块 id → `{kind, name, pos, config, agent}`）、`children`（子条目设置）、`verbs`（声明的动作）、`deleted_at` |
| `memberships` | 映射 | 键 `"<归属到的条目>\|<成员>"` → `{pos, created_at}` |
| `axes` | 映射 | 轴 id → `{name, pos, deleted_at}` |
| `placements` | 映射 | 键 `"<轴>\|<条目>"` → `{at, span?}`，`at` 是带间隙的实数，和现在的叙事序一样 |
| `bands` | 映射 | 区段 id → `{axis, start, end?, entry?, label}` |
| `timeline_views` | 映射 | 视图 id → `{name, axis, pos, lanes（泳道 id → {entry, source, pos}）, bands（集合）}` |
| `patches` | 映射 | 照 v2.2，`element` 换成 `entry` + `module` |
| `plot_grids` | 映射 | 键 `"<条目>/<模块>"`，内容照 v2.2 |
| `relation_types`、`relations` | 映射 | 照 v2.2；端点种类只剩 `entry`、`material`、`comment`、`patch`；端点限制可以按模板 |
| `comments` | 映射 | 照 v2.2，`target_kind` 改用上面的种类，加 `module`（指向哪一篇正文） |
| `materials`、`assets`、`material_folders`、`facts`、`memory`、`writing_days` | 照 v2.2 | |

去掉的根容器：`nodes`、`acts`、`storylines`、`categories`、`elements`、`time_pins`、`drift_groups`。

### 正文文档的 id

| 文档 | id |
| --- | --- |
| 条目的一篇正文 | `body:<条目 id>/<模块 id>` |
| 模板里一篇正文的初始内容 | `template:<模板 id>/<模块 id>` |
| 素材笔记、帮手对话 | 照 v2.2 |

人物链接的标记照旧是 `entity:<目标 id>`，值里的 `kind` 只剩 `entry` 和 `material`，链到某一篇正文时加 `module`。

### 不变量

| 不变量 | 靠什么 |
| --- | --- |
| 树不成环 | LoroTree 保证 |
| 条目的模板不在了 | 读取时当作没有模板的条目，只显示已有的数据，不丢 |
| 换模板不删数据 | 新模板没有的模块，数据原样留着，界面放在「原来的内容」里，换回来就回来 |
| 只能删没人用的模板 | 命令层预防；合并后仍有人用已删的模板，照上一条容错 |
| 归属到的条目必须开了归属 | 命令层预防；读取时没开就忽略这条归属，数据留着 |
| 自动链接的名字和别名唯一 | 范围改成「开了自动链接的条目」，规则照 v2.2 |
| 落点的轴、泳道和区段绑定的条目都要在 | 读取时不在就不显示 |
| 成书的层级不嵌套 | 命令层预防；读取时只认最外层 |
| 跨文档写入的先后 | 照 v2.2：先写正文文档，再写书目文档 |

## 旧库导入的映射

| 旧版 | v3 |
| --- | --- |
| 幕 | 书稿下的「幕」条目，按书序把章节分进去 |
| 章节 | 「章」条目，住处按幕和书序；叙事序变成「叙事时间」轴上的落点 |

| 时间钉 | 「叙事时间」轴上没有终点的区段，绑定的构想照旧绑定 |
| 补丁、情节规划、批注、待办、关系、素材、资源、项目设定、记忆、写作日 | 换成新的键和种类，内容照搬 |

## 对现有代码的影响

按 crate 粗算，`next/` 里约一半不受影响（编辑引擎、设计系统、平台、存储底层、帮手运行时、导出排版），约四分之一要局部改（外壳、编辑器的人物链接、帮手面板、审阅、统计、情节规划、关系），约四分之一要重做（`dr-model`、`dr-doc`、`dr-workspace` 的按种类命令、旧库导入、要素、构想、故事线、时间线、Markdown 文件夹、帮手工具）。

## 要作者定的事

1. **时间线的「按书序」看法**：v3 的时间线只有作者自己加的轴，书序（文稿顺序）不是轴。现在的「按书序」看法，建议改成「按文稿顺序排开、只能看不能拖」，还是干脆去掉？
2. **幕**：默认结构里，幕变成书稿下的一层（书稿 / 第一幕 / 第一章）；时间线上的幕轨变成绑定这些幕条目的区段，位置由作者在轴上拖。这样可以吗？
3. **泳道绑一个叶子**（比如一个人物）时放什么：建议放「和它有关系、或正文里提到它，并且在这条轴上有落点的条目」。

## 不做的

- 代码插件。
- 通用的 Markdown 编辑器功能（公式、图表、插件系统、任意类型的文档）。
- 公式字段、汇总字段这类数据库功能。
