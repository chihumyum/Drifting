# M36 Hosted 同步 v2

先读 [README.md](README.md) 的共用约定和 [m35-account.md](m35-account.md)。会话令牌来自 M35；协议层可以先写，最后接上 M35。

## 要做的

用 Loro 的更新同步书。**决定 D6**：沿用现在的对象日志 HTTP 协议，换一个命名空间承载 Loro 的更新批次和快照。服务端只存不透明对象，几乎不用改。

- **上传和下载**：
  - 每篇文档记 `remote_vv`（服务端已经有的版本），只传这之后的改动。F2 已经有 `export_for_upload`，导出 `remote_vv` 之后的改动。
  - 压缩和上传互不相干。
- **恢复**：新设备、或者本机库丢了，从服务端把书拉回来。
- **配额**：500 MiB 软上限，1 GiB 硬上限。照旧版提示。
- **帮手对话也同步**：每个对话一篇只追加的 Loro 文档，和别的文档走同一条路，不另做一套同步引擎（M27）。
- **同步状态记号**，作者 2026-11-02 定的：
  - 位置：稿纸左下角一枚砂笔记号，跟着稿纸走；分屏只放在左边那张稿纸上；本机库不放。
  - 已同步：什么都不显示。
  - 同步中（传了 3 秒还没完）：云图标整块呼吸，上传下载同一种；完成 1.5 秒后淡出；打字时淡出，停笔 2 秒再回来。
  - 重试中：云慢闪。离线：散砂的云。
  - 所有错误统一用危险色的「！」：没能启动、连续出错、存储已满、需要重新登录。指着出悬停卡，说明问题，能重试、重新登录、打开设置。
  - 重的问题同时进通知中心（铃铛换成「！」，钉一条直到解决）。普通的上传下载不进通知中心。
  - 详见 `docs/hosted-sync/sync-status.md`。

## 旧版

- 旧的同步引擎 `src/renderer/sync`：约 3.5 万行，大部分被 Loro 取代，主要看它的**对象日志协议**怎么调服务端。
- `src-tauri/src/hosted_sync.rs` 等三个文件，主要是给 WebView 的代理；只留 origin 校验、带校验的流式传输、取消，约 150 行。
- 文档：`docs/hosted-sync/README.md`、`sync-status.md`。

## 新版放哪、接哪

- 新 crate `next/crates/dr-sync`：协议、调度、状态，不依赖 GPUI。
- **存储那头归 F2**（`dr-store`）：`remote_vv`、`export_for_upload`、导入远端更新、同步状态表都在 F2。要的接口不够，写进「待协调」请 F2 加，不要自己改 `dr-store` 的内部。
- 远端更新导进来以后，书目、索引、编辑器怎么刷新：F2 的事件总线和 F3 的事件已经有，照着用。
- 状态记号挂在稿纸角上：外壳的 `workspace/corner.rs` 归 F6。要一个挂接点，写进「待协调」；你先把记号视图和状态模型写好。
- 服务端如果确实要改（比如新命名空间要登记），只写进文档的「待协调」，说清要改什么，不改服务端。

## 完成标准

- 两个本机库对着一个本机假服务：
  - 各自写、同步、收敛，逐字节相同；
  - 断网后续传；
  - 配额触顶；
  - 从空库恢复。
- 同步状态的每种状态都有测试，按上面的规则显示或不显示。
- 不连真服务。
