# M38 分享链接（发布端）

先读 [README.md](README.md) 的共用约定和 [m35-account.md](m35-account.md)。

## 要做的

客户端发布端：
- 发布一章或一个构想，拿到链接；
- 作者停笔几秒后自动推新版本，像云文档，不用手动发布；
- 收件箱：轮询读者的评论，回流到审阅（M18），评论能标「已解决」。

作者定过的规则：
- 拿到链接就能读；登录 Drifting 账号才能评论。不做逐个批准，也不做邮箱名单。
- 所有读者互相看得到全部评论，也看得到作者的「已解决」状态。
- 不做多人一起改正文。

**阅读页不在这份里。** 决定 D8：阅读页由服务端用 Rust 直接出 HTML（axum + maud），和导出共用「正文转 HTML」；跑在哪里随 D7 定，D7 还在等作者。这份只做发布端。正文转 HTML 要做成发布和导出（M41，`dr-export`）共用的一份，写进文档。

## 旧版

- `src/renderer/features/share-links/*`（约 1k 行）
- `src/shared/share-document.ts`：发出去的文档格式
- `docs/share-links.md`：先读它的「Limits」

## 新版放哪、接哪

- 新 crate `next/crates/dr-share`，加界面的 `dr-view-share`。
- 入口：每种正文页的 ⋯ 菜单里已经有「分享」。M41 dr-text 那一路做了 Markdown 分享，经 `add_page_menu` 登记。发布到链接接在旁边。
- 评论回流：变成 M18 的审阅条目。来源怎么标，写进「待协调」请 F3 / F4d 看。
- 停笔几秒自动推：订阅 F3 的提交事件，不要轮询正文。

## 完成标准

- 对着本机假服务：发布、自动更新、取消发布、收件箱拉回评论、标已解决。
- 发出去的文档格式和旧版 `share-document.ts` 对得上，有快照测试。
