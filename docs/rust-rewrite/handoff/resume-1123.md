## NP 联网请求跟着系统代理走

- **为什么**：`next/` 的 reqwest 关着默认特性、没开 `system-proxy`。从访达或开始菜单启动的 App 没有 `HTTPS_PROXY` 这类环境变量，开着系统代理而不是 TUN 的人会直连，直连线路不好时就是「登录正常、同步失败」。0.1 同一个缺口 2026-11-23 修了（`d57fb838a`，`src-tauri`）。
- **范围**：`next/Cargo.toml` 的 reqwest 特性；建客户端的六处（`dr-sync/src/protocol.rs`、`dr-account/src/client.rs`、`dr-platform/src/feedback.rs`、`dr-platform/src/update/fetch.rs`、`dr-agent-providers/src/transport.rs`、`dr-mcp/src/outbound/destination.rs`）。
- **要做的**：
  1. 打开系统代理（macOS 的网络设置、Windows 的 Internet 选项都读到）。
  2. 这几种目的地不走任何代理：回环地址；本机和局域网的模型服务（`dr_agent_providers::local` 认成本机或局域网的地址）；MCP 往外连时的回环端口；Hosted 源是回环地址时（开发用的假服务）。规则写在一处，六处共用，不各写各的。
  3. `rmcp` 自己带的 reqwest 传输也要看一眼是不是同一套设置。
- **回归测试**：不依赖这台机器真实的系统代理设置。起一个本机的假代理，证明走代理的请求经过它、回环和局域网的请求不经过它；`cargo tree -e features` 一类的检查守住特性不被关掉。
- **不做的**：不加代理设置界面，不改超时和重试。
- **验不了的要写明**：Windows 上读 Internet 选项只能交叉编译，实机要作者或虚拟机里验。

  4. 粘进标题、表格格子、输入框这类不是正文的地方，照现在只进字。

- **不能有的**：外链图片不下载；脚本、样式表、事件属性全丢；不因为一段坏 HTML 崩或卡住（大小有上限，超了按纯文本）。
