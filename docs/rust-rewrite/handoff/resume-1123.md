## AB 打开开关时把全书补一遍，和自动链接的几处收尾

- **依据**：progress.md「等作者的事」第 21 条「自动链接（AL）」的 (a)(b)(c)(e)(f)，作者 2026-11-24「都按照你的推荐来。」规则的全文在本页「AL」一节和 [kernel-v5.md](../kernel-v5.md) 第 16 节「自动链接」。
- **现在**：打开一个原来关着的开关以后，开关关着那阵子写下的名字在数据里没有链接，正文里只出点状下划线，作者往那一段打字时那一段才链上。
- **要做的**：
  1. **打开时把全书补一遍。** 三种打开都算：条目自己的开关从关到开、按层一起打开、设置里的总开关从关到开（对所有开着的条目）。谁打开的都一样（作者、Agent、MCP、同步以外的任何命令来源），所以放在命令这一层或会话提交之后，不放在界面里。
     - 补的是「照现在的规则本来会链上、但数据里没有」的那些名字和别名：用现成的配链接规则（`dr-workspace/src/autolink.rs` 的 `plan` 一套：最长匹配、名字唯一、手动的链接受保护、已有的链接不动），写成自动的链接（不带手动标记）。正文之外，批注和关系描述里的名字照它们现在的规则，现在不自动链的不补。
     - 在后台做，不卡界面：开关那条命令照常马上生效；补链接一篇正文写一次。重型种子（100 章、约 165 万字、300 个要素）按层一次打开全部人物要多久、主线程最长停多久，量出来写进报告（不提交测量证据）。
     - 正在编辑器里开着的那一篇当场看到链接出来，光标和选区不动；正在组字（输入法拼音还没上屏）的那一篇等组字结束再写。
     - 不往作者的撤销里加东西：编辑器里 ⌘Z 不会一下撤掉补上的链接；开关那条命令的撤销照旧只是把开关关回去（关了以后照显示规则链接本来就不显示，数据留着）。
     - 做到一半退出：下次打开这本书接着补完（这台设备上留一个待办的记号，不同步）。别的设备收到「开关打开了」不自己补，等同步过来的正文。
     - Agent 的「这一轮读过才能写」的守卫照现有规矩：正文被补过链接以后算变了，Agent 要重读。
     - 关掉开关不动数据（AL 第 6 条），不做反向的清理。
     - 改名、加别名以后已经写下的旧字要不要补，这一路不改，查清现在怎样、写进报告。
  2. **模板编辑器里「名字参与自动链接」那几个字**改成说默认的：简体中文「新建时跟随这一层的自动链接」，九种语言照这个意思。它管的事不变（新建时跟不跟所在层的默认、按层一起打开时带不带上它）。
  3. **重名时说清原因。** 打开一个和别的开着的条目重名（名字或别名相同）的条目，现在只出通用的「未能保存」。改成说清是哪一个名字、和哪一个条目撞了。简体中文：「没有打开：「{名字}」已经是「{另一个条目}」的名字或别名。」九种语言照这个意思；单个打开和按层一起打开都用它（按层时说第一处撞的）。命令仍旧整条拒绝，规则不变。Agent 和 MCP 收到的错误里也带上这两个名字和对方的 id。
  4. **项目模板带上条目自己的开关。** 另存项目模板时把条目的开关写进去（模板条目加一个可选的 `auto_link`）；用模板建新项目时，写了的照写的，没写的照现在（模板的 `linkable` 加所在层的默认）重新算。只加不改；新版没发布，不做旧模板文件的过渡。
  5. **内置写书模板写给 Agent 的说明**里还按旧规则讲的几句（`dr-doc/src/v3/novel.rs` 里「每个分类开启自动链接」「分类下的要素……名字与别名在全书正文中自动链接且唯一」「继承上一层的……自动链接等设置」这些）改成新规则：条目自己的「自动链接」开关才算数，分类上的开关是「一起开关加这一层新建的默认」。不比现在长（CX 守着 32768 上下文至少 1024 的余量）。
- **范围**：`dr-workspace`（`autolink.rs`、开关的三条命令、会话）、`dr-doc`、`dr-model`（项目模板条目）、`dr-editor`（开着的那一篇怎么接住后台写进来的链接）、`dr-shell`（重名提示出在哪）、`dr-view-templates`、`dr-i18n`、`dr-agent-tools`（错误里的名字）、`dr-samples`／`dr-testkit`（种子里靠显式状态的地方不用动）。和 AP 同时在跑：AP 动 `prose.link` 和正文写入协议里的逆操作，这一路不动它们。
- **回归测试**：单个打开、按层打开、总开关打开以后，没开着的章里那个名字在数据里成了自动的链接；手动的链接和已有的链接逐字节不变；重名、最长匹配照规则；关着的条目不补；补完再关再开数据不变；做到一半重开接着补完；编辑器里开着的那一篇光标不动、撤销栈不多一步；组字时不写；重名提示带两个名字；项目模板往返带着开关；`cargo test -p dr-view-agent --test local_context` 的余量照旧过。
- **真窗口**：在示例书里关着总开关写一个人物的名字、再打开，正文里当场成链接；新建一个条目、在别的章里先写它的名字、再打开它的开关，换到那一章看是链接；按层打开；重名时看那一句。屏幕睡着跑不了照实写没跑。

## AP Agent 用 `prose.link` 加的链接记成手动的

- **依据**：progress.md「等作者的事」第 21 条「自动链接（AL）」的 (d)，作者 2026-11-24「都按照你的推荐来。」
- **现在**：`prose.link`（Agent 和命令「把这几处字链到某条目」）写的是不带手动标记的链接，所以目标的开关关着时读成普通字。它是有意加的，按理和作者 @ 出来的一样。AL 没改，是因为这条命令的撤销只认不带标记的值（共用的逆操作描述不了别的元数据），直接改会让它拒绝在已有的自动链接上再加、也拒绝摘掉自动链接。
- **要做的**：`prose.link` 加的链接带手动标记（和编辑器里 @ 的同一种值，`manual: true`），不受开关影响，自动链接的规则把它当受保护的。它的撤销改成按原值恢复：原来那一段是没有链接、自动的链接还是手动的链接，撤销以后就是什么，逐字节一样。在已有的自动链接上再加（变成手动的）、摘掉链接这两种不再被拒绝。别的走同一个逆操作的命令（摘链接、整段替换等）查一遍，行为不变或者跟着变对，逐条写进报告。
- **不变的**：导入的旧链接、AL 之前的旧链接仍当自动的；编辑器里 @ 的照旧；关掉开关不动数据。
- **范围**：`dr-workspace` 的正文写入协议和逆操作、`dr-agent-tools` 的 `prose.link`（和工具目录里它的说明：一句话说清它加的链接不受开关影响，不比现在长多少）、`dr-doc`。和 AB 同时在跑：AB 动 `autolink.rs` 的配链接和开关命令，这一路不动它们。
- **回归测试**：`prose.link` 以后目标关着也画成链接；撤销回到原值（三种原值各一条）；在自动的链接上再加、摘掉；Agent 回执里的逆操作能照样重放；工具目录快照更新。
- **文档**：`kernel-v5.md` 第 16 节、K6／Agent 工具的结论文档里讲 `prose.link` 的地方。

## AL 条目的自动链接：默认关、显式打开，开关管已经连好的链接

- **依据**：作者 2026-11-24 的八条（[progress.md](../progress.md)「作者定下的」），定稿页是 <https://claude.ai/artifact/Vxfunju8SBn37AxGW1yGQ2> 的「第 2 版」（每处选中的就是定了的）。起因是用户要「全局开关和单个科目和要素开关」，作者把方向反了过来：0.1 所有要素一律自动链接，新版条目默认不链接，显式打开才链接。
- **现在**（2026-11-23 做原型时对代码查实）：
  - 一个名字链不链看三样：设置里的总开关 `editor.auto_entity_links`、条目模板的 `linkable`（模板编辑器完整视图里的「名字参与自动链接」）、它住的那一层的 `auto_link`（沿住处继承；`dr-model/src/v3.rs` 的 `AutolinkNames::of`）。条目自己没有开关。
  - **链接是存在正文里的**，不是显示时现算的：编辑器写进去用 `dr-editor/src/entity_links.rs` 的 `apply`，命令写进去用 `dr-workspace/src/autolink.rs` 的 `apply`、`link_written_v3`；画的时候（`dr-editor/src/decor/mod.rs` 的 `find_links`、`looks.rs`）只看目标还在不在。
  - 总开关或一层关掉以后，已有的链接不动，只是以后打的字不再链；「名字还没链上」的点状下划线不受总开关管。
  - 正文的 @ 用的是自动链接那张名字表（`assist.rs` 的 `update_menu` → `NameIndex::load`），所以一层关掉，那层的条目在正文里 @ 不到；批注和建关系里列的是全书活着的条目。
  - @ 挑的链接和自动链的存下来是同一种值（不带 block 的 `{kind:"entry"}`），分不出来。
  - 打开一个原来没开的开关，不会给已经写下的名字补链接：`autolink::keep_added` 没有任何地方调用，编辑器只在作者往某一段打字时把那一整段重配一遍（`link_pass`）。
- **定了的**：
  1. 每个条目有自己的「自动链接」开关，新建的默认关；开着它的名字和别名才自动链接。开关显示什么就是什么。
  2. 按层的开关留着，意思变了：打开 = 住在下面的条目一起打开，以后在这一层新建的默认开着；关掉反之；单个条目之后能自己改。它不再是压在条目上面的一层。子层里新建的条目，默认值取最近的、设过值的那一层。
  3. 内置写书模板里人物、地点这几层预设开着（照它们现在的状态）；作者自己建的层和模板一律默认关。
  4. 条目模板的 `linkable` 换了角色：只决定这种模板的条目新建时跟不跟所在层的默认、按层一起打开时带不带上它（分组这类装东西的模板不带）；不再否决链接。作者在条目上自己打开的，照样链。
  5. 从 0.1 导入：0.1 里会自动链接的都开着（照 0.1 自己的规则，要素之外还有章节标题，见 `src/renderer/lib/extensions/entity-link.ts`），别的关着。目的是导入那一刻正文里看到的链接和 0.1 一样。导入后保留着链接、但照这条规则会关着的种类，逐种列进报告。
  6. **关掉以后，正文里已经指向它的链接当场不再显示成链接**：字照旧，没有下划线，点不动，指着不出名字卡；数据留在正文里不动。再打开，当场全回来。
  7. 从这一路起，@ 出来的链接另记成手动的，不受开关影响，自动链接的规则（`plan`、`protect_v3`）把它当受保护的；之前的旧链接统一当自动的。
  8. 设置里的总开关、按层的开关照第 6 条同一个规矩：总开关关掉，全书自动的链接当场都不显示，再打开都回来；点状下划线也跟着总开关。
  9. 开关放在两处：条目页最下面那一组开关里，「挂在这里的条目」下面一行；悬停卡里一行（左栏条目卡在「层级」下面，正文名字卡在「建关系」下面）。
  10. 正文里的 @ 列全书活着的条目，和批注里一样，不再和名字表绑在一起。
