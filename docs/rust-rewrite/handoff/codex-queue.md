# Codex 的连续任务队列

2026-11-08。M27 已经审过、合进 `main`（第十七批）。从这里起不用每做完一个模块就停下等：照下面的顺序一个接一个做，做完一个就提交、写好文档，接着做下一个。共用约定照 [README.md](README.md)；每个模块的要求看它自己的任务书。

## 怎么连着做

1. **每个模块一个分支**，名字照 `codex/mNN-<名字>`。
   - 开下一个之前先 `git merge main`（监管会话随时在往 `main` 里合东西），再从**上一个模块的分支**开新分支。
   - 这样后一个能用前一个的代码，不用等监管会话合完。
   - 不 rebase 已经交出去的提交。
2. **每个模块收尾的时候**：全套检查（README 里那四条加 `pnpm public:check`）都过了；模块文档写好；在文档开头写一行「交回状态」，写清分支、最后一个提交、还差什么。
3. **碰到要作者定的事，或者要别的会话加接口**：写进模块文档的「待协调」，先用最小的办法绕过去，接着往下做。只有整条链都卡住才停下。
4. 作者会不时把做好的分支转给监管会话合进 `main`。你在下一个模块开始时 `git merge main` 就能拿到。合的时候整合分支上改过的地方，以 `main` 为准。

## 第二十三批审查反馈：M31（2026-11-08）

M31 `ef63d4f9` / 合入 main 后的 `0f1b0799` 已开始审查，暂未接收，仍需带上 M29 修复。

- **P1：退出／切库及控制操作仍可能同步卡住界面**：`AgentController::close` 在 GPUI 的 release hook 内直接 poll `control.abort()`；`Control::request` 会阻塞获取 `accepting` mutex，而 M27 正常完成路径持有该锁跨 `drain()` 和 Completed 的 journal／holder 写入。终态写入慢或被阻塞时，close 连返回可等待的 future 都做不到；面板的 Stop／插话／回答同样在前台 poll 控制请求。控制信箱改成非阻塞发送，或移到后台派发，让同步 freeze 只冻结入口，并保留所有开始、读取和写入的结算屏障。静态调用链加原 Control 实现的独立锁调度复现确认阻塞超过 500 ms；尚未做整应用窗口复现。补“终态持久写入被阻塞时 close 立即返回、窗口仍能响应，最终放行后正确释放”的回归。
- **先修元数据回执的导航与首次引导**：`panel.rs` 把 `SettlementRef.document` 当作改动对象；只改元数据时收据是 `book:<id>`，于是“本轮改动”退到书主页，打开不到被改的要素或批注。首次引导还会为这条收据显示“版本历史”，但 F3 `history.points` 明确拒绝 book 文档（不是正文）；点击后仍无条件结束引导。按实际效果对象导航，只为有正文历史的目标提供历史入口，并在成功打开实际改动后结束引导。补第一轮仅改书／要素元数据的回归，不能只用正文写入证明此路径。
- **多轮对话的卡片顺序**：`panel.rs` 先画全部持久消息，再画全部 run 的流式消息、搜索、历史提问和改动卡。第二轮开始以后，旧轮卡片会排到最新回复之后；流式完成时回复又跳到前面。将附属卡按所属 session／turn 放回对应消息位置，补至少两轮、流式转最终态和重开对话的顺序回归；32 步单轮场景不能覆盖。
- **发送和轮数上限文案**：实现是 Enter 发送、Shift+Enter 换行，但九语言输入提示仍写 Cmd/Ctrl+Enter，须与当前行为一致；轮数上限描述宣称自动续跑／手动继续，M27 实际会以 Protocol error 进入 Failed，面板没有续跑入口。文案准确描述当前行为即可，不借此提前实现 M30。更改源文案并重新生成各平台文件。
- **折叠入口可访问性**：推理、工具调用和结果标题只有 `div.on_click`，没有可操作角色、名称或键盘焦点。使用既有可访问交互模式并补 AX／键盘检查，保留已有阅读顺序。
