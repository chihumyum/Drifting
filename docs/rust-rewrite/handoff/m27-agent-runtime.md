# M27 帮手运行时核心

先读 [README.md](README.md) 的共用约定。帮手这一组（M27–M34）以这份为地基。M28 模型接入可以接着在同一个任务里做。

## 要做的

和模型无关的帮手运行时。这是阶段 5 的起点。旧版的运行时核心约 5.7 万行，其中很多是给旧数据模型和 Yjs 做适配的；新版**重新设计，不逐行搬**，行为照旧版。

已经定下的：

- **只有本机一种接法。** 运行时在应用进程里跑。旧版协议里的 `local` / `sidecar` / `remote` 接缝不保留（作者 2026-11-07 定）。
- **运行日志是唯一的事件流。** 界面上的消息由事件推出来，不另存一份。写入的结算记录和 Loro 的更新在同一个事务里落盘（F2 的 `dr-store` 已经支持帮手写入的结算记录，见 f2-store.md）。
- **对话同步，日志不同步。** 每个对话一篇只追加的 Loro 文档，随书同步；运行日志、事件、权限请求只留在本机。
- **帮手写入直接生效，不分权限档。**
  - 作者 2026-11-06 定：删除也不再确认。
  - 撤销走历史：F3 有 `history.agent_changes`、`history.undo_agent`，能按来源撤回，连带的删除也能撤回。
  - 只有两种情况要先问作者：生成图片要花钱（M33），以及外部插件的工具。
- **帮手和界面对同一操作的语义不一致时，以界面为准。** 比如删章、新建重名。
- 运行时要能做到这几件事：
  - 向作者提问，等作者回答再继续；
  - 中途转向：作者在运行中插话；
  - 在当前工具调用之后停下；
  - 立刻中止。
- 写入的身份：F3 的 `Actor::Agent { session, turn, call }`。

## 新版放哪、接哪

- 新 crate `next/crates/dr-agent`：运行时、事件、驱动接口。和界面无关，不依赖 GPUI。
- 驱动接口给 M28 用：流式输出、工具调用、思考内容、用量。这一份先带一个测试用的假驱动，按脚本吐事件，测试全用它。
- 工具层是 M29。这一份只定义「运行时怎么调工具」：工具描述、调用、结果、并发。M29 再从 F3 的注册表生成工具。
- 对话文档的结构要和 F1 对：在 `dr-model` 里登记新的文档种类和不变量，写进「待协调」请 F1 审，或者照 `loro-schema.md` 的写法提出来。本机日志表要新加迁移，迁移归 F2：照 `dr-store` 的迁移门禁加，并写进「待协调」。
- 不碰界面。面板是 M31。

## 完成标准

- 用假驱动跑通：一轮普通对话、一轮带工具调用的写入（写进书、结算记录落盘、能按来源撤回）、提问与回答、中途转向、当前工具后停、中止。
- 崩溃恢复：写入事务中途崩溃，重开后书和结算记录一致。照 `dr_testkit::crash` 的试验台做。
- 文档写清：事件种类、状态机、驱动接口、对话文档结构、和旧版的对照。
