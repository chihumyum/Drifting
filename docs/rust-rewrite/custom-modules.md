## 1. 大白话

**为什么做。** 条目页上的东西都是模块：正文、字段、键值表、补丁、情节规划、下面的条目、挂在这里的条目、媒体，一共八种，写死在代码里。想记「这一章埋了哪些伏笔、后来在哪收回」「这个人物的弧光」「世界的年表」「一种魔法的规则」，只能拿字段和键值表凑。作者要的是：用户自己做模块，可以让 AI 生成，可以拿给别人用，像项目模板一样。

**做成什么：**

1. **模块是一份数据，不是代码。** 一个模块就三样东西：**装什么**（几块积木，能套着装）、**长什么样**（一棵盒子树，说怎么排、什么字、什么边）、**写给 Agent**（这个模块是干什么的、每块怎么填）。App 里有一个画它的通用渲染器，没有任何能执行的东西。
2. **模块和项目无关。** 做好的模块存在「我的模块」里（书库里，跟着同步），任何项目的任何条目模板都能用。项目里存一份抄本，所以书拿到别的设备、分享链接、导出的书文件里都能打开。
3. **做模块只有一个地方：模块工作台。** 三条路进它：跟 Agent 说、往 Agent 栏里丢一张草图或截图、在「添加模块」菜单里点「新建模块…」自己摆。工作台左栏是装什么，稿纸是预览，右栏是长什么样、写给 Agent 和 Agent。
4. **改了「我的模块」，用着它的项目都跟着换**（第 7 节）。条目里填过的值不会丢。
5. **模块能单独导出成一个 `.driftingmodule` 文件**，别人导入；第二期和社区模板走同一个公开仓库。

**作者会看到的不同：**

- 条目模板的「添加模块」菜单：自带的八种下面多一节「我的模块」，再下面「社区」（第二期），最下面「新建模块…」。
- 条目页上多出各种长相的模块；指着正文里一个条目的名字，悬停卡里每个自定义模块多一行。
- 「全部项目」页的左栏，「我的模板」下面多一节「我的模块」。

**分两期。** 第一期：模块格式和校验器、工作台、渲染器、我的模块、导出导入、项目模板带模块。第二期：社区模块，跟社区模板一起做（kernel-v5 第 15 节第 43 条：新版发布以后）。

**不做的：**

- 不做代码插件，也不做公式、汇总字段（2026-11-18 作者：「按照你的建议来吧」，沿用 kernel-v3「不做的」）。积木画不出来的东西（地图、家谱树之类）走主仓库的合并请求，随发版进 App，成为自带的模块种类。
- 不放开颜色、额外字体和图片（第 4 节，风格选了甲）。
- 不在 App 里做上传和发布，照项目模板。

## 2. 一个模块里有什么

| 部分 | 内容 |
| --- | --- |
| 名字 | 一行字，工作台的标题点了就改。所有模块用同一个砂笔图标（「线装」），没有自己的记号 |
| 装什么 | 积木的列表，「一组」「一串」里面还能再放积木（第 3 节） |
| 长什么样 | 三种大小各一棵盒子树：「一块」必须有，「一行」「铺满」可以没有，没有就跟着「一块」（第 4 节） |
| 写给 Agent | 名字、说明、注意事项，加上每块积木各一句（第 5 节） |
| 示例 | 一份示例值，工作台预览切到「示例」时用，社区里逛的时候也用它画 |

模块里没有的：颜色、字体文件、图片、网址、脚本、样式表、表达式、指向某个项目里任何东西的 id（条目、条目模板、视图），以及账号、设备和书库的任何标识。

## 3. 装什么：积木

| 积木 | 存什么 | 对应现在的字段类型 |
| --- | --- | --- |
| 一行字 | 一行纯文本 | `text` |
| 一段字 | 多行纯文本（不是正文：没有格式，不能批注到字） | `long_text` |
| 数字 | 一个有限实数 | `number` |
| 日期 | `YYYY-MM-DD` | `date` |
| 单选 | 选项里的一个 | `select` |
| 多选 | 选项里的若干个 | `multi_select` |
| 勾选 | 开或关 | `toggle` |
| 条目 | 指向这个项目里的一个或几个条目 | `entity_ref` |
| 图片 | 素材库里的一个文件 | `image` |
| 一组 | 自己不存值，把几块积木装在一起 | — |
| 一串 | 若干项，每项是同样的几块积木；串里还能再有串 | — |

规则：

- **积木有自己的 id**，改名不换 id。值按 id 存，所以改名、挪位置、套进别的组都不丢值（第 7 节「值不丢」）。
- **一串是能长的。** 每一项有自己的 id；拖动排先后。年表那样的「纪元里一串事件」就是串里套串。
- **「条目」积木不能限定只指某个条目模板。** 条目模板是项目里的东西，模块和项目无关（替作者定的）。
- **没有公式和汇总。** 「一行」里能显示「3 处伏笔」，那是渲染时数一串有几项（第 4 节的「显示成个数」），不是一个存起来的字段，也不跨条目算。

## 4. 长什么样：盒子树

「长什么样」是一棵盒子树，像设计软件里的自动布局；每种节点都能一对一画成 GPUI 的 `div`、`flex`、`grid`。节点只有五种：

| 节点 | 是什么 | 能设的 |
| --- | --- | --- |
| 盒子 | 装别的节点 | 排法（竖、横、格）；间距；内边距；对齐（起、中、末、撑）；宽（自动、随内容、填满）；边；底；圆角；装饰；格的列宽；不换行；最宽 |
| 每一项 | 把一串的每一项各画一遍 | 指哪一串；排法（竖、横）；间距；分隔（无、线、轴）；连接（无、箭头）；每一项长什么样（一个盒子） |
| 值 | 画一块积木的值 | 指哪块积木；显示成什么（看积木：数字显示成数字或点数，单选显示成字或记号，一串显示成个数）；字体；大小；墨色；最多几行 |
| 字 | 一段写死的字，比如「收在」「想要」 | 文字；字体；大小；墨色 |
| 记号 | 一个砂笔记号 | 哪一个（dr-ui 已有的砂笔记号） |

### 风格只用现有的设计语汇（风格甲）

能挑的只有下面这些，清单外的写了也会被校验器拦下：

| 属性 | 能挑的 |
| --- | --- |
| 字体 | App 的三种：衬线、无衬线、等宽 |
| 大小 | 标题、正文、小、注 |
| 墨色 | 一到四档（App 的墨色深浅） |
| 边 | 无、发丝线、玻璃线、砂笔框 |
| 底 | 无、稿纸、淡墨 |
| 圆角 | 0、2、4、8 |
| 装饰 | 无、弧线（一道砂笔弧） |
| 间距、内边距 | 0、4、8、12、16、24 |
| 记号 | dr-ui 已有的砂笔记号；单选显示成记号时，第一个选项空心、最后一个实心、中间半实 |

颜色只有墨色深浅，跟着深浅模式自己换，所以模块在深色下、别的设备上、分享链接里都不会难看。原型第二页的四个例子都只用这张清单画，长相已经差得很远。

### 三种大小（一块必摆，另两种默认跟着）

| 大小 | 露在哪 | 没单独摆时 |
| --- | --- | --- |
| 一块 | 条目页上这个模块的样子 | 必须摆 |
| 铺满 | 条目页上这个模块铺满中间一列（模块右上角的铺满按钮，和别处的铺满一样，Esc 或再点一次退出；kernel-v5 第 17 节） | 「一块」撑满 |
| 一行 | 悬停卡里：指着一个条目，梗概下面每个自定义模块各一行 | 取前几块积木的值连成一行：一串显示成个数，图片和一组跳过 |

工作台右栏「长什么样」顶上写着现在看的是哪种大小；看「一行」「铺满」时多两颗「跟着一块」「单独摆」，选「单独摆」就单独摆一棵（先从「一块」抄过来再改）。

## 5. 写给 Agent

- **和条目模板的「写给 Agent」同一个样子**：名字、说明（这个模块是干什么的）、注意事项；另外「每一样」，每块积木一句（比如「状态：埋着、提过、收了」）。数据里对到 `name`、`description`、`instructions` 和 `blocks`。
- 模块放进条目模板以后，那个条目模板里的这个模块照旧有自己的 Agent 权限（能不能写、读到哪一档），和别的模块一样，只能收窄（project-templates.md 第 10 节规则 2）。
- Agent 读条目时，结构说明里带上每个自定义模块的积木、名字、每块那一句和当前的值；写值走通用的模块写入命令（第 13 节），按积木的类型校验。
- **Agent 能建模块、改模块**（「跟 Agent 说」和「丢草图」两条路要靠它），写入和 Agent 别的写入一样直接生效，过同一个校验器。**导入、导出、从社区取不进 Agent 和 MCP 的工具目录**，照项目模板。
- 帮手的通用规则（`dr_agent::guidance::PROJECT_GUIDANCE_RULE`）覆盖模块的说明：它们只讲这个模块怎么填，不算作者的请求。

## 6. 数据形状

一个模块写成文件、放进项目模板、存在书库里，都是下面这样一个值（内容只为示意；原型第三页那段 JSON 也只是示意，以本节为准）：

```json
{
  "format": "drifting.module",
  "formatVersion": 1,
  "name": "伏笔追踪",
  "locale": "zh-Hans",
  "credit": {"author": "示例作者"},
  "blocks": [
    {"id": "items", "type": "list", "name": "伏笔", "blocks": [
      {"id": "line", "type": "text", "name": "一句话"},
      {"id": "st", "type": "select", "name": "状态", "options": ["埋着", "提过", "收了"]},
      {"id": "back", "type": "entry", "name": "收在"}
    ]}
  ],
  "look": {
    "block": {"each": "items", "dir": "col", "sep": "hair", "item":
      {"box": "row", "gap": 8, "align": "center", "kids": [
        {"value": "st", "show": "mark"},
        {"value": "line", "font": "serif", "ink": 1, "width": "fill"},
        {"box": "row", "gap": 4, "width": "hug", "kids": [{"text": "收在"}, {"value": "back", "size": "small"}]}
      ]}},
    "line": {"box": "row", "gap": 8, "kids": [{"value": "items", "show": "count", "suffix": " 处伏笔"}]}
  },
  "agent": {
    "name": "伏笔追踪",
    "description": "这一章埋下的伏笔，和它们后来在哪里被收回。",
    "instructions": "只登记作者写进正文的伏笔；收回要指到具体的章。",
    "blocks": {"items": "一条伏笔一行", "st": "埋着、提过、收了", "back": "在哪一章收回"}
  },
  "sample": {"items": [{"line": "墙上的旧照片少了一个人", "st": "收了", "back": ["第十二章"]}]}
}
```

- **结构是封闭的。** 不认识的键、积木种类、节点种类、属性、取值一律拒收，和项目模板一样（project-template-format.md 第 1 节）。
- **`look.line`、`look.full` 没有这个键 = 跟着「一块」**（第 4 节）。
- **示例值里的「条目」只是几个字**，预览时画成链接的样子，不指向任何真实条目。
- **规范化写出**：UTF-8、固定的键顺序和缩进，同一个模块每次导出逐字节相同。
- **`formatVersion`** 是模块格式自己的版本。读到比自己新的就拒收并说明。社区上线前照旧干净改；上线那一刻起和项目模板一样，承诺能读所有发出去的旧版。
- **上限**（数字在实现时校一遍，写进校验器）：整份不超过 256 KiB；积木不超过 100 块；串里套串不超过 4 层；三棵盒子树合计不超过 400 个节点；写给 Agent 的字合计不超过 2 万字。

## 7. 存在哪：我的模块、项目里的抄本

### 我的模块

- **每个模块是书库里的一篇文档** `module:<模块 id>`，不属于任何书，跟着书库同步，照「我的模板」（project-templates.md 第 5 节）：`payload` 里整个存第 6 节的值，改就整个换，两台设备各改各的留后写的那份。
- **它不是书的内容。** 不计字数、不搜索、不导出、不进书文件。
- **随改随存**：工作台里没有保存键，改了就写，⌘Z 撤回；Agent 改的也是一步。

### 项目里的抄本

- 书目文档多一个根映射 `modules`：模块 id → `{value, source}`。`value` 就是第 6 节的值；`source` 记它是不是跟着「我的模块」走（下面）。
- 条目模板里多一种模块种类 `custom`，配置里只指一个模块 id；模板模块自己的 id、名字、Agent 权限、`in_book` 照旧。
- **条目里的值**存在条目节点的 `module:<模板模块 id>` 下：按积木 id 的映射，一串是能移动的列表、每项带自己的 id。和书目文档别处一样，不认识的键原样保留。

### 改了「我的模块」以后：自动换（丙）

- **用着它的项目一打开就是新的。** 打开项目时，抄本和「我的模块」里那份不一样，就换成「我的模块」里的。开着的项目里在工作台改，当场就是新的；在别的设备上改了、同步过来，也当场换。
- **想让某个项目长得不一样，在工作台上方点「另存一份」**：变成「我的模块」里一个新模块（新 id），这个项目的条目模板改用它，原来那个不动。工作台上方写着「我的模块 · 用在 N 个项目」。
- **值不丢。** 抄本换了，条目里的值一个不动：删掉的积木，值留在书里不显示，加回来就回来；改了类型的积木，旧值读得成新类型就显示，读不成就留着不显示。
- **代价**：改一次会影响所有用它的项目，包括分享出去的链接（分享页读的是书里的抄本，作者在任一设备上打开那个项目以后就是新的）。

### 跟着别人的模板或书来的模块：不进我的模块（甲）

- 用别人的项目模板新建、导入别人的书，里面带着的模块只在那个项目里，不进「我的模块」，也不跟着谁换。
- 模板编辑器里这个模块那一行写「模块」（不写「我的模块」），旁边只有一颗「存进我的模块」：点了进「我的模块」（新 id），这个项目改指向它，从此跟着走，那一行也换成「我的模块」和「改」。没存进去之前不能改（原型第三页「北渡里的模板」就是这么画的）。

### 怎么认「跟着我的模块走」

抄本的模块 id 在「我的模块」里有，就跟着走；没有就是跟着别人来的。

- 导入 `.driftingmodule`、「另存一份」、「存进我的模块」都给新 id，所以别人那里来的模块不会碰巧和我的同名同 id。
- 用自己「我的模板」里的模板新建项目，模板里的模块 id 和「我的模块」对得上，新项目照样跟着走。
- 从「我的模块」里删掉一个，用着它的项目留着抄本照常能用，从此不再跟着换（删除的界面见第 16 节第 4 条）。

## 8. 模块工作台

形状照原型第一页。

**三个入口，进同一个工作台：**

1. **跟 Agent 说**：在任何一个 Agent 对话里说要什么。Agent 直接建好模块、放进当前的条目模板，对话里一张卡「打开工作台」。
2. **丢一张草图或截图**：拖进 Agent 那一栏，Agent 照图建，同样给一张卡。
3. **自己摆**：模板编辑器「添加模块」菜单最下面「新建模块…」，打开一个空的工作台。空工作台只有一句「拖进草图或截图」。

**开在当前项目的窗口里（甲）。** 工作台是稿纸上的一个药丸；它在前面时，左栏换成「装什么」，右栏换成「长什么样 · 写给 Agent · Agent」；切到别的药丸，两栏换回来。底栏照旧。左右栏随药丸换内容在 App 里是第一次，实现时要单独验。

**左栏「装什么」**：积木树，一块一行；最下面一排是全部积木。点一块积木加进去；先选中一个「一串」或「一组」再点，就加进它里面。

**稿纸是预览**，上面一排切：

- 大小：一行、一块、铺满；
- 内容：示例、空、借一个真实条目（借的是这个项目里用着这个模块的条目）；
- 宽窄：窄、中、宽；
- 深浅：浅、深。

预览里点哪一处，就选中它在盒子树里的节点，右栏跟着跳过去。

**右栏：**

- **长什么样**：盒子树和选中节点的属性（第 4 节那张清单）。
- **写给 Agent**：照条目模板的那一栏。
- **Agent**：同一个对话，继续说就继续改。

## 9. 进模板

- 条目模板编辑器的「添加模块」菜单：自带的八种（还是现在这一串）；一道线；「我的模块」一节，一个模块一行；「社区」收着（第二期）；一道线；「新建模块…」。
- 点一个就加进模块列表。那一行写「我的模块」，旁边「改」，点了打开工作台。
- 菜单里只能挑，不在菜单里编辑、导出、删除。

## 10. 我的模块、导出、导入、社区

**「我的模块」列在「全部项目」页的左栏（甲）**，排在「我的模板」下面，小标题「我的模块」，一个模块一行。悬停卡里：名字、用示例画的「一块」、一道线，下面编辑、导出（.driftingmodule）、删除。

**导出**：不出对话框，直接弹存文件的窗口，模块存的什么样就导出什么样。署名照项目模板：导出的人的账号显示名，没设名字或没登录就没有。

**导入**：左栏「导入模块」（在「导入模板」下面），或者把文件拖进窗口。过了校验器就进「我的模块」，中间没有确认页；导入总是新加一份，不覆盖已有的。导入失败照导入模板失败的说法。

**文件**：扩展名 `.driftingmodule`，就是第 6 节的值写成的一份 UTF-8 JSON 文本。

**社区**（第二期，和社区模板一起）：

- 和项目模板同一个公开仓库，多一个放模块的文件夹，每个模块一个子文件夹。投稿、改版、撤下、举报都照 project-templates.md 第 9 节。
- 仓库的 CI 用同一个校验器查；维护者重点读写给 Agent 的那几段。
- 目录里多一种条目：模块的 id、名字、描述、署名、积木数、文件地址和 sha256。App 只读官网域名下的那份目录，照项目模板。
- 「添加模块」菜单里「社区」那一节展开逛，选一个就取文件、校验，进「我的模块」，再加进这个条目模板。逛的时候用模块里的示例值画「一块」。

## 11. 和项目模板、书文件的关系

- **项目模板带着它用到的模块。** 模板值多一个 `modules`：模块 id → 第 6 节的值；条目模板里 `custom` 模块指着其中一个。另存为项目模板时，用到的抄本一起带上；新建项目时一起抄进书里。这是项目模板格式要改的地方（[project-template-format.md](project-template-format.md) 第 5 节的模块种类多一种 `custom`），格式还没发布，照旧干净改。
- **项目模板照旧不跟。** kernel-v4 的「模板更新与项目无关」对项目模板照旧有效；这一页只让模块跟着「我的模块」走（作者 11-20 选丙）。
- **书文件**（`.driftingproject`）带着书目文档，抄本在里面，所以拿到别的设备照样能开；导入别人的书时，抄本按第 7 节算「跟着别人来的」。
- **内置的「写书」不带自定义模块。**
- **导出成书和 Markdown 文件夹第一期都不带自定义模块**（第 16 节第 2、3 条）。

## 12. 安全与校验器

和项目模板一样：模块里没有能执行的东西，所有入口过同一个校验器（`dr-model` 里的一个模块，能从命令行单独跑，给社区仓库的 CI 用）。

**校验器要拦的：**

| 拦什么 | 为什么 |
| --- | --- |
| 不认识的键、积木种类、节点种类、属性、取值 | 结构封闭，不能有藏东西的地方 |
| 第 4 节清单以外的样式：颜色值、字体名、图片、网址、样式表片段、档位以外的数字 | 风格甲；也防有人借样式塞东西 |
| 脚本、HTML、表达式、公式 | 没有能执行的东西 |
| 指向项目里东西的 id：条目、条目模板、视图、文件 | 模块和项目无关 |
| 盒子树里指着不存在的积木；「每一项」指的不是一串；「显示成」和积木的类型对不上 | 画得出来 |
| 积木 id 重复；单选、多选的选项为空或重复；示例值和积木类型对不上 | 值能存、能读 |
| 超过第 6 节的上限 | 防坏文件和故意构造的文件 |
| 比自己新的 `formatVersion` | 说清楚是版本问题 |

**哪些地方过它：** 工作台和 Agent 每次写模块；导入 `.driftingmodule`；另存、导入项目模板时里面带着的模块；从社区取下的文件（先对 sha256）；社区仓库的 CI。书里的抄本读的时候也过一遍：过不了的模块在条目页上画成一个空的占位，值照旧留着（第 16 节第 6 条）。

**风险和项目模板一样**：最实际的是别人模块里写给 Agent 的话把 Agent 带偏。对策照 project-templates.md 第 10 节：社区的上架前有人读过，帮手的通用规则，建好以后能改；不为它加展示和确认。

## 13. 命令

名字和参数由做数据层的一步定，这里只列要有哪些：

| 命令 | 做什么 |
| --- | --- |
| 建、改（整个换）、改名、删一个我的模块 | 书库文档 `module:<id>`；改的时候顺手换掉开着的项目里的抄本 |

## 14. 不变量

| 不变量 | 在哪保证 |
| --- | --- |
| 模块里没有能执行的东西，没有清单外的样式，没有指向项目里东西的 id | 校验器 |
| 同一个模块每次导出逐字节相同 | 导出的测试 |

## 替作者定的

底层做法，设计会话这样定：

- 模块是数据，三部分：积木、三棵盒子树、写给 Agent，加一份示例值。原型里那段 JSON 只是示意，格式以第 6 节为准：头两个键照项目模板写成 `format`、`formatVersion`。
- 积木对到现有的字段类型（`text`、`long_text`、`number`、`date`、`select`、`multi_select`、`toggle`、`entity_ref`、`image`），另加「一组」「一串」两种装积木的。
- 值按积木 id 存在条目节点的 `module:<模板模块 id>` 下，一串是能移动的列表、每项带 id。换抄本不碰值；读不成新类型的旧值留着不显示。
- 书里一个根映射 `modules` 存抄本；条目模板多一种模块种类 `custom`。
- 我的模块一份一篇书库文档 `module:<id>`，`payload` 整个换，照我的模板。
- 「跟着走」按 id 认：抄本的 id 在我的模块里有就跟着换。导入、另存一份、存进我的模块都给新 id。
- 「条目」积木不能限定条目模板。
- 「单独摆」一行或铺满时，先从「一块」抄一棵过来再改。
- 「一串显示成个数」是渲染时数的，不是字段。
- 单选显示成记号：第一个选项空心、最后一个实心、中间半实。
- 格的列宽：每一列是「填满」或一个固定宽度，固定宽度从一张档位表里挑（48 到 320，每 8 一档）。
- 上限的几个数字（第 6 节）。
- 模块格式的版本和项目模板格式分开；社区上线前干净改。
- 项目模板格式多一个 `modules`，格式还没发布，直接改。
- Agent 能建、改模块和写值；导入、导出、从社区取不给 Agent 和 MCP。
- 社区和项目模板共用一个仓库、一份目录、一个 CI。
