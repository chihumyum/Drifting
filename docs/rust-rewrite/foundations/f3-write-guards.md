# F3：写入守卫（按记录）

2026-11-12。接着 [f3-workspace.md](f3-workspace.md) 的「写入顺序与补偿」，讲受守卫的写入（`Workspace::call_guarded`）到底守什么。

状态：**第 1、2、3 步已落地**（内核原语、每条写命令的声明；帮手工具按记录记账和守卫；界面的保存路径不再观察整本书）。

## 大白话

「先读后写」的调用方（帮手、MCP、界面的保存）要保证一件事：我是照着读到的内容改的，要是这段内容在我读完之后被别人改过，我这次写入就不能落下去，否则会把别人的改动盖掉。

以前的做法是给整篇书目文档记一个版本号，写入时比对。可一本书只有一篇书目文档，条目树、模板、归属、时间线、补丁、情节格、关系、批注、素材、设定、记忆、写作日都在里面。于是每分钟一次的写作日记录、同步进来的任何改动、帮手改了别的条目，都会让所有等着提交的写入失败，哪怕它们碰的根本不是同一样东西。

现在改成：**写入只和它依赖的那几条记录比对**。书里别处怎么变都不影响它；它要替换的那条记录变了，照旧拒绝。

## 模型

- **记录键**：书目文档里一块可以单独比对的内容，写成「集合 + 路径」。
  - 路径为空：整个集合（`templates`、`timeline_views`、`meta`……）。
  - 一段：一条记录（映射的键，或者条目 / 素材夹的 id）。例：`timeline_views/<视图>`、`patches/<补丁>`、`entries/<条目>`、`plot_grids/<条目>/<模块>`（这个键本身带斜杠，所以键在接口里是数组，不是拼好的字符串）。
  - 更多段：记录里面的一个值。例：`entries/<条目>/title`、`entries/<条目>/fields/<模块>/<字段>`、`entries/<条目>/kv:<模块>/<行>`、`timeline_views/<视图>/pins/<时间钉>`。
  - 条目树另有一种键：**某一层的子条目顺序**（`children_of`，不给父级就是顶层）。
  - 短路径包含以它开头的长路径：读过整条记录，就算读过它的每个字段。
- **记录状态**：这块内容**自己存着的全部东西**，包括查询不显示的（回收站里的泳道名下的位置、换模板后留下的旧模块值）。取的是它的深层取值，每条记录读一次。条目记录是它的元数据加住处（父级）；同一个 id 有两个树节点时（两台设备各建了一个），两个都算。它不单独记两样东西：嵌在记录里面的值是用容器还是普通值存的，以及嵌在里面的富文本的格式。
- **摘要**：记录状态的 SHA-256。两次读到的摘要相同，就是这条记录一点没变。它只看内容，不看是谁、分几次写成的，重开库、换一台设备读出来都一样。这一点是按构造保证的：记录状态里每个对象的键都按字典序排好再取哈希。Loro 把一个映射交出来时用的是哈希表，键的先后取决于那张表是怎么建起来的，不取决于内容；dr-doc 取值时就排好序，算摘要的地方再核对一遍，不靠上游碰巧稳定。
- **观察**：`Workspace::observe_records(书目文档 id, 键列表)`，在持有者的一次读任务里算出每个键的摘要和它的普通值。不导出、不导入、不解码书里其余部分。
- **前置条件**：调用方交给 `call_guarded` 的 `WritePreconditions.records`，每条是「这个键现在应该是什么样」，有两种说法：
  - **摘要**（`Expected::Digest`）：和我观察时一模一样。整条写、帮手的写入用它。
  - **取值**（`Expected::AnyOf`）：这个键是单独一个普通值（没存就是 `null`），而且等于我给出的几个值之一。界面改一个字段时说「`[我显示过的旧值, 作者改成的新值]`」：现在是旧值就写，已经是新值也算数（别处做了同样的改动），是第三个值说明别人改过，拒绝。它不需要先观察，界面手里本来就有显示过的值。给任何容器用取值永远不成立：整条记录、列表、富文本（补丁正文），以及藏在一个普通映射值里面或者非映射容器底下的值。字段要是换了一种这个界面没显示过的存法，就不该由它盖掉。
  - 一条前置条件可以标成**只在被替换时比对**（`if_replaced`）：只有这次调用替换了这条记录、它的一部分、或者包含它的记录时才比对。界面把快照里所有显示内容的摘要一股脑交上来，不用知道每条命令替换什么，内核只拿其中被写到的那几条来比。
  - 比对都在持有者的**写任务里、任何改动之前**做，所以读和写之间插不进别的写入。
- **正文文档照旧按整篇的版本守卫**（`WritePreconditions.versions`）：一篇正文只属于一个条目的一个模块，粒度已经够细。批注锚定对来源正文的检查也不变。
- 书目文档也还可以按整篇版本守卫。只有真的需要整本书不动的调用才这样用：完整条目快照的原子恢复（`entry_snapshot.*`）。

## 内核强制的规则

1. **调用方说过的都要成立。** 这次调用带来的每一条前置条件（书的整篇版本、每条记录的摘要或取值）都在写任务开头比对。有一条不符就返回 `conflict`（`stale observation: book:<id> record <键>`），什么都不写，不记撤销日志。
2. **替换什么，就得读过什么。** 每条写命令都声明它「替换」的内容：用入参的值盖掉的已存的值，以及因为入参点了名而删掉的记录，声明到它实际写的最细路径。受守卫的调用必须给每一条声明带上同一路径或上级路径的前置条件，缺了就返回 `conflict`（`read required: book:<id> record <键>`）。带了整篇版本等于全都读过。
3. **不用声明的两类**：命令自己生成 id 新建的记录；命令自己照着当前文档规划出来的连带改动（取消归属时清掉的位置、放进回收站时跟着走的子树）。后一类本来就在租约里或写任务里按现状算，不依赖调用方读到过什么。
4. **什么都不替换，就不用读。** 纯新建（声明为空）的写入不带任何关于这本书的前置条件也可以通过；它带来的前置条件照第 1 条比对。有声明却一条关于这本书的前置条件都没带：`read required: book:<id>`。`require_all: false` 只关掉第 2 条的「缺了就拒绝」，第 1 条照样比对。
5. 没有按记录约定的命令（见下表最后两行）只认整篇版本；调用方带来的记录前置条件它们也照第 1 条比对。
6. 受守卫的调用新建正文文档之前，先在读任务里把第 1 条查一遍，过期的调用不会留下没人认领的正文。

声明是写在每个 `Cx::write_book_v3(slot, Replaces::…, …)` 调用上的必填参数，新加一条写命令不写它就编译不过。

## 这样守，守住了什么、没管什么

- **过滤后的读取不能授权整份替换**这一条不变，而且判断依据更准了：摘要算的是存着的全部内容，所以查询里看不见的数据变了，照样冲突；`RecordObservation.value` 给出记录存着的普通值，调用方拿它和查询结果对一下，就知道自己看到的是不是全部（帮手的 `timeline::Coverage`、时间线界面的 `covers` 已经是这么比的，只是以后数据来自这一条记录，不再来自整本书）。回归：`stored_data_a_filtered_read_hides_is_part_of_the_record`。
- **比的是内容，不是版本。** 记录被改走又改回原样，算没变，写入可以通过。照着读到的内容去改一条内容没变的记录，不会丢任何东西。
- **守卫不替命令检查不变量。** 「这个条目还活着吗」「这条泳道还收这个模板吗」仍由命令在书的租约里照当前文档校验，读取容错兜底。以前整本书的版本号顺带把「我读完之后书里任何变化」都挡了，现在不挡无关的变化，这正是这次改动的目的。
- **嵌套内容怎么存、嵌套富文本的格式不在摘要里。** 第 1 步原先逐层取带类型的原值，一条记录要读几十次，外壳快照给它显示的每条记录各取一个摘要，新的 Heavy 书（817 个摘要）要 27 毫秒，用了三年的书（1381 个摘要）要 43 毫秒；改成每条记录读一次深层取值以后分别是 9.9 和 21.1 毫秒（release 构建，中位数，机器同时有别的编译）。少掉的这两样不影响「照着读到的内容改不会盖掉别人的改动」：格式变了而文字没变，整条写回去的文字相同，富文本按差异更新，格式留着；存法变了是外来写入方才会造成的，取值前置条件仍然只认直接存着的单个普通值。
- **已删除记录底下保留的子映射不在摘要里。** Loro 里删掉一个映射键之后，原来那个子映射的内容还留着，别的设备离线时写进去的字段同步过来也在，只是读不到。摘要只算读得到的内容。时间线的字段级命令和两个逆操作自己另查这一层（`timeline_field_restore_state`、`membership_restore_state`），照旧。
- 这仍然是每篇文档各自的守卫，不是跨文档事务。

## 调用方怎么改

**帮手工具（第 2 步，已做）**

读工具调用：

- 不再前后各 `observe` 一遍整本书。执行器先取这次读涉及的文档的版本号（`Workspace::version`，不读内容），执行查询，观察这次读覆盖的记录，再取一次版本号；前后相同，说明查询结果和记录摘要是同一个状态下的。这个版本括号只管这一次调用，过后正文按它的版本守，书目只按读到的记录守。
- 每个 subject 记下它背后的记录和当时的摘要（`dr-agent-tools/src/records.rs`）：

  | subject | 背后的记录 |
  | --- | --- |
  | `entry:<id>` | `entries/<id>` |
  | `level:<id>` | `entries/<id>` 加这一层的子条目顺序 |
  | `entry:*`、`entry:all`、`entry:roots` | 顶层的子条目顺序；列出来的每个条目另有自己的 `entry:<id>` |
  | `module:<条目>:<模块>`（来自 `module.read`） | `entries/<条目>/fields/<模块>`、`entries/<条目>/kv:<模块>`、`plot_grids/<条目>/<模块>`，以及读到的每条补丁和关系 |
  | `module:<条目>:<模块>`（来自模块清单或模块正文）、`module:<条目>:*` | `entries/<条目>` |
  | `entry_template:<id>`、`timeline_view:<id>`、`entry_relation_type:<id>` | 那一条记录；`:*` 是整个集合 |
  | `membership:<层级>\|<成员>`（`membership.list` 的每一行、`level.get` 的每个成员） | `memberships/<层级>\|<成员>`；`membership:*` 是整个集合 |
  | `fact`、`memory`、`material`、`material_folder`、`comment`、`relation`、`asset`、`book` | 同名集合里的那一条；`:*` 是整个集合（`book` 是 `meta`） |
  | `prose:<文档>` | 正文文档，按版本，不变 |
  | `entry_history:<书>` | 没有按记录的依据：整本书的版本 |

- 书里别的记录变了，不清空已经读过的。同一条记录再读一次，换成新摘要。

写工具调用：

- 带上这次写入要求的每个 subject 背后的记录摘要，正文目标照旧带版本。整条替换点名了已有记录的（`timeline_view.put`、`entry_template.put`、`entry_relation_type.put`），只带那一条的摘要，不带整个集合的。
- 只有 `entry_history.restore` 还带整本书的版本（它的依据是 `entry_history.version` 读到的那个版本）。
- 写完（不论成败）只忘掉这次写入用到的 subject 和它们所在的列表：照着写的那份内容不能悄悄当成最新，要重读；这一轮读过的其他记录照旧有效，可以接着写。以前是任何一次写入都清空对这本书的全部读取。
- 冲突按记录计数：`stale observation: book:<id> record <键>` 里的记录冲突两次，这一轮对这条记录停手；别的记录不受影响。
- 写前快照（`entry_snapshot.create_with_receipt`）带同一组记录前置条件和正文版本，过期的写入不留快照。快照会推进书的版本，但碰不到被守的记录，所以不用再把回执里的新版本换进守卫；只有带整本版本的那一种还要换。
- 时间线的 `Coverage` 留着，原始数据来自 `timeline_views` 集合的记录观察。取消归属除了两个条目，还要求读过时间线视图（证明没有隐藏位置会被连带清掉，这份证据必须是当前的）和被取消的那条归属。

比以前严的两处（都是内核按声明拒绝的，不是执行器另加的规则）：

- 只看过模块清单（`module.list`）就整条替换补丁或情节格、删关系，以前放行，现在要先 `module.read`。清单里没有这些内容，这本来就不满足「整条替换前完整读过」。
- 取消归属、给已有的归属改顺序，要读过那条归属（`membership.list`，或它所在层级的 `level.get`）。以前只要求读过两头的条目。新加一条归属不替换任何东西，照旧只要两头的条目。

每次调用的其他整本读取也换掉了：工具目录缓存的失效判断、结构说明的前后比对改用 `Workspace::version`；`is_v3_book` 对已经打开的书不再拷贝整本（`Workspace::is_v3_book`）；`prose.read` 取批注锚点改在持有者读任务里读。名字解析（`resolve_v3`）每次调用仍拷贝一份书目文档，见「还没做的」。

**界面（第 3 步，已做）**

界面的保存有三种写法，都不再观察整本书：

1. **从显示的快照直接改**（要素与分类、岛屿、时间线上的拖放和泳道、项目记忆）。外壳读书目快照的那次读任务里，顺手取了它显示的每条记录的摘要：每个条目、每层的子条目顺序、每个模板、归属、时间线视图、素材和素材夹（`dr_shell::book::v3::BookV3::guard()`）。保存时把这组摘要全部交上去，都标成「只在被替换时比对」。草稿是从哪个快照开始的，就一直带那个快照的摘要；失败后重试才换成新的。

   从对话框或拖放发起的命令（要素页的 `Mutation`）还多守一层（`BookV3::guard_for`）：入参里点了名的条目和模板、这些条目上面的各层层级、以及它们各自的模板，不管命令替不替换它们都要比对。对话框上显示的东西是从这些记录里来的：新条目会住到哪一层、这一层收不收它、默认用哪个模板，层级设置还会从上层继承。例：悬停卡里「新建」打开以后，别处把这条泳道的「新条目住在」改了，这时点「创建」会被拒绝并保留标题，重试后按新的住处创建。新建命令本身不替换任何记录，只靠「被替换时比对」拦不住这种情况（真窗口场景 `k4-g2-actions` 第 79 步查出来的）。
2. **保存前读一次要改的那条记录**（补丁、键值行、时间钉、模板、情节格、新建时间线视图、主页的新建动作、导入）。用 `observe_records` 读这一条：读到的值用来和草稿合并或核对完整性，读到的摘要交给写入。读在合并之前，所以读之后这条记录再变，写入照旧被拒。
3. **只改一个值**（页面头部的标题和字段）。不观察，带取值前置条件 `[显示过的旧值, 新值]`；作者明确重试时先读一次当前值，改成 `[当前值, 新值]`。

各处用的是哪一种：

| 界面 | 写法 | 守的记录 |
| --- | --- | --- |
| 要素页的补丁（`dr-view-elements/src/fields/guarded.rs`） | 2 | `patches/<补丁>`；写入改用 `module.edit_patch`，只写改过的字段 |
| 要素页的键值行（同上） | 2 | `entries/<条目>/kv:<模块>/<行>`；改已有行用 `module.edit_kv`，新建行守「这一行还不存在」 |
| 要素、分类、岛屿、关系上的各种改动（`dr-view-elements/src/data.rs` 的 `Mutation`） | 1 | 快照里被这条命令替换的记录，加入参点名的条目、其上各层和它们的模板 |
| 页面头部的标题、字段（`dr-view-page`） | 3 | `entries/<条目>/title`、`entries/<条目>/fields/<模块>/<字段>` |
| 模板编辑（`dr-view-templates/src/model.rs`） | 2 | `templates/<模板>`（新建时守它还不存在） |
| 情节格（`dr-view-plot/src/v3.rs`） | 2 | `plot_grids/<条目>/<模块>` |
| 主页的新建动作（`dr-view-home/src/v3.rs`） | 2 | 声明这个动作的层级条目，加模板集合 |
| 时间线：摆放、拉长、泳道增删改序、视图改名（`dr-view-timeline`） | 1 | 快照里的那个视图 |
| 时间线：时间钉增改 | 2 | `timeline_views/<视图>/pins/<时间钉>`；完整性核对用这一条时间钉存着的值 |
| 时间线：新建视图、幕轨道模板 | 2 | `timeline_views/<视图>`、`templates/tpl-act-track` |
| 项目记忆（`dr-view-agent/src/project_memory.rs`） | 1 | 快照里被改的那条记忆，另加「这本书没进回收站」（`meta/deleted_at` 取值为空） |
| 导入一篇文档（`dr-export/src/import/write.rs`） | 2 | 解析出来的目标层级和模板 |

读一份前后一致的拷贝时用来括住它的两次整本观察（项目记忆、主动建议的签到、导入、帮手的结构说明），都换成了 `Workspace::version`。

新增的两条字段级命令：

| 命令 | 入参 | 说明 |
| --- | --- | --- |
| `module.edit_patch` | `{book, entry, module, id, title?, body?}`，`title: null` 清空标题 | 只写给出的字段，返回改完的补丁。读和写在同一个写任务里，没给的字段保持当时存着的值；补丁已被删掉时返回 `not_found`，不会建出一条空的 |
| `module.edit_kv` | `{book, entry, module, row, key?, value?}` | 同上，行的位置不动 |

它们不进帮手的工具目录（帮手照旧整条写，由执行器带记录摘要）。`module.put_patch`、`module.put_kv` 不变。

## 变了的行为

- **带记录前置条件的受守卫调用，不再因为同一本书里无关的写入而冲突。** 这是目的。带整篇版本的调用一字不变，所以现有调用方和现有测试的结果都没变。
- `entry.update` 只写入参点了名的字段。以前会把另外几个字段按命令读到的值重写一遍，租约外同步进来的改动有可能被写回旧值。
- `WritePreconditions` 多了 `records` 字段（默认空）。用结构体字面量构造它的 10 处补了 `records: Vec::new()`，其中 3 处在测试里，属于机械改动，断言没动。
- 冲突信息里记录级的两种多了 `record <键>` 后缀；`code()` 还是 `conflict`。
- 新接口：`Workspace::observe_records`、`Workspace::version`、`Workspace::is_v3_book`、`dr_workspace::observe_records_in`（给自己在读任务里读快照的调用方），类型 `RecordKey`、`RecordObservation`、`RecordPrecondition`、`Expected`；dr-doc 新增 `v3::RecordKeyV3`、`RecordReaderV3`、`RecordStateV3` 和 `BookViewV3::record_state`（只加不改）。
- 摘要只在内存里用（一轮对话、一个界面的草稿），不落盘、不同步，所以以后换哈希或者 Loro 升级改了序列化都不影响已有数据。
- 命令面：新增 `module.edit_patch`、`module.edit_kv`（注册表和能力清单各多两条；帮手目录的排除表多这两条，可调用的工具没变）。其余命令的入参和输出没变。
- 界面这边（第 3 步）：保存只在它替换的那条记录变了的时候冲突。以前是同一本书里任何变化都冲突，要素页的 `Mutation`、时间线的各种编辑、项目记忆都是这样。
- 导入校验（第 5 步）：校验用的拷贝也并入还在等依赖的更新。以前能通过的一种顺序（改 `meta.v` 的更新先到、依赖后到）现在被拒。
- 帮手这边（第 2 步）：同一本书里无关的改动（包括帮手自己对别的记录的写入）不再让它重读；冲突信息里是记录不是整本书；上面「比以前严的两处」。

## 导入校验（第 5 步）

从同步收到一份书目更新时，库先把整本书目拷贝一份，把更新并进拷贝，看并完以后它还是不是 v3 的书，是才真的导入。拷贝的代价跟着书的大小走：新书 1.6 毫秒，三年的书 97 毫秒，发生在这本书的存储线程上，这期间这本书的写入排在后面。整次远端导入是 4.4 和 110 毫秒。

**结论：判断方法不改。** 没有找到既安全、又不带来新代价的便宜做法。顺带补了现有校验的一个漏洞。

### 怎么算「还是 v3」

一份更新能不能进，看的是「库里已有的全部操作，加上还在等依赖的更新，再加上这一份」合并以后 `meta.v` 是不是 3。更便宜的做法必须对每一种输入给出同一个结论，包括依赖还没到的更新、和本机最新版本并发的更新、先写上 3 再删掉的更新。

### 试过的做法

| 做法 | 三年的书上 | 为什么不用 |
| --- | --- | --- |
| 只看更新本身（在空文档上导入） | 很便宜 | 增量更新依赖库里的历史，在空文档上只会挂起，看不到它改了什么。Loro 1.17.1 没有「不导入就读出一份更新里各个操作」的公开接口。`validate_book_header` 已经用这一招拦完整的旧格式载荷，拦不住增量。 |
| 扫字节 | 很便宜 | 更新是压缩编码的，扫不准。 |
| 用浅快照当底 | 导出 25 + 导入并合并 12 = 37（现在约 95） | 只对「从本机最新版本接着写」的更新有效。两台设备都写过时，对方的更新落在浅快照起点之前，导不进去，要退回整份做法，这时更慢（37 + 95）。小书上也更慢（新书 9 对 1.6）。 |
| 先导入、再检查、不对就撤 | 平时不花钱 | Loro 不能回滚。要做成「不落盘、丢掉内存里的文档、从盘上重装」，得改 dr-store 的持有者，而读者和界面共用着同一个文档对象。这是唯一平时不花钱的做法，但属于存储层的设计改动，不在本任务范围。 |
| 把拷贝留着，下次接着用 | 稳定后 0.5；头两次 64 和 105 | 结论和现在等价（先比版本向量，不相等就重建；被拒的更新会弄脏拷贝，要丢掉重建）。代价是每本正在同步的书在内存里多一份完整文档，校验钩子里多一份状态。这是缓存，没有自己加，留给监管者定。 |

### 现在的时间花在哪

三年的书：导出快照 20，导入快照 11，往刚导入的拷贝里并第一份更新 64（拷贝是懒加载的，第一次合并才把历史解开）。三年的书目文档 26 MB 里有 23 MB 是写前快照清单；文档小下去，这三项一起小。建议的顺序是先等书目文档瘦身（另一项工作），再量；还不够，再做「把拷贝留着」。

### 补上的漏洞

快照不带「还在等依赖的更新」。于是有这样一种顺序能绕过校验：一份改 `meta.v` 的更新先到，它依赖的更新还没到，它挂起，校验看不出问题；依赖随后到，校验用的拷贝里没有那份挂起的更新，照样通过，真的文档却把两份一起应用了。结果是书被标成非 v3，重开以后打不开。合并前的 `main` 上能复现。

现在校验用的拷贝也并入 `LoroDoc::export_pending_updates()`。两份一起到、标记先到依赖后到、依赖先到标记后到，三种顺序里改标记的那一份都进不来，书保持 v3（`dr-workspace/tests/cutover.rs` 的 `a_marker_change_that_arrives_before_its_dependency_is_refused_with_it`）。没有挂起的更新时多一次返回空的调用，量不出差别。

被拒以后，那份挂起的更新还留在内存里，带着它依赖的更新会一直被拒，这本书的同步停在这里，书本身完好。挂起的更新不落盘（持有者只存已经应用的操作），重启后要等对方重发，那时它的依赖已经在库里，会被直接拒掉。

- `entry.update`、`module.set_field` 自己在大书上要几百毫秒，是现在标题和字段保存的大头。
