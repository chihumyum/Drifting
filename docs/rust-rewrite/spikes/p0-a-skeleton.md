# P0-A 工程骨架：结论

2026-11-07，分支 `claude/p0a-skeleton-aff432`，基于 `main` a2546cab。代码在 `next/app/drifting`，打包脚本在 `next/script`，CI 是 `.github/workflows/next.yml`。

## 结论

**能做，而且不用改 GPUI。** 在 Zed `v1.27.0` 的 GPUI 上，探针要的几件事都做出来了，全部是 GPUI 的公开接口，外加几行 AppKit 调用：

- **自定义标题栏**：内容一直铺到窗口顶上，红绿灯挪到旧版的位置，在 42 pt 的标题栏里垂直居中；拖动标题栏移动窗口，双击按系统设置缩放或最小化。最小窗口 1000×700，默认 1440×900，和旧版一样。
- **菜单栏**：应用菜单（关于、设置占位、服务、隐藏、退出）、编辑菜单（撤销、重做、剪切、复制、粘贴、全选）、窗口菜单。系统认出了编辑菜单，自动加上「自动填充」「听写」「表情与符号」；窗口菜单里系统也加了平铺、全屏和窗口列表。
- **深浅色**：跟随系统；系统切换时窗口收到通知，换一套颜色重画。验证时没动系统设置：开发开关只改本应用自己的外观，走的是和系统切换同一条路。
- **打包**：`script/bundle-mac` 打出 `Drifting Next.app`，用 `open` 打开（和双击走同一条路）能起来，带旧版的图标。开发期身份是 `cc.drifting.next.dev`，和装着的正式版互不干扰。

**最要紧的发现：工作区原来的依赖声明在 macOS 上一个字都画不出来。** `gpui_platform` 少开了 `font-kit` 特性，GPUI 就退回一个「只排版、不画字形」的占位文字系统，只在日志里说一句；程序又没装日志器，所以完全静默。骨架里那个空窗口的「Drifting」字样其实从来没显示过。已在 `next/Cargo.toml` 补上，也在共享笔记里告诉了另外几路。GPUI 的很多错误都只走 `log`，所以骨架加了一个最小的 stderr 日志器（`DRIFTING_LOG`）。

**启动不慢，慢的是 macOS 的启动流程，而且机器在测的时候很忙。** 几路会话同时在编译，测量时 12 核机器的负载在 6 到 44 之间，墙钟时间被拉长了好几倍。拆开看：

- 我们的程序和一个最小的 AppKit 程序（Swift 写的，开一个空窗口）在同样条件下几乎一样快，说明 GPUI 本身没有添多少开销。
- 用 `open`（也就是双击）启动比直接运行可执行文件多出 0.3–0.4 秒，这一段对照程序也一样多，是 Launch Services 自己的。
- 进程从启动到画完首帧，实际只用了 0.13 秒 CPU，其余时间都在排队。

**数字**（M3 Pro，release 构建，明细见文末）：

| 项 | 结果 |
| --- | --- |
| `.app` 体积 | 12.7 MiB：可执行文件 8.4 MiB，两份图标 4.3 MiB；压成 zip 7.3 MiB |
| 冷启动到首帧，`open` 启动（负载约 10，9 次中位数） | 0.70 s（0.55–0.81） |

**对计划的影响**：没有推翻任何决定。有一处要作者留意：发布档的「冷启动到书架 ≤ 300 ms」，在这台机器上，连最小的 AppKit 程序经 `open` 启动都超过了，预算要么改成从进程 `main()` 开始算，要么在空闲机器上重测后再定。

## 怎么验证的

都在本机做，没改系统设置，测试窗口用完都关了。

- **窗口和标题栏**：用 `screencapture -l <窗口号>` 截了浅色、深色、设置占位卡、关于窗口和打包后的窗口。红绿灯中心落在 42 pt 标题栏的正中，标题居中，标题栏的底色铺到了红绿灯下面。
- **深浅色**：系统是浅色。`DRIFTING_APPEARANCE=dark` 启动后，探针记下的顺序是：窗口按浅色打开 → 画完首帧 → 开关在首帧之后改本应用的外观 → 窗口收到「外观变为 dark」→ 重画成深色。这和系统切换走的是同一个回调。浅色、深色各截了图，系统设置前后都是浅色。
- **菜单**：用系统事件（辅助功能接口）列出每个菜单项、可用状态和快捷键，再用它「点」菜单项：
  - 复制 → 主窗口视图收到了 Copy；设置… → 出现占位卡；关于 → 打开关于窗口；关闭窗口 → 关于窗口关了；最小化 → 主窗口收进 Dock；退出 → 进程退出。
  - 没有模拟按键（怕按键落进别的应用）。快捷键是从菜单项上读出来的：⌘, ⌘H ⌥⌘H ⌘Q ⌘Z ⇧⌘Z ⌘X ⌘C ⌘V ⌘A ⌘M ⌘W 都在。
- **打包**：`codesign -dv` 显示 ad-hoc 签名、标识 `cc.drifting.next.dev`；`plutil` 检查过 `Info.plist`；`assetutil` 显示分层图标有浅色、深色、可着色三种外观和 32–1024 px 六种尺寸。`open` 打开后，菜单栏第一项是「Drifting Next」，进程的 bundle id 是开发用的那个。
- **Windows**：本机跑不了 Windows。对 `x86_64-pc-windows-msvc` 目标的 `cargo check` 和 `cargo clippy -D warnings` 都通过。GPUI 的构建脚本要用 `llvm-rc` 把 Windows 清单编进程序，本机用的是 Homebrew LLVM 里现成的那一个，只临时放进 PATH，没装新东西。真正在 Windows 上跑起来、看三个按钮和 Snap 布局，要等 CI 或作者的虚拟机。
- **CI**：`actionlint`（带 shellcheck）通过；`node scripts/check-ci-contract.mjs` 照旧通过。没推送，CI 本身没跑过。

## GPUI 的坑

按影响从大到小：

1. **macOS 不开 `font-kit` 就不出字。** 见上。`next/Cargo.toml` 现在是 `features = ["font-kit", "runtime_shaders"]`。Windows 用 DirectWrite，不受影响。
2. **GPUI 的报错只走 `log`。** 不装日志器，字体、着色器、窗口的问题全是静默的。骨架装了一个 stderr 日志器，默认 warn 级；F7 换成 `tracing` 和日志文件时要接住 `log` 的输出。
3. **`KeyBinding::new("secondary-z", …)` 会在启动时崩。** `secondary-`（macOS 上是 ⌘，别处是 Ctrl）只在按操作系统解析键位文件时有效，写在代码里就是解析失败、`unwrap` 崩溃；而且崩在 GPUI 的启动回调里，会变成「uncaught foreign exception」直接中止。骨架用一个宏在编译期拼 `cmd-` / `ctrl-`，测试会构造全部快捷键，能提前抓到。
4. **菜单动作派发期间，当前窗口被「借出」。** 应用级的动作处理函数里直接更新当前窗口，会得到「window not found」，而且很容易被 `.ok()` 吞掉。最小化、缩放、关闭窗口、打开设置一开始都是这样静默失效的。要用 `cx.defer` 等派发结束再动窗口（`menus::after_dispatch`）。F6 的命令系统要把这条写进约定。
5. **菜单项可不可用，取决于有没有人处理这个动作。** 编辑菜单六项只有在焦点所在的视图处理了对应动作时才可点，应用在后台时全部变灰。撤销、重做不走 AppKit 的 `undo:` / `redo:`；剪切、复制、粘贴、全选走系统的 `cut:` 等，再转回 GPUI 动作。所以编辑器只要处理 `edit::Undo` 这六个动作，菜单和快捷键就都通了。
6. **窗口菜单靠英文标题 `Window` 认。** GPUI 只把标题恰好是 `Window` 的菜单交给系统当窗口菜单。菜单翻成中文，窗口列表和平铺项就没了。系统认编辑菜单的规则没找到文档，中文标题下能不能保住「听写」「表情与符号」没试。
7. **红绿灯坐标的含义和 Tauri 不同。** GPUI 把按钮放在一条比按钮高 `2y` 的条里居中，`(18, 14)` 才让 14 pt 的按钮落在 42 pt 标题栏正中；旧版 Tauri 的 `(18, 23)` 照抄过来会偏下。
8. **macOS 27 上，让 AppKit 管标题栏拖动会让点击变慢。** GPUI 新加了 `app_owns_titlebar_drag`：开了以后 AppKit 不再处理标题栏，拖动和双击要自己写（按下后移动就 `start_window_move`，双击调 `titlebar_double_click`，后者会读系统「双击标题栏」的设置）。
9. **现在的构建每开一个窗口都要现编着色器。** 工作区开了 `runtime_shaders`（打出来的包也是），GPUI 在每个窗口的渲染器创建时编一次 Metal 源码。系统会缓存；从数字看，缓存跟着可执行文件走：重新编译后的第一次启动多出约 0.33 s，和单独编一次这份着色器的耗时相当。正式包预编译以后就没有这一步。
10. **外观回调在窗口打开时会先空响一次**（外观没变也会调），统计切换次数时要去掉。
11. **增强对比度下可能被当成浅色**（只读过代码，没验证）。GPUI 只认 Aqua、DarkAqua 和两个 Vibrant 外观，别的名字一律当浅色；系统开了「增强对比度」时，外观名是另外的高对比度版本，所以「深色 + 增强对比度」可能画成浅色。要作者手测；真有问题，F6 可以自己问 AppKit 最接近深还是浅，绕过 GPUI 的判断。
12. **Windows 没有菜单栏。** `set_menus` 在 Windows 上只把菜单存成数据，快捷键照样生效；Zed 是在标题栏里自己画了一个菜单按钮。Windows 上要不要画、画在哪，归 F6。
13. **点 Dock 重新开窗**要在 `run` 之前注册（`Application::on_reopen`）。
14. **从后台进程 `open` 的应用拿不到焦点。** macOS 14 起应用不能自己抢前台，`cx.activate(true)` 在这种情况下不生效，窗口出来了但红绿灯是灰的。作者自己双击时不受影响；自动化验收要先把应用切到前台，菜单项才会按焦点视图启用。
