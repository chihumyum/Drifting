# P0-D 视觉探针：素玻璃、砂笔、字海、封面

2026-11-07。探针程序在 `next/spikes/visual`（包名 `visual-spike`），截图在 [p0-d/](p0-d/)。

## 定了什么

2026-11-07 作者看过以后：素玻璃「按性能优先定」，浮条「你定」，字海简化「可以」。据此：

- **素玻璃用乙（遮盖）。**
  - 为什么：甲是三个方案里唯一每帧要用 CPU 重算的，性能优先就先排除它。乙和丙每帧都几乎不花 CPU，乙还保留了纹理切出来的粗细不一的边，更像现在，所以选乙。
  - 乙的条件是玻璃底下和四周得是已知的平色。底下不平的少数地方（压在图片、PDF 上的玻璃之类）退回丙的均匀细线。
  - 菜单和悬停卡的细线沿用现在 `glass-ring.png` 的做法，也是 GPU 直接画。
- **浮起的玻璃（工具条、Dock 药丸、浮着的侧栏开关）用不透明的稿纸色。** 乙本来就要求这样；没有背景模糊以后，半透明只会让底下的字清清楚楚地透出来，不如不透。菜单和悬停卡现在就是不透明的，正好一致。
- **字海用简化画法**：动起来时点留在原地，只浮出字。
- 砂笔图标和记号用 `svg()` 内嵌位图着色，封面和热力图用 CPU 画成位图。这两条是技术选择，随结论一起定。

## 先说结论

- **素玻璃**：GPUI 不能给单个元素做背景模糊，这一点三个方案都补不回来。除此之外，三个方案都能做出来，差别在「边像不像」和「代价放在哪」：
  - **甲（烘焙）**：照着现在 CSS 的算法，用 CPU 把每块玻璃的边逐像素算成一张小图贴上去。边和现在一模一样，浮条也能半透明。代价是正在流动或正在变化的那几块玻璃，每帧要重算一次。
  - **乙（遮盖）**：GPU 先把玻璃纹理整块铺上，再用底色把中间盖掉，只留一圈边；流动就是挪纹理。边几乎一样，CPU 不花力气。条件是玻璃底下和四周必须是一块已知的平色，所以浮起的工具条只能不透明，下面的正文完全看不见。
  - **丙（平线）**：只用 GPUI 自带的细边框和内阴影。最便宜，放在什么上面都行。但边变成了一条均匀的细线，现在玻璃最有辨识度的「粗细不一」没有了，流动也只剩内晕慢慢绕圈。
  - 作者让按性能优先定，选了乙，见上一节。
- **砂笔图标**：「内嵌位图」最好。和现在一模一样，换颜色不花任何代价，占的内存也最少。「转矢量」在 16px 下看不出区别，48px 下砂粒糊成了一片。「预着色」每多一种颜色，全套图标多占约 5 MB。
- **字海**：水面计算几乎不花时间（每帧约 0.1 ms）。花时间的是把几千个字交给 GPUI 去画：
  - 完整照搬现在的画法，每帧 8–20 ms，波大的时候超出 120 Hz 的预算；
  - 简化成「波过的时候，底下的点不跟着晃，只浮出字」，每帧 3–7 ms，基本在发布档以内。
  - 作者同意用简化画法。
- **封面和热力图**：用 CPU 画成位图再贴上去，没有问题。一张封面 7–10 ms，热力图约 4 ms，放后台线程画完再贴即可。

## 素玻璃

### 现在的玻璃是怎么画的

`src/styles/materials.css` 的 `.glass::before`：

- 两层内阴影：一条 1px 的环，和一圈向内晕开的光（默认 9px）；
- 颜色是 `--glass-cc`，强度是 33% × 1.8 × 当前强度；
- 两层一起被 `glass-thick.png`（150px 一块，平铺）当遮罩切开，所以边粗细不一；
- 悬停时遮罩的位置 15 秒沿对角线走 150px，这就是「流动」。

浮起来的玻璃（工具条、Dock 药丸、浮着的侧栏开关）底下垫 80% 的稿纸色，加 1.6px 背景模糊。菜单和悬停卡现在是不透明的桌面色，边是同一张纹理预先着色好的 `glass-ring.png`，铺在一层内缩 1px 的底色下面，露出来的就是一圈细线。

GPUI 里缺的三样东西决定了要怎么改：

- 没有单个元素的背景模糊；
- 没有遮罩；
- 没有自定义着色器。

### 三个方案

| | 甲 烘焙 | 乙 遮盖 | 丙 平线 |
| --- | --- | --- | --- |
| 怎么画 | CPU 按 CSS 的公式逐像素算出环、内晕和纹理切口，存成一张图贴上去。流动时按新的纹理位置重算 | 把纹理当单色图（SVG 包一层 PNG）用 GPU 着色铺满控件；再用底色盖住中间（一块 1px 内缩的实色，加一块柔边阴影做内晕的渐隐），圆角外面用底色补回。流动时只挪纹理 | 一条均匀的 1px 边框，加一层内阴影当内晕，浓度按纹理的平均透明度（0.463）折算。流动时内阴影的偏移慢慢绕圈 |
| 像不像 | 和现在逐像素同一个算法：粗细不一的边、内晕、按下加深、深色里内晕提亮，都对得上 | 静止、悬停、按下、选中在截图里和甲几乎分不出来。内晕的渐隐曲线是近似的；深色下环和内晕只能用同一种颜色（取两者中间），有颜色的玻璃在深色里环略亮、内晕略暗 | 结构对（细线加内晕，四种状态、时长都一样），但边是整齐的实线，像一圈柔和的磨砂描边；流动只是一点光影绕着走，不明显 |
| 浮条底 | 84% 稿纸色。正文从浮条底下透出约 16%，字是清楚的（现在是模糊的） | 只能不透明：遮盖要求底是平色。浮条下的正文完全看不见 | 92% 稿纸色，透出约 8% |
| 放在不平的底上 | 可以 | 不行：字海的点、正文、图片会在控件里面和圆角外面被底色盖掉一块。菜单的投影在圆角处也会被切掉，所以菜单和悬停卡改用现在的 `glass-ring.png` 做法 | 可以 |
| 每帧 CPU | 流动或变化中的玻璃，每块每帧重算一次：28px 圆钮 0.04 ms，156×36 工具条 0.27 ms，240×200 菜单 0.9 ms | 几乎为零（挪几张贴图） | 几乎为零 |
| 内存 | 每块看得见的玻璃一张图（宽 × 高 × 4 × 2²）：工具条 90 KB，菜单 770 KB，整个稿纸页约 2.2 MB | 一张纹理（共用），颜色随便换 | 无 |
| 代码上的负担 | 尺寸、状态一变就要重算并换掉旧图（`drop_image`），忘了就会占着图集不放 | 每个控件都要知道自己底下和四周是什么颜色，传错了会露出色块 | 无 |

稿纸页整帧的 CPU 时间（release，1280×800 窗口，2 倍屏；包括正文、菜单和两侧八块一直在流动的对照玻璃）：

| | 甲 | 乙 | 丙 |
| --- | ---: | ---: | ---: |
| 工具条和一个按钮在悬停中，p50 | 1.1–1.8 ms | 0.45–1.8 ms | 0.6–1.8 ms |
| 其中甲的重算 | 每帧约 5.4 块，共 0.7–0.8 ms | — | — |

三个方案的 GPU 开销都看不出差别。

### 共同的限制

- **浮条下的正文是清楚的，不是模糊的。** 甲和丙只能调「透多少」：现在的 80% 加模糊，换成 84% 不模糊，字还认得出来，所以截图里浮条下面那行字是可读的。要和现在一样「几乎看不见」，得调到 92% 以上，或者像乙一样不透明。
- **菜单和悬停卡本来就不透明**，三个方案在这里差别只在那圈细线：
  - 甲：烘焙出来的静止细线；
  - 乙：现在的做法原样搬过来，GPUI 的贴图支持逐角圆角，正好够用；
  - 丙：一条均匀细线。

## 砂笔图标

132 张 96px 白色遮罩，三种着色办法：

| | 内嵌位图 | 转矢量 | 预着色 |
| --- | --- | --- | --- |
| 怎么做 | 一个只装着这张 PNG 的 SVG 交给 GPUI 的 `svg()`；GPUI 用 resvg 栅格化后只取透明度，画的时候按当前颜色上色 | 把遮罩按三档透明度描成轮廓（7125 个环，12 万个点），叠成一个 SVG | 每种颜色生成一张彩色位图，缓存起来 |
| 效果 | 和现在一样，砂粒都在 | 16px 下看不出区别；48px 下砂粒变成了一团团的色块，干笔的毛边变整齐了 | 和原图一样；缩到 16px 时没有逐级缩小的过滤，颗粒略显生硬 |
| 内存 | 源文件 571 KB（PNG 转 base64）；每种尺寸每个图标一张单通道小图，16px 约 4 KB，颜色不占内存 | 源文件 771 KB，比 PNG 还大；显存同左 | 每种颜色每个图标 36 KB，全套约 4.9 MB，GPU 里再存一份 |
| 换颜色 | 零开销 | 零开销 | 全套重新着色 0.3 ms，然后整套重新上传到 GPU |
| 首次画出 | 每个图标每种尺寸约 0.14–0.24 ms（之后缓存） | 0.15 ms，复杂的到 3 ms；另外描轮廓本身 43–55 ms（可以预先做好） | 几乎为零 |

内嵌位图同样适用于砂笔记号（`sand/` 里的遮罩）：原型里书架卡、悬停卡的记号都是这样画的。

## 砂笔与「叠色」

现在浅色主题里砂笔用 `multiply` 叠上去，GPUI 没有混合模式。在平的底色上可以换算成普通叠加：把颜色先乘上底色，再按原来的透明度画上去，结果完全一样（`theme.rs` 的 `sand_on`）。原型里的封面笔迹、热力图、字海里浮起的字都这样画。

不平的底上就对不上了，比如正文里批注的砂笔压在字上。那里可以改成把砂笔画在字的下面，效果等价。这一条留给 F4 / `dr-editor`。

## 字海

照现在的模型搬到 CPU 上：

- 水面是 7px 一格的二维波动方程，9 点拉普拉斯，吸收边界，每秒 100 步，和帧率无关；
- 字是 10px 一格，用的是那段合成散文；
- Loading 是数字雨，加上被水托起的粗体衬线「Loading」：字形用 GPUI 的 resvg 把 SVG 文字栅格化到水面格子上。
- 「Loading」松开时的炸开做了简化：没有先把字的笔画连成一整块剪影，也没有让中间那块水慢慢沉下去，所以第二道余波会比现在略明显。

画法：

- 静止时，整片点是一张缓存的 10×10 格贴图，平铺约 120 次，不计算。这时画一帧 CPU 只要 0.2–0.5 ms，而且水面静止时根本不出帧。
- 动起来时，只画被水、雨或字碰到的格子。

1280×800 窗口：127×75 格字，183×110 格水。每帧 CPU 时间（release，含整帧排版和绘制）：

| 情形 | 动着的格子 | 简化画法（默认） | 完整画法（`SEA_PAINT=full`） |
| --- | ---: | ---: | ---: |
| Loading（雨加字） | 5–7 千 | p50 3.1–3.6 ms，p95 5.8–7.7 ms | p50 8.4–11.5 ms，p95 11–14 ms |
| 松开时炸开 | 约 9 千 | p50 6.0–6.7 ms，p95 7.9–11 ms | p50 18–20 ms，p95 23–25 ms |
| 每 250 ms 落一滴 | 约 8.4 千 | p50 5.0–5.5 ms，p95 6.6–6.8 ms | p50 16–18 ms，p95 19 ms |
| 其中水面计算 | — | 0.1 ms | 0.1 ms |

- **完整画法**和现在的着色器一样：每个动着的格子先盖掉原来的点，再把点画到被坡度推开的位置，然后画字。每格两块矩形加一个字。
- **简化画法**：点留在原地不动，只画浮起来的字。
- **钱花在哪**：GPUI 每画一个图元，CPU 要 0.5 µs 左右（矩形和字形差不多），一万个就是 5 ms。简化画法每格只剩一个字形，所以快了三倍。
- **GPU 不是瓶颈**：离屏渲染加读回整帧，静止和翻涌时都是 9–12 ms，差别在噪声里。
- **预算**：按 [benchmarks.md](../benchmarks.md) 的帧时间，探针档 16.7 ms、发布档 8.3 ms。简化画法的 p50 都在发布档以内，p95 只在炸开那一下、机器忙的时候超过；完整画法在大波浪时连探针档都超。
- **再往下优化的路**：
  - 按水面高度跳过更多格子；
  - 或者给 GPUI 打补丁，开一个批量提交精灵图的接口，绕开逐个图元的开销。

## 顺带发现的 GPUI 事实

- **macOS 上要开 `gpui_platform` 的 `font-kit` 特性，否则一个字都不画。** P0-A 已发现并在它的分支上改了工作区依赖；本探针只在自己的 `Cargo.toml` 里加了这个特性，不和那边冲突。
- **截图不需要录屏权限。** `HeadlessAppContext` 加 Metal 离屏渲染器，用的是真实的文字系统；`Window::render_to_image` 把一帧画进纹理再读回。这两样要开 `gpui_platform/test-support`，本探针放在可选的 `capture` 特性后面。窗口模式截图不可靠：窗口被别的程序挡住时 macOS 不出新帧。
- **`svg()` 栅格化后只留透明度，画的时候再上色。** 所以「SVG 里只装一张 PNG」就能给任意位图遮罩上任意颜色，还是 GPU 缓存的。
- **`paint_image` 可以给每个角单独设圆角。** 所以「纹理铺在不透明底下、露出一圈细线」这种做法能原样搬过来。
- **每个图元约 0.5 µs 的 CPU 开销。** 一帧画上万个图元就要 5 ms 以上。Super View、全书视图这类图元多的界面要早点考虑。
- **没有混合模式。** 平底上的 `multiply` 可以换算成普通叠加。

## 当时请作者定的事

问的是这三件，答复见开头「定了什么」：

1. **素玻璃选哪个方案**：甲、乙、丙，或者混用。
2. **浮条底透多少**：没有背景模糊以后，84% 时浮条下的字可读，92% 隐约可见，100% 看不见。
3. **字海的简化画法能不能接受**：波过时底下的点不跟着晃，只浮出字。不接受的话，完整画法在大波浪时会掉帧，要给 GPUI 打补丁。

都在 `next/spikes/visual/src/`：

| 文件 | 内容 |
| --- | --- |
| `glass.rs` | 三个方案：`bake_rim`（甲）、`paint_cover`（乙）、`paint_flat`（丙）；状态和时长在 `Anim` |
| `icons.rs` | 描轮廓（`vectorize`）和预着色（`tint`、`TintCache`） |

| `covers.rs` | 等高线（`topo`）、笔迹（`sand_cover`）、热力图（`heatmap`） |
| `scenes.rs` | 五个页面 |
| `capture.rs` | 离屏截图、测量，以及用合成鼠标事件检查悬停、按下和点击 |
| `theme.rs` | 从 `index.css` 抄来的颜色，以及 `sand_on` |
