## 1. 目标与判断依据

目标是让输入、标签切换、Agent 流式输出和图谱操作的开销，主要取决于本次变化涉及的内容，
并控制大型项目、长会话和多标签场景下的增长。模块拆分服务于数据归属、失效范围与独立验证。

当前源码中可定位的集中点如下。行数仅用于定位审查对象，不能直接证明卡顿。

| 对象 | 基线观察 | 优化价值与证据边界 |
| --- | --- | --- |
| `useEntityEditor.ts`，1,564 行；`entity-link.ts` | 文档变化会触发全文实体链接 DOM 查询和颜色写入；上下文颜色解析包含数组查找 | 位于编辑热路径；已确认重复操作路径，尚未测量真实输入延迟 |
| `data-store` 消费者、`EditorMainArea` | 审查定位 25 处无 selector 的 `useDataStore()` 调用；所有已打开的桌面标签保留编辑器；各编辑器又订阅多组项目数据 | 数据更新可传播到不相关和隐藏视图；保留编辑器本身承担连续性契约 |
| `agent-chat-store.ts`，1,451 行 | 每个 journal/transient 事件复制已见事件 ID 对象；累计复制量随事件数呈平方增长 | 长流式会话有明确算法风险；不能把隔离表达式的运行时间当作界面卡顿时长 |
| `DesktopSuperElementView.tsx`，3,069 行；`DesktopStoryGraphView.tsx`，2,351 行；`DesktopBottomTimeline.tsx`，1,710 行 | 数据投影、几何测量、手势和浮层集中；连线中查找实体，几何状态更新落在大组件 | 需要隔离更新范围，减少重复查找和布局读取；已有手势优化须保留 |
| `ProjectRuntimeProvider`、`workspace-projection.service`、`reference-index.service` | 结构变更走完整工作区捕获，发布后启动整项目正文引用重建 | 小变更可能触发大项目开销；正文增量已有独立路径，不能全部归为全量刷新 |
| `AppRoutes`、`DesktopOverlayHost` | 多个路由、图谱和浮层静态导入；该基线既有构建的主 JS 约 5.29 MB，gzip 约 1.48 MB | 是加载边界候选；文件字节数不能代替原生启动实测 |

既有优化应继续保留：正文持久化 400 ms 合并及退出/失焦/保存刷新、自动链接 500 ms 合并、
普通事务映射 dangling decorations、Agent 历史消息 memo、图谱平移中的直接 DOM transform、
正文同步与结构刷新分流，以及工作区的 `projectId + epoch` 原子发布。
具体参数以实施时源码为准，F0 需复核基线是否漂移。

## 2. 架构边界与目标分工

沿用[当前 renderer 架构](../renderer-ui-architecture.md)：desktop/mobile 是兄弟 shell，
共享项目运行时。增加明确的读取、计算和显示边界，不创建第二套正文或 Agent 权威状态。

| 层/职责 | 权威数据与生命周期 | 允许的失效和更新范围 |
| --- | --- | --- |
| 项目运行时 | SQLite、live Yjs、同步、Agent Runtime；按项目/用户生命周期持有 | 事务提交和项目切换；不随子路由或普通标签切换重启 |
| 项目只读快照与 selector | 一致性快照及 ID 查询；缓存归属项目和 generation | 同一批快照原子可见；只改变语义上受影响的记录与集合引用 |
| 派生索引 | 名称、颜色、归属、关系端点、图谱读模型 | 按语义修订失效；支持清空重建，无权覆盖 SQLite/Yjs |
| 编辑器会话 | 文档连接、撤销历史、选择、滚动和未提交字段 | 与打开标签生命周期一致；隐藏时仍接收权威更新和完成必要持久化 |
| 编辑器显示效果 | 链接着色、Review 装饰、浮层和可见统计 | 按实体、可见性及版本更新；显示前补齐，不重建文档会话 |
| Agent 投影 | 持久日志投影和 transient 展示状态 | 去重、顺序与恢复归运行时投影层；React 只订阅所需会话/消息 |
| 图谱视图 | 共享纯读模型；shell 各自拥有手势、导航和浮层 | 视口、几何、卡片、选择分别更新；不把移动端手势搬进共享数据层 |
| 路由和重型功能入口 | 模块加载与错误/重试呈现 | 按访问需求加载；不能因 lazy 边界重复创建项目运行时 |

实施时应在现有 `features`、`services`、`store`、`hooks` 下选择最窄归属。
无需为每行表格创建顶级目录、通用事件总线或新的全局 store。
先写清输入、输出、owner、dispose 与失效条件，再抽模块。

必须守住的边界：

- live Yjs 是正文真相；`contentJson` 是 seed/cache；自动正文写入继续经过 live `Y.Doc` 或 `writeChapterProse`。
- 隐藏标签不因性能优化丢失文档、撤销、滚动、选区或草稿。可见 split 的两侧都要正常显示，仅焦点侧拥有命令。
- 未审阅 Agent 内容不能因延迟装饰或标签切换短暂暴露；Review 决定仍持久化在 SQLite。
- 工作区不能混用两个项目、两个 generation 或半批新旧关系数据；旧异步结果不能发布到新项目。
- 不修改已发布迁移，不重置作者数据库。若 F6 确需新增持久进度结构，另加迁移并履行安全快照与兼容性验收。
- 不改变 provider-neutral Agent 的 `local`/`sidecar`/`remote` 接缝，也不恢复已退役产品。
- [Copilot 重设计](../copilot/redesign-plan.md)仍按独立计划推进；本计划只可提供订阅/调度基础，不能据此宣称其功能完成。
- 保留 drift 节点任一端点决定特殊边的规则，以及 act/chapter/scene/beat/note 五层语义。

建议实施顺序：**F0 → F1 → F2 → F3 → F4 → F5 → F6 → F7 → F8**。
这表示默认优先级，表中前置条件才是硬依赖。F4 可在 F0 后独立推进；若启动实测成为首要问题，

每阶段按“证据/复现 → 最小实现 → 回归和契约更新”拆成可审查的提交或 PR。
不要求凑固定提交数，也不把所有重构合成一次大合并。阶段完成必须同时具有代码、对应持久文档和真实验收证据。

## 4. F0：建立可复现的性能基线

**产出：** 合成项目生成入口、场景执行说明、运行结果格式和首份基线报告。
先复用 [Dev CLI](../dev-cli/README.md) 建立合成数据，使用
[frontend debug](../frontend-debug.md) 的只读检查面采集；不向运行中的个人项目注入数据。

拟定测试矩阵如下，所有规模均为待 F0 校准的候选，不能直接解释为承诺容量。

| 维度 | 候选规模 | 检查目的 |
| --- | --- | --- |
| 项目实体 | 50 / 300 / 1,000 章节；100 / 1,000 / 5,000 元素 | 区分跟随活动文档增长和跟随整个项目增长的成本 |
| 关系 | 500 / 5,000 / 30,000 条 | 图谱构建、端点查找、测量与视口密度 |
| 当前正文 | 5,000 / 20,000 / 50,000 中文字符；0 / 100 / 500 个实体链接 | 输入、粘贴、自动链接、撤销与着色 |
| 会话 | 1 / 5 / 20 个打开标签，包含 split | 切换、后台计算、恢复显示与内存释放 |
| Agent | 1,000 / 4,000 / 16,000 个事件，外加重复、重放、取消和长历史 | 去重复杂度、投影合并与恢复 |
| 同步 | 单实体结构变化、小批结构变化、纯正文、整项目恢复 | 更新范围、原子性与引用追赶 |

不用做所有维度的笛卡尔积。先设小项目控制组，再单独放大一个维度，最后组合关键压力场景。
所有正文必须合成，不提交个人作品、数据库、绝对个人路径或账号信息。

采集至少覆盖：输入到绘制 p50/p95、主线程长任务、组件 commit 数/耗时、链接查询/解析/写入次数、
Agent 去重操作及通知次数、端点测量次数、SQL/索引处理源数、打开与关闭标签后的内存、首屏实际加载/执行模块。
内存报告区分 JS heap 与原生进程，并说明 GC 和采样条件。

记录 source SHA、构建类型、应用包身份、设备/内存、系统、WebView、fixture seed/hash、操作序列、
预热和重复次数。耗时比较采用同环境多次运行的中位数和 p95；微基准与端到端测量分开。
测原生应用前，确认启动的是对应 checkout 的新构建。CDP、模拟器合成输入不替代实机中文输入法或触摸验收。

现有[桌面 RC 性能目标](../qa/desktop-alpha-release-candidate.md)是 M1/8GB 上冷启动可交互 ≤4 s、
打开 5 万中文字符 ≤3 s、输入到绘制 p95 ≤50 ms；这是待验收目标。
其他场景的时间/内存预算在 F0 用基线与设备能力校准，并在实现前固定，不能事后挪动门槛来制造收益。
不把“文件小了多少”或开发构建中的单次耗时作为性能通过标准。

**验收 F0-01–04：** 可重新生成同一合成数据；可关联构建和结果；能分辨全量/局部更新；预算、
设备及未运行项明确。性能采集入口不增加生产默认热路径成本，不收集正文内容。

**回退：** 关闭或移除采集器，不触碰业务数据；基线不可信时先修复测量，不据此启动大范围改造。

## 5. F1：先修输入热路径

**范围：** `lib/extensions/entity-link.ts`、`lib/entity-link-appearance.ts`、`hooks/useEntityEditor.ts` 中的着色接线。

1. 将目标 ID 到颜色/归属的解析建立为可复用查询，避免每个链接都遍历项目数组。
   F1 可先提供局部接口；F2 再归并到项目索引，避免同时维护两套失效规则。
2. 先加入颜色未变化时不写 style 的保护，再跟踪事务影响的链接范围。
   普通文字编辑只处理新建或受影响的链接 DOM；纯 selection 事务不扫描全文。
3. 处理 mark 跨边界、粘贴、删除、undo/redo、远程 Yjs 变化及 ProseMirror 重建 DOM 的情况。
   优先使用事务映射/插件状态确定影响范围；不可只凭输入字符或旧 DOM 身份跳过更新。
4. 名称、归属、主题或颜色设置变化使用明确的 appearance revision；必要的全量重着色保留为可测量的慢路径。
   初次挂载、恢复和无法安全定位范围时也允许显式全量处理。
5. 保留自动链接、持久化合并和已有 decoration 映射。首轮不改正文模型或 Yjs 写入时序。

**验收 F1-01–04：** 长文中在链接外连续输入，不逐键查询所有链接；selection-only 更新不触发着色扫描；
颜色未变时无冗余 style 写入；新链接、颜色/归属变化、粘贴、撤销、远程编辑和中文组合输入显示正确。
在同一 fixture 下比较输入分位数和长任务，达到 F0 固定预算。

**回退：** 可单独恢复旧着色策略；缓存可丢弃重建，正文不变。出现链接遗漏或组合输入异常，
先回退范围优化，再保留已经独立验证的查询索引和 no-op 保护。

## 6. F2：收窄订阅，建立项目派生索引

**范围：** `store/data-store.ts` 及高频消费者、`useEntityEditor` 的名称/颜色索引、项目统计投影。

1. 先处理 NodeEditor、左右栏、BottomTimeline、图谱等热路径的全 store 订阅，改为字段/实体 selector。
   action 单独订阅；返回对象/数组的 selector 必须有稳定结果或合适的相等判断。
2. 给项目只读层建立按 ID 的查询与稳定记录引用；一次快照仍原子发布。
   不在各组件内各建一份 `Map`，也不因一次统计字段改变重建所有实体名称/颜色缓存。
3. 明确至少四类失效：实体存在/名称、归属/颜色、正文指标、关系/排序。
   修订号从真实语义变更导出；不能漏标、依赖调用者随手递增，或在 render 中全量拼字符串。
4. 名称解析、链接外观、关系端点查找归属项目级派生缓存；按 project/generation 清理。
   暴露只读查询，不让消费者修改共享 Map。旧项目异步计算完成后也不能污染新项目。
5. 写作统计仅因所需指标变化重算。当前总字数相同时已有 no-op，应保留，不将其误写为每次都会持久化。

**验收 F2-01–04：** comment 更新不触发仅依赖章节/名称/颜色的消费者；单节点指标更新不使名称/外观索引失效；
相关更名、删除、归属和排序可立即正确失效；换项目、刷新和恢复没有混合快照或残留缓存。
用订阅通知和实际 React commit 验证，不能只统计 `useDataStore()` 文本出现次数。

**回退：** 按消费者回退 selector 接线或清空派生缓存，不更换权威 store。
第一轮无需把全部历史数组 API 一次性迁到新结构，也不增加数据库表。

## 7. F3：保留编辑会话，暂停不可见的显示工作

**范围：** `EditorMainArea`、`EditorSurfaceLifecycle`、`useEntityEditor` 及 Agent Review decoration 接线。

1. 将 `useEntityEditor` 按生命周期拆成文档/持久化、链接索引接线、Review 装饰、可见交互等有明确 owner 的单元。
   对外入口仍可保留；禁止只是把所有 hook 搬到新文件后在每个编辑器中全部运行。
2. Review 订阅按实体和实际相关修订过滤，避免每个编辑器对所有 Agent edit store 变化 dispatch meta 事务。
   同实体的多标签/多 split 仍共享权威状态，分别保持显示正确。
3. 隐藏会话保留 Yjs、必要持久化、撤销和字段草稿；可延迟纯显示的全量装饰/测量，将其标为 dirty。
   文档变化仍须满足编辑器及审阅安全要求，不能一概暂停所有插件或远程更新。
4. 在已有 ready/可见提交屏障中补齐 dirty 显示，然后再显示 incoming surface。
   若装饰影响未审阅文本遮罩，安全遮罩必须持续有效，不能先露出正文再异步补装饰。
5. split 的像素可见性与命令归属分开；关闭标签/项目时释放监听器、计时器、索引引用和文档保留计数。

不再串入整套偏好设置。`acceptance/f7-settings-baseline.json` 从隔离的 `4a6734d` 检出构建，
`acceptance/f7-settings-deferred.json` 记录同样的生产入口观察：初始 JS 依赖从 5,187,486 降至

设置加载器为同一构建文件的显式重试增加新的查询标识；真实阻断请求后，桌面/移动独立设置均恢复。
加载期间栏目选择、返回及桌面弹窗 Escape 保持可用；重复访问复用成功的代码缓存。
这批没有验证完整项目设置、编辑器/ProjectRuntime 组合连续性、原生资源协议或 F0 延迟预算。

F7c 将故事/元素图谱分别迁入延迟入口，先加载可独立重试的共享图形组件，再加载选中的视图主体。
桌面 host 与移动兼容入口共用局部 loading/error 外壳，导航和返回保持可用。共享代码成功后复用，
不缓存项目、编辑器或图谱实例。生产图检查覆盖静态 JS/CSS 依赖，防止冷共享依赖绕过重试所有者。
`acceptance/f7-graphs-baseline.json` 从干净的 `d7e8c9a` 检出构建；对照
`acceptance/f7-graphs-deferred.json`，初始静态 JS 依赖从 5,013,055 降至 4,923,305 字节。

设置加载回归另存 `acceptance/f7-settings-after-graphs.json`，历史 F7b 报告保持不变。
这批不等同于完整 ChapterEditor/ProjectRuntime、原生平台交互或 F0 延迟预算验收；预加载仍待继续。

F7d 增加入口意图预加载：停留 120 ms 后在 idle 窗口请求，最多一个后台任务和一个待处理意图；
新的待处理意图替换旧项。离开入口、取消触控、卸载、窗口失焦或页面隐藏取消未启动任务。
失败的后台尝试不污染首次打开；正式点击可接管同一请求，也可绕过其他后台任务直接加载。
图谱主入口、图谱切换/移动结构入口及设置入口共用已有代码缓存，后台不创建视图或项目实例。
每个资源每次 renderer 生命周期最多尝试一次后台预加载，失败不会因重复 hover 反复请求。
`acceptance/f7-intent-preloading.json` 记录真实入口浏览器检查、既有图谱重试回归和确定性调度测试。
完整项目/设备连续性与首开预算仍未计为通过；F7 与 F8 的其余门槛继续保持未完成。

**范围：** `AppRoutes.tsx`、desktop/mobile shell 入口、`DesktopOverlayHost`、图谱和低频模态框、Vite 构建分析。

1. 记录首屏真正加载、解析、执行的模块，而不只观察打包后的 chunk 总数。
2. 按路由/功能入口引入 dynamic import，优先低频设置、重型图谱和独立模态框；检查 barrel 静态导入是否重新串回主包。
   项目运行时和必要原生事件监听须按已有启动时序就绪，不能为了缩小首包延后到丢失事件。
3. 预加载基于用户入口或首次空闲，限制并发；首次加载保留稳定外壳和可取消状态，后续访问复用模块缓存。
   incoming editor 的加载继续遵守既有 ready 屏障，不用 Suspense fallback 覆盖正在写作的整个工作区。
4. 为 chunk 加载失败提供局部错误与重试；验证原生本地资源路径、离线启动、升级后的资源一致性。
   对 desktop/mobile 分别测量，不将 native 本地 JS 的 gzip 缩小等同于网络收益。

**验收 F7-01–04：** 不访问重型功能时不加载/执行对应代码；访问后功能完整且重复打开无空白闪烁；
模块失败不会丢失编辑状态或重启项目运行时；首屏和首开功能均达到 F0 预算，避免将全部耗时转移到首次点击。

**回退：** 单个入口可恢复 eager import；不调整作者数据、导航含义或 runtime 生命周期。

## 12. F8：组合验收与防止回退

1. 在基线和最终实现执行同一批 fixture/操作序列，报告输入、标签、Agent、图谱、同步、启动和内存的变化。
   列出退化项及原因；局部计数下降不能代替整体效果。
2. 覆盖中文 IME、长文粘贴、连续撤销、快速标签/split 切换、隐藏标签接收远程正文、Agent 输出并行编辑、
   结构同步、项目切换、取消、断开/重连和进程恢复。压力轨迹只用合成数据。
3. 将确定性约束纳入普通 CI：无关订阅通知、失效范围、事件等价性、重复处理、队列恢复、项目隔离、依赖边界。
   受设备噪声影响的 p95/内存/原生启动放到固定性能环境；结果带容差与复跑规则，不让随机时延拖垮普通测试。
4. 桌面原生新构建、Android/iOS 可用环境分别记录。模拟器、合成输入、物理设备、真实账号同步验收状态分开；
   缺失设备保持 `NOT RUN`，不沿用旧二进制的结果。不会用本计划代替已有签名 RC 或 Drive 实机门槛。
5. 更新实际已实现的 renderer 契约、编辑生命周期、同步/Agent 文档，以及对应生成器产生的验收证据。
   计划文件只链接真实输出，不手工把生成文件改成“通过”。未过门槛的阶段不得标 complete。

**验收 F8-01–04：** 组合场景达到固定预算和正确性门槛；CI 回归保护可复现；文档与精确 SHA 对齐；
实机和发布缺口明确，未测项目没有被计入已验收。

**回退：** 按阶段定位并撤回引起退化的变更；先恢复可靠数据与显示，再重新测量。
没有证据收益的复杂抽象应简化或撤销，不为保留重构成果追加永久兼容层。

## 13. 检查、证据与执行边界

各阶段先运行针对实际风险的行为测试，合并前执行仓库规定的检查：

```bash
pnpm ci:contract:check
pnpm public:check
pnpm lint
pnpm typecheck
pnpm test
pnpm agent:capabilities:check
pnpm test:renderer-architecture
```

构建使用 CI 的明确环境配置：

```bash
VITE_LOCAL_ONLY_MODE=true VITE_REQUIRE_AUTH=false VITE_AI_TRANSPORT=direct \
VITE_API_BASE_URL=http://localhost:3000 API_BASE_URL=http://localhost:3000 \
pnpm exec vite build --config vite.renderer.config.ts
```

涉及 Agent 会话同步受保护源码时，运行 `pnpm agent:conversation-sync:check`；若生成证据需要更新，
使用 `pnpm agent:conversation-sync:evidence` 真实运行生成器，然后检查 diff。涉及调试入口时执行
`pnpm frontend:debug:check`。原生迁移/恢复、触摸与性能须补对应专项验证，不能以 TypeScript 测试替代。
纯计划文档变更无需重新生成实现证据。

F0 应补充一个独立计划/报告校验入口，校验阶段依赖无环、验收 ID 唯一、证据路径存在及结果归属。
每份性能运行报告应由执行器输出 fixture、build、scenario、metric、unit、samples、summary、status 和
局限说明；只存合成操作统计及脱敏环境信息。计划 JSON 中的 evidence 只引用已发生的运行结果。
机器通过与人工/实机验收分开表示，CI 不得将单纯填写文档视为完成。

建议按三批评估是否继续投入：

- **第一批 F0–F3：** 达成输入与多标签场景的首轮可测收益；完成后再决定大范围 UI 拆分的必要性。
- **第二批 F4–F6：** 处理长会话、大图和大型项目同步的规模增长；F6 单独保留恢复验收关口。
- **第三批 F7–F8：** 优化加载，验证组合效果并固化防回退规则。

实施进度和实际证据统一记录在[执行记录](README.md)及验收清单；未完成的项目不得记为达标。
