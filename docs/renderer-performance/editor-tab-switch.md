# 切换编辑器标签（2026-10-30）

## 问题

release 基线里，切换标签的单帧冻结 p50 约 57–81 ms，开着侧栏时 p95 约 120 ms；展开侧栏约 160–180 ms（见[重型 seed 基线](heavy-seed-baseline.md)）。

对 release 构建的 WebContent 进程做原生栈采样（8 次切换），主线程时间分布：

| 部分 | 每次切换约 |
| --- | ---: |
| JS（React 渲染、提交和副作用） | 21 ms |
| JS 里同步读取 `offsetLeft` 等触发的强制样式与排版 | 16 ms |
| 渲染时的样式计算 | 19 ms |
| 合成层计算（`computeCompositingRequirements`） | 15 ms |
| 事件区域 | 4.5 ms |
| 绘制 | 23 ms |

其中绘制有约 10 ms 花在 WebKit 为透明层递归计算裁剪框上。整页约有 2280 个渲染层：

- 界面外壳约 1380 个，例如底部时间线 100 个片段、每个约 5 层；
- 隐藏的标签约 830 个。

### 切换过程

切到一个已打开的标签，要经过同一任务里的几次同步提交：

1. 新表面变为"准备中"：`content-visibility` 打开，`visibility` 仍隐藏；
2. 它的展示层补上隐藏期间推迟的工作，然后报告就绪；
3. 新表面变为可见，旧表面隐藏。

如果第 1、2 步之间有代码同步读取布局，新表面的样式和排版会被提前强制算一遍。第 3 步改变 `visibility` 后，整个子树的样式又要再算一遍。采样里，这类读取来自每次切换都会重新渲染的几个控件。

## 修复

- **`PanelTabTray`**：原来每次渲染后都测量当前标签的位置，现在只在选中的标签或标签数变化时测量。尺寸变化仍由 `ResizeObserver` 处理。
- **`GlassSlider`**：父组件常常内联构造 `options` 数组，导致每次父组件渲染都重新测量。现在测量的依赖改为选项值拼成的键。
- **选择水波（`flowGlassSelection`）**：原来在改变选择的那次提交里同步测量每个胶囊。现在先同步设好状态属性，下一帧再测量并开始动画，动画仍在同一帧开始。
- **顶部标签条**：所有胶囊都放得下、且标签条停在起点时，当前胶囊一定在视野里，不再读 `offsetLeft` 和 `scrollLeft`。
- **章节面板的行**：每次切换，章节面板会渲染约 3 次，原来每次都把约 126 行连同新建的回调和样式对象全部重画。现在行是 `memo` 组件，操作回调保持稳定，只重画选中状态变化的两行。Debug 构建下用 React 提交探针测 6 次切换，`SandCell` 渲染次数从 2268 降到 131。

以下测试覆盖这些改动：

- `src/renderer/lib/glass-wave.test.ts`："measures the pills only on the next frame"，旧实现在这里失败。
- `src/renderer/components/ui/switch-layout-reads.acceptance.test.ts`：固定上面三个控件的守卫。

## 应用内结果

`pnpm perf:stress --release --foreground`，修复前 `df251d31`、修复后 `af91ba0b` 交替各跑三遍。原始数据：[acceptance/optimization-foreground-2026-10-30.json](acceptance/optimization-foreground-2026-10-30.json)。

| | 修复前 | 修复后 |
| --- | ---: | ---: |
| 切换标签 p50 / p95，侧栏关 | 57–58 / 84–97 ms | 56–62 / 92–97 ms |
| 切换标签最差帧 p50，侧栏关 | 49–50 ms | 50–54 ms |
| 切换标签 p50，侧栏开 | 78–85 ms | 75–85 ms |

切换的帧时间没有可测的改善。去掉的强制排版和行重绘只是整帧里的一小部分；占大头的是新表面的样式计算、合成层计算和绘制，这次没有动。这几处改动让切换路径上不再提前读取布局，行为不变，所以保留。

### 撤回：关闭后保留侧栏面板

曾尝试让打开过的侧栏面板在关闭后留在隐藏的 React `<Activity>` 里，以加快再次展开。为此 `perf:stress` 加了"关闭后再展开侧栏"（`reopen-sidebars`）一段，前台测得最差帧（左 / 右）：

- 修复前：93 / 54 ms；
- 保留面板后：94 / 105 ms。

原来关闭后卸载、再展开时重新挂载，本来就只要约 90 ms，比第一次展开（约 170 ms）快得多。保留面板没有加快再次展开，还多占内存，已撤回。
