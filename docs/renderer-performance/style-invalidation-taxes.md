# 动画、样式表与通配规则带来的样式税（2026-10-30）

切标签之后的若干帧、关掉最后一个标签、打开第一个章节、打开大视图时，都有一部分开销与当前操作本身无关，而是来自界面上常驻的三样东西。

## 测量方法

Debug 实例放在内建屏上：窗口可见但不在最前，WebKit 照常渲染，只是帧率被节流。

- 用 `sample` 对 WebContent 进程采样；
- 按调用栈最内层的类别，把主线程采样分到样式、排版、合成、绘制、JS 等类别；
- 改动先用运行时注入的样式或 CSSOM 修改做实验，确认收益和视觉不变后再实现。

## 1. 常驻的暂停动画（`lib/glass-awake.ts`）

### 问题

每个玻璃控件的 `::before` 和侧栏单元格的 `.cell-ring`，静止时都挂着一个暂停的 `glass-flow` 动画，共 375 个。

只要页面上任何地方有动画或过渡在跑，WebKit 每一帧都要为每个带动画的元素做一次样式更新，暂停的也不例外。例如：

- 切标签后的选择水波；
- 侧栏滑动；
- 悬停淡入淡出。

在一个与它们无关的 4 像素方块上跑透明度动画，同样时间内样式采样数为：

| 条件 | 样式采样数 |
| --- | ---: |
| 有这 375 个暂停动画 | 52 |
| 没有 | 2 |

### 修复

光圈从没流动过时，停在动画的第一帧，而那正是它静止时的遮罩位置。所以：

- 静止的光圈不挂动画；
- 指针或焦点到达控件时，先给它加上 `data-glass-awake`，光圈从第一帧开始流动，和原来一样；
- 不再被指着或聚焦后，只要光圈从没动过、或已经淡出看不见，就摘掉标记。

流动过并且仍然可见的光圈（选中、按下、`glass--rest`）会一直保持标记，所以停留的位置不变。自己会流动的 `glass--waiting` 和 `glass-sweep` 照常常挂动画。

单元格光圈补上了与动画起点相同的静态 `mask-position`。

### 效果

在 12 个标签、两侧侧栏都打开的 Debug 实例上，切换 10 次的样式采样数从约 600 降到 129。

## 2. Tiptap 的基础样式表（`styles/tiptap-base.css`）

### 问题

Tiptap 创建编辑器时会往 `<head>` 注入一张基础样式表，销毁最后一个编辑器时再删掉。增删样式表会让整页的样式和排版全部失效：关掉最后一个标签后，下一个任务里约 47 ms 用在样式、76 ms 用在排版，而这期间 DOM 并没有变化。打开第一个章节时再付一次。

### 修复

- 编辑器创建时传 `injectCSS: false`；
- 同一张表随应用样式一起加载，放在应用自己的样式之后，与原来运行时追加的位置一致；
- 测试保证它与已安装的 `@tiptap/core` 逐字一致。

通览全书里的静态章节行也因此始终带有这些样式，不再取决于当时有没有活动的编辑器。

## 3. 预置样式里的通配伪元素

见[预置样式不再覆盖 ::before 与 ::after](preflight-pseudo-elements.md)。要素全景首开的样式采样数从 359 降到 233。
