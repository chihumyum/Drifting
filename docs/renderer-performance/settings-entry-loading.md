# 独立设置入口

`/settings` 由 `AppRoutes` 直接挂载桌面或移动设置壳层，不再通过项目路由加载器。
设置标题、返回与导航先显示；`BasicPreferencePanels` 的外观和语言设置同步可用。
编辑器偏好、账号/快捷键/同步等控制面板、模型与密钥按三个功能组加载，代码在窗口内缓存。
桌面书架设置列出所有不属于某本书的设置：账号、外观、编辑器、语言、模型与密钥、主动建议、
外部 Agent 访问（仅 macOS/Windows）、快捷键、同步与数据、更新、隐私、关于；回收站和通用 Agent 面板读的是打开的书，
只在项目内设置里。
打开同步不会请求模型、Agent 或工作区界面。原有设置项、账号门槛与来源页面返回行为保留。

重型面板的等待和错误仅出现在内容区域，期间可以切换基础设置或返回书架。
迟到的模块只缓存代码，不挂载已离开的面板。独立设置不持有项目编辑会话；显式重试
刷新当前文档并保留所选 URL 与已持久化偏好，清除浏览器缓存的失败 JS/CSS 依赖。
项目内设置弹窗保留连续滚动布局，分组加载失败时仅重取失败组，成功组复用原组件。
其重试不刷新文档，保留编辑会话和偏好保存语义；生产模块图检查共享依赖已在项目入口
就绪，避免拆分后的依赖失败被单一外层入口的重试缓存住。
账号与同步共用一个加载入口，使两者共用的命令和状态适配器保持在同一个缓存/重试边界。

```bash
pnpm perf:renderer:settings
node scripts/run-renderer-settings-entry.mjs --check
```

`acceptance/settings-entry.json` 由脚本生成：生产构建检查基础偏好在静态入口中、工作区和
重型面板不在静态入口中。开发与生产浏览器均渲染真实桌面/移动设置，阻断工作区文件后
打开基础设置，检查偏好持久化；延迟和拒绝控制面板文件，验证局部转圈、导航、迟到结果、
同组切换、刷新重试及返回；另用合成草稿验证项目设置分组重试不替换原 DOM。
浏览器使用合成书架/认证初始化，不读取作者数据库或账号。
单次基础设置导航耗时只作诊断；原生输入、完整应用启动与真实账号同步不是这份证据的范围。
视觉截图留在本机 `.qa/settings-entry/`，不作为公共源文件提交。

旧 `run-renderer-deferred-settings.mjs` 及 F7 报告保留为历史对照；其所有设置均异步加载的
断言已被当前基础设置直接可用的边界取代，历史校验需带 `--check --historical`。
