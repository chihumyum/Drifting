# 移动端搜索焦点与滚动回归

状态：已验收关闭（2026-08-26）。五项全部在 iOS 模拟器上以原生触摸注入 + 真实
iOS 软键盘复验通过，维护者委托执行；证据见文末验收记录。

## 问题

1. 从编辑态进入搜索态并聚焦搜索输入框后，点击附件栏返回会收起键盘。正确行为应是退出搜索态、恢复此前的编辑态，并保持键盘与正文编辑焦点连续。
2. 搜索没有匹配项时，点击上一个或下一个按钮会使搜索输入框失焦并收起键盘。
3. 搜索存在多个匹配项时，快速连续点击上一个或下一个也会使输入框失焦；慢速点击不一定出现。结果切换不应改变搜索输入框焦点或键盘状态。
4. 在搜索态手动聚焦正文、使搜索框失焦后，再点击附件栏返回虽然不会收起键盘，但会改变页面的垂直位置。
5. 从编辑态进入或退出搜索态时，正文都会发生可见的垂直位移。搜索状态切换不应修改或补偿正文滚动坐标。

## 交互边界

- 搜索态附件栏中的结果切换及其他非返回操作不得触发 `blur`。
- 从编辑态进入的搜索必须记住编辑态来源；返回时恢复编辑态，而不是先关闭键盘或降级到阅读态。
- 搜索态切换与返回不得改变正文的垂直滚动位置。

## 源码边界

- 编辑态打开搜索时沿用已经打开的键盘状态，不产生中间的关闭帧。
- 编辑态的搜索入口按钮同时取消 `pointerdown` 与合成 `mousedown` 的默认聚焦转移，让 ProseMirror 保持 DOM 焦点直到搜索输入框接管同一输入会话。
- 返回编辑态时，在搜索输入框卸载前同步把焦点交给 ProseMirror。
- 搜索结果切换在 `pointerdown` 执行，并在附件栏捕获阶段取消非输入控件的默认聚焦行为。
- 搜索态不接管编辑器顶部滚动留白；编辑附件栏切换为搜索栏时也不清空共享键盘几何。

自动化测试只能覆盖状态、事件和布局所有权；连续触摸、快速连点、iOS IME 与视觉位置由下方的真实输入验收关闭。

## 验收记录 — 2026-08-26

环境：iOS Simulator（iPhone 17 Pro，iOS 26.5），HID 级原生触摸注入 + 真实 iOS
软键盘；DOM/几何断言经 frontend-debug 桥读取。逐项结果：

1. 编辑态 → 搜索 → 附件栏返回：恢复编辑态，键盘全程物理连续
   （visualViewport.height 539 无中断帧），ProseMirror 持有 DOM 焦点。
2. 无匹配（0/0）时真实点击上一个与下一个：搜索框保持焦点，键盘保持展开。
3. 快速连点下一个（repeat 注入 + 连续单点，推进至 4/4）：焦点与键盘始终保留。
4. 搜索态真实点击正文夺焦后返回：键盘不收起，scrollTop 与首段视口位置
   逐像素不变（136 / 162）。
5. 编辑态进入与退出搜索：正文零垂直位移（进入 28/270 → 28/270；退出
   136/162 → 136/162）。

边界说明：非物理真机（触摸时序与硬件性能不在本记录范围）；注入通道仅支持
ASCII 查询文本，连续中文 IME 组合输入未在本记录覆盖；期间两次 vite 重载
（并行源码编辑所致）令两条中间读数作废，受影响步骤均已重跑后通过。
